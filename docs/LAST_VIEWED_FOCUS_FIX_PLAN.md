# خطة علاج شريط «كنت تعمل على ملف» — رسالة «لا تملك صلاحية تنفيذ هذا الإجراء»

> **الحالة:** خطة منقحة بعد المراجعة النقدية — لا تنفيذ قبل موافقة صريحة من المستخدم.
> **النطاق:** واجهة فقط (`frontend/`) — لا مساس بالخلفية ولا هجرات قواعد بيانات.
> **المرجع التحليلي:** مراجعة شاملة قبل الكتابة + مراجعة نقدية خبيرة بعدها (نُقّحت الخطة تبعًا لها — انظر §10 سجل التنقيح).

---

## 1. ملخص المشكلة

- يظهر شريط `كنت تعمل على ملف «مستند 7»` بزر `فتح الملف` رغم أن الملف لم يعد مملوكًا للمستخدم الحالي (نُقل لزميل، أو دخل حساب آخر بنفس تبويب المتصفح).
- الاسم يظهر `مستند 7` لأن جلب الاسم `GET /documents/7` يُرفض بـ `403` (الخلفية تطبق `CanAccessOrFollowAsync` في `DocumentsController.cs:205-212` / `67-79`)، فيبتلعه `catch` ويستبدله بالبديل المجهول `DocumentsList.tsx:396`.
- النقر على `فتح الملف` يذهب إلى `DocumentView.tsx` الذي يعرض `getApiErrorMessage` من `client.ts:12` → `لا تملك صلاحية تنفيذ هذا الإجراء`.
- السبب الجذري ثلاثي: (أ) `DocumentView.tsx:107-108` يسجل أي معرّف فورًا حتى لو كان `403`، (ب) الشريط لا يتحقق من الصلاحية، (ج) `lastViewedDocumentId` مفتاح عام في `sessionStorage` بلا مالك (`listSession.ts:14-15`) ولا يُمسح عند تبديل الحساب (`AuthContext.tsx:36-42`).

---

## 2. الأهداف

1. ألا يظهر الشريط لملف لا يملك المستخدم الحالي صلاحية فتحه.
2. ألا يُسجل ملف غير مقروء كـ «آخر ما فُتح».
3. ألا تُورث ذاكرة الجلسة بين الحسابات في نفس التبويب.
4. بدون أي تغيير على الخلفية (سلوك `403` صحيح أمنيًا) ولا على العقود/الهجرات.

---

## 3. القرارات المعمارية المعتمدة (بعد المراجعة التحليلية)

| النقطة | القرار المعتمد | المبرر |
|---|---|---|
| **مصير الشريط عند فشل جلب الاسم** | مسح وإخفاء **فقط على `403`/`404`**؛ غيرهما (انقطاع شبكة `!response` أو `5xx`): **محاولة واحدة** لكل `focusId` في التركيب (حارس `ref`) ثم إخفاء **بلا مسح** — تُعاد المحاولة عند زيارة القائمة التالية | منع ضجيج إعادة الجلب مع الحفاظ على السياق من خلل لحظي |
| **سجل مخزن لمستخدم آخر** | **تجاهل وإعادة `null` بلا حذف** | دالة القراءة بلا أثر جانبي؛ الحماية من التسريب تتحقق بالقراءة نفسها، وإشارة المستخدم الآخر تبقى سليمة |
| **صيغة التخزين** | مفتاح جديد `lastViewedDocument` بسجل صريح `{ version: 2, userId, documentId }` + حذف المفتاح القديم عند أول كتابة | عقد صريح بلا تخمين إرث؛ المفتاح القديم لا يُقرأ أبدًا |
| **تواقيع الدوال** | `userId: number \| null` **إلزامي**، والاستدعاء `user?.id ?? null` | يفشل البناء عند نسيان الهوية بدل تعطّل صامت |
| **تقييد موضع القائمة `documentsListPosition`** | **مؤجل** — خارج نطاق هذه المهمة | تقليل حجم التغيير؛ العطل المبلّغ يخص آخر ملف مفتوح فقط. تُفتح مهمة لاحقة منفصلة إن رُصد تسريب فعلي للفلاتر |
| **إحالة شريط على ملف غير مقروء** | **إخفاء كلي** — لا شريط بلا رابط ولا رسالة «غير متاح» | الشريط وعدٌ بالفتح؛ إن لم يكن ممكنًا فإخفاؤه هو السلوك المتوقع |

## 4. التصميم التفصيلي

### 4.أ `frontend/src/utils/listSession.ts` — تقييد آخر ملف بالمستخدم

- **الصيغة الجديدة:** مفتاح جديد `lastViewedDocument` يحمل سجلًا صريحًا `{ version: 2, userId: number, documentId: number }`:
  ```ts
  const FOCUS_KEY = 'lastViewedDocument';
  const LEGACY_FOCUS_KEY = 'lastViewedDocumentId';
  const FOCUS_RECORD_VERSION = 2;
  ```
  المفتاح القديم لا يُقرأ أبدًا بعد هذا التغيير، ويُحذف عند أول كتابة ناجحة بالمفتاح الجديد (نظافة لمرة واحدة) — فلا حاجة لأي تخمين لصيغة الإرث.
- **التواقيع الجديدة (`userId` إلزامي — يفشل البناء عند نسيانه بدل تعطّل صامت):**
  ```ts
  loadLastViewedDocumentId(userId: number | null): number | null
  saveLastViewedDocumentId(id: number | null, userId: number | null): void
  ```
  - `save`: `id` غير صالح (`null`/غير رقمي) أو `userId == null` → `removeItem(FOCUS_KEY)`؛ وإلا `setItem(FOCUS_KEY, JSON.stringify({ version: 2, userId, documentId: id }))` ثم `removeItem(LEGACY_FOCUS_KEY)`.
  - `load`: لا قيمة → `null`؛ ثم `try JSON.parse` مع التحقق **بهذا الترتيب**: (1) كائن غير فارغ؟ (2) `version === 2`؟ (3) `userId` و`documentId` رقمان صحيحان موجبان؟ أي فشل في الشكل → `null` بلا حذف (اتساقًا مع عُرف `loadDocumentsListPosition` الذي لا يحذف التالف)؛ (4) `userId` المخزن ≠ المعامل → `null` **بلا حذف** (تجاهل يحمي من التسريب ويحفظ إشارة المستخدم الآخر)؛ وإلا أعد `documentId`.
- **مبدآن مُلزمان:** دالة القراءة بلا أثر جانبي حذف؛ والحذف الصريح يتم فقط عبر `save(..., null)` من مسارات `403`/`404` في `DocumentsList`.

### 4.ب `frontend/src/pages/DocumentView.tsx` — التسجيل فقط بعد تحميل مؤكد

- **الحالي (`:107-108`):**
  ```ts
  useEffect(() => { if (id) saveLastViewedDocumentId(Number(id)); ... }, [id]);
  ```
- **المقترح — فصل التأثير إلى اثنين:**
  ```ts
  // 1) إعادة ضبط واجهات الاستئناف — يبقى على [id] كما هو
  useEffect(() => {
    appealMenu.setOpen(false);
    setAppealFormVariant(null);
    setInfoAppeal(null);
  }, [id]);

  // 2) التسجيل المشروط — فقط بعد تحميل الوثيقة
  useEffect(() => {
    if (id && doc) saveLastViewedDocumentId(Number(id), user?.id ?? null);
  }, [id, doc, user?.id]);
  ```
  حيث `doc = docQuery.data ?? null` (`:98`). عند `403` يبقى `doc == null` فلا يُسجل — تُكسر حلقة إعادة التوليد الذاتي. إعادة الحفظ عند كل `refetch` ناجح غير ضارة (نفس القيمة — idempotent).
- **الاستيراد:** `user` متاح عبر `useAuth()` (`:45`).

### 4.ج `frontend/src/pages/DocumentsList.tsx` — شريط يتحقق من الصلاحية

- **الحالة القابلة للضبط + حارس المحاولة الواحدة (`useRef` مستورد أصلًا في الملف):**
  ```ts
  const [focusId, setFocusId] = useState<number | null>(null);
  const focusFetchAttempted = useRef(false);
  useEffect(() => {
    focusFetchAttempted.current = false; // focusId جديد → محاولة جلب جديدة مسموحة
    setFocusId(loadLastViewedDocumentId(user?.id ?? null));
  }, [user?.id]);
  // معالجة السباق: user يبدأ null (AuthContext يحمّل /auth/me لاحقًا)
  ```

- **جلب الاسم (`:383-398`) — تمييز سبب الفشل مع منع إعادة الجلب المتكرر:**
  ```ts
  import { isAxiosError } from 'axios';

  useEffect(() => {
    if (focusId == null || data == null) return;
    if (focusVisible) {
      if (!scrolledToFocus.current) {
        scrolledToFocus.current = true;
        document.getElementById(`doc-row-${focusId}`)?.scrollIntoView({ block: 'center' });
      }
    } else if (focusName == null && !focusFetchAttempted.current) {
      focusFetchAttempted.current = true; // محاولة واحدة لكل focusId في هذا التركيب
      api.get<DocumentResponse>(`/documents/${focusId}`)
        .then((r) => setFocusName(identityName(r.data) || displayFileNumber(r.data) || `مستند ${focusId}`))
        .catch((err: unknown) => {
          if (isAxiosError(err) && (err.response?.status === 403 || err.response?.status === 404)) {
            saveLastViewedDocumentId(null, user?.id ?? null);
            setFocusId(null);
          }
          // انقطاع شبكة (!response) أو 5xx: لا مسح ولا إعادة محاولة في هذا التركيب —
          // الشريط مخفي (focusName == null)، والمحاولة تتجدد عند زيارة القائمة التالية.
        });
    }
  }, [focusId, focusVisible, focusName, data, user?.id]);
  ```
  - مسار النجاح يبقى كما هو — `مستند N` يظهر فقط لملف مقروء بلا أسماء (حالة مشروعة).
  - مسار `403`/`404` يمسح التركيز ويُخفي الشريط فورًا (لا بديل مجهول برابط ميت).
  - `401` لا يصل للـ `catch` — `client.ts:59-62` يحوّل إلى `/login` تلقائيًا.

- **`openDocument` (`:376-379`):**
  ```ts
  const openDocument = (id: number) => {
    saveDocumentsListPosition({ query, status, applicant, court, lawyer, administrativeBranch, executedEntity, publicEntityBranch, page });
    saveLastViewedDocumentId(id, user?.id ?? null);
  };
  ```
  آمن لأنه يُستدعى من القائمة حيث الملف ظاهر = مقروء قطعًا.

- **العرض (`:603-610`) بلا تغيير بنيوي** — الشرط `focusId != null && !focusVisible && focusName` يُخفي تلقائيًا عند مسح `focusId`.

## 7. الحالات الحدّية

| الحالة | السلوك |
|---|---|
| ملف مقروء بلا أسماء ولا رقم | `مستند N` (نجاح) — يُعرض |
| `403` / `404` على جلب الاسم | مسح وإخفاء |
| انقطاع شبكة (`!response`) أو `5xx` | محاولة واحدة ثم إخفاء بلا مسح ولا إعادة محاولة في التركيب؛ المحاولة تتجدد عند زيارة القائمة التالية |
| `401` | إعادة توجيه إلى `/login` عبر `client.ts` |
| `user == null` عند التهيئة | `focusId == null` حتى تحميل المستخدم — ثم `useEffect` يزامن |
| سجل مخزن لمستخدم آخر | تجاهل (`null`) **بلا حذف** — إشارة المستخدم الآخر تبقى سليمة |
| المفتاح القديم `lastViewedDocumentId` | لا يُقرأ أبدًا؛ يُحذف عند أول كتابة بالمفتاح الجديد |

## 10. سجل تنقيح الخطة (تبعًا للمراجعة النقدية)

1. **حارس `focusFetchAttempted`**: محاولة جلب واحدة لكل `focusId` في التركيب — منع إعادة الجلب عند كل تغيّر `data` (كان سيُدخل ضجيج طلبات على فشل الشبكة).
2. **اختلاف المستخدم → تجاهل بلا حذف** (دالة القراءة بلا أثر جانبي) بدل المسح — حماية من التسريب مع حفظ إشارة المستخدم الآخر.
3. **مفتاح جديد `lastViewedDocument`** بسجل مُصدَر `{ version: 2, userId, documentId }` بدل تخمين صيغة الإرث — المفتاح القديم لا يُقرأ أبدًا ويُحذف عند أول كتابة.
4. **`userId` إلزامي** في التواقيع مع `user?.id ?? null` عند الاستدعاء — النسيان خطأ بناء.
5. **استكمال قسم الاختبارات**: اختبار النقر (`1333-1344`)، والـ`mock` الافتراضي في `DocumentView.test.tsx:160`، وجعل اختبار انقطاع الشبكة إلزاميًا مع فحص عدم تكرار الطلب.
6. **تصحيح صياغة «إخفاء مؤقت»** إلى السلوك الفعلي: إخفاء بلا مسح مع تجدد المحاولة عند زيارة القائمة التالية.
