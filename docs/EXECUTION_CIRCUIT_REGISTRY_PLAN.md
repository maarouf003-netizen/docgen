## 2. سجل القرارات المعتمدة (56 بندًا — أي تغيير يتطلب موافقة)

1. البطاقة الآن لدور `head` فقط؛ التصميم يقبل الدور السادس (رئيس الشعبة) لاحقًا دون كسر العقود.
2. الدائرة مرتبطة **بفرع الإدارة والمحافظة**: ربط `BranchId FK`، وقائمة المحافظة بمطابقة `Governorate`
   (بلا افتراض فرعٍ واحدٍ للمحافظة — لا قيد وحدانية عليها في `BranchConfiguration.cs`).
3. القاعدة تجريبية فارغة — لا ترحيل بيانات؛ القفل على الجديد مباشرة.
4. الدائرة **إلزامية دائمًا وفي كل الأوضاع** (طالبة تنفيذ / منفذ عليه / عرض وإيداع).
5. الحقل نفسه **زر مقفل** بداخله «اختيار» (نمط `frontend/src/pages/DocumentForm.tsx:1071` للجهات).
6. الإدارة لرئيس القسم فقط (`CanManageExecutionCircuits = head`)؛ المدير/المشرف إحصائيات فقط؛
   المحامي اختيار فقط. (**مرفوض**: بديل المشرف عند غياب الرئيس — القرار: رئيس القسم حصرًا ولا أحد غيره.)
7. إعادة التسمية = **تحديث جماعي فوري** لكل الملفات في نفس المعاملة + تدقيق.
8. الحذف ممنوع بوجود أي ملف تنفيذي (تصميميًا: لا زر حذف — بل «إفراغ أولًا»؛ وخادميًا `409`).
9. نقل ملفات محامٍ داخل الدائرة يشمل **الملفات والإنابات دون الاستئنافات**.
10. إحصائيات الدوائر = صفحة مستقلة للمدير/المشرف بمنتقي فرع: (الدائرة × عدد ملفاتها × عدد المحامين
    **النشطين** فيها أي من لديهم ≥ ملف واحد).
11. وجهة نقل الإلغاء: **دائرة واحدة ثابتة** في **نفس الفرع** ولمحامي نفس الفرع (`BranchId` لا يتغير أبدًا).
12. **النقل الشامل ليس عملية مستقلة** — هو خطوة إجبارية داخل تدفق الحذف فقط.
13. الإحالة بمربعات اختيار **لكل الملفات** (وليست للمتعارضة فقط)، قابلة للتكرار لمحامين عدة حتى الصفر.
14. الأرقام الجديدة **إلزامية لكل ملف**: الرقم جديد إلزامًا، النوع/السنة معبأة بالقديمة قابلة للتعديل.
15. **بلا اقتراح تلقائي** — إدخال يدوي خالص (الأرقام من المحكمة وغير متسلسلة).
16. إدخال المحامي للأرقام **نهائي مباشرة** وقابل للتصحيح من صفحة التعديل (مع إعادة تحقق الوحدانية).
17. **التدوير** يدور على الأرقام الجديدة تلقائيًا (مربوط بـ `FileNumber` الحالي)؛ القديمة توثيق فقط؛
    `BaseNumbers` السنوية لا تُمس **بالتدوير** (مسحها عند الإحالة بين الدوائر محكوم بالبند 51 لا بهذا البند).
18. التنبيه: **بانر فوري فقط** بعد نجاح الإفراغ/النقل بالنص الحرفي:
    «لا تنسى نقل ملفات هذه الدائرة لمحامي أو محامين اخرين ان كان لذلك مقتضى»
    (ملاحظة: داخل التدفق الجديد يُستبدل عمليًا بإعادة الإسناد داخل المعالج + تنبيهات المحامين أدناه —
    يُثبت النص في شاشة التأكيد النهائية).
19. تنبيه المحامي (لكل محامٍ × دائرة، مدمج، يُصفّى تلقائيًا عند الصفر، يتبع المالك عند إعادة الإسناد):
    «أحال لك رئيس القسم ملفات من دائرة كذا — يرجى تحديث معلوماتها» ← يفتح **صفحة معلقاته كلها
    مجموعةً بالدوائر** (استعلام لا عمود جديد — يُعاد استخدام `DocumentId + TargetLawyerId`؛ مع ملاحظة
    أن `HeadAlert` يحمل خمسة أعمدة ربط (`DocumentId/DelegationId/AppealId/ReviewLetterId/PublicEntityId`
    سطور 16-29 لا عمودًا واحدًا، والنمط القائم للتنظيف هو الربط بالكيان الأب).
    خطاف التنظيف مسمّى `DeleteByPendingRegistration` (على نمط `DeleteByDelegationAsync` في
    `DelegationService.cs:410`) — يُستدعى عند اكتمال إعادة قيد آخر ملف معلق للمحامي وعند انتقال
    الملكية، فالتنبيه يفتح الصفحة لا ملفات بعينها.
20. الإنابات: المنيب المنقول يسحب إناباته **كما هي** (يتحدث عرض المنيب تلقائيًا)؛ المناب المنقول
    يُحدَّث `DelegatedCourt` لوجهته؛ `AssignedLawyerId` لا يُمس أبدًا؛ الواردة المعلقة بلا ملف مناب
    تُعاد توجيهها للدائرة الجديدة — الكل موثق في `DocumentOccurrence`.
21. **العقد**: `DocumentUpsertRequest += ExecutionCircuitId: int` (إلزامي)؛ الخادم **يشتق**
    `Court/CourtNorm` من الدائرة **ويتجاهل نص العميل دائمًا** (لا `400` — حفظًا للعقد مع العملاء
    والاختبارات القائمة التي ترسل `court`) — يُلغي الثقة الحالية

22. **الاستثناء الخارجي**: الإنابة الخارجية (`IsExternal=true`) دائرتها خارج المحافظة وخارج السجل —

    يبقى مُزامَنًا؛ الذي يتغير مصدر الخيارات فقط فلا ينكسر التصدير والبوابة).
25. **قاعدة الجد**: تعديل ملف على دائرة **معطلة** مسموح وتبقى دائرته (القفل يمنع الاختيار الجديد فقط).

## 4. تصميم الخلفية

### 4.1 الكيان الجديد `ExecutionCircuit`

```csharp
ExecutionCircuit {
  Id: int
  BranchId: int FK → Branch (إلزامي)
  Name: string (200)
  NameNorm: string (200, unique × BranchId — تطبيع ArabicNameNormalizer نفسه)
```

### 4.2 التعديلات على الكيانات القائمة

- `Document` += `ExecutionCircuitId: int? FK` (إلزامي للجديد **عدا ملفات المناب الخارجي**
  `IsExternal=true` — البند 54؛ `NULL` مستحيل عمليًا لغيرها لأن القاعدة فارغة
  والقفل من اليوم الأول) + `NeedsRegistration: bool` (`flag` «بانتظار إعادة القيد»)؛
  `Court/CourtNorm` يبقيان **عرضًا مُزامَنًا** من الدائرة (نمط `ApplicantRegistryId`) حتى لا تنكسر:
  الفلاتر، `ExcelExportService`، `DocumentContextBuilder.court_with_prefix`، `FileDataCard`.
- `DocumentDelegation` += `DelegatedCircuitId: int? FK` (للداخلية فقط — تُشتق من اختيار المنابة؛
  الخارجية `IsExternal=true` تبقى `DelegatedCourt` نصًا حرًا حسب البند 22).
  **اعتماد الإنابة** (`DocumentDelegationService.cs:373-379`) يستنتج `ExecutionCircuitId` للملف المناب
  من `DelegatedCircuitId` بدل السطر الحالي `Court = Normalize(delegation.DelegatedCourt)` —
  وإلا انكسر إنشاء المناب (ملف بلا دائرة إلزامية).
- تعديل ملف «بانتظار إعادة القيد» من صفحة التعديل برقم غير فارغ **يُسقط الـ `flag`**
  (مع إعادة تحقق الوحدانية) — تطبيقًا للبند 16.
- الوحدانية تنتقل إلى `‏(ExecutionCircuitId, FileNumber, FileType, FileYear)‏` (جزئي يستثني المحذوف
  و`NULL` — فيحمي تفريغ الأرقام أثناء انتظار إعادة القيد من أي تصادم)، **مع إسقاط الفهرسين النصيين
  المركبين** (`Court` و`CourtNorm` — `DocumentConfiguration.cs:179-187`) في الهجرة نفسها (البند 52 —
  وإلا بقي قيد نصي عالمي يتصادم مع دائرتين متساويتي الاسم في فرعين مختلفين)؛ وصفوف المناب الخارجي

## 5. التدفقات (الحالات الأربع النهائية)

### 5.1 إدخال دائرة → اختيارها في ملف

رئيس القسم «إدخال دائرة» ← المحامي زر الدائرة المقفل «اختيار» ← قائمة دوائر فرعه ← إلزامية تمنع
الحفظ ← الخلفية ترفض أي اسم خارج السجل (`400`).

### 5.2 تعديل تسمية

`rename` ← تحديث `Name/NameNorm` + تحديث جماعي `Court/CourtNorm` لكل `Documents` المرتبطة في نفس
المعاملة + وقوعّة/تدقيق + `Version` متفائل (تعارض `409` عند التزامن).

### 5.3 نقل ملفات محامٍ (داخل نفس الدائرة — روتيني)

اختيار المصدر والهدف (فحص الفرع/التفعيل) ← تأكيد نهائي (نمط `TransferAllFilesModal` بخطوتيه) ←
نقل الملكية + `AssignmentKindCatalog.Transfer` + تدقيق. **بلا إعادة قيد وبلا تنبيه إعادة قيد**
(الدائرة لم تتغير). **وتبديل الدائرة نفسها من التعديل** (مسموح + `409` عند التعارض) يسجل الوقوعتين
تلقائيًا (البند 48).

### 5.4 إلغاء دائرة (التدفق المركزي — إفراغ ثم حذف)

1. رئيس القسم يختار الدائرة الهدف (**ثابتة** لكل العملية، نفس الفرع) ← بدء الإفراغ **يعطّل
   الدائرة الملغاة تلقائيًا** (البند 40 — لا ملفات جديدة أثناء التفريغ).
2. قائمة كل ملفات الدائرة الملغاة بمربعات اختيار ← تحديد دفعة ← اختيار محامٍ (نفس الفرع) ← «إحالة»
   ← تُعاد القائمة بالمتبقي حتى **الصفر**. «إلغاء الإفراغ» في أي لحظة **يعيد تفعيل** الدائرة (البند 46).
3. كل ملف محال: مالك جديد + `CircuitId` جديد + رقم/نوع/سنة = `NULL` + `NeedsRegistration = true`
    + **مسح صفوف `DocumentBaseNumber` الخاصة به** (البند 51 — وإلا أظهر `EffectiveFileIdentity`
    الرقم القديم بدل الجديد) + وقوعّة «أُحيل من دائرة كذا برقم كذا» (تحمل `FromCircuitName/ToCircuitName`
    نصًا — §4.5) + تحديث/إنشاء التنبيه المدمج للمحامي.
4. البانر الحرفي في شاشة التأكيد: «لا تنسى نقل ملفات هذه الدائرة لمحامي أو محامين اخرين ان كان
   لذلك مقتضى».
5. عند الصفر (ملفات + إنابات واردة معلقة مُعاد توجيهها + **لا صفوف محذوفة منطقيًا** — البند 41؛
    مسار إفراغ المحذوفة منطقيًا الوحيد: **استعادة ثم إحالة** — `RestoreAsync` يفحص الوحدانية بالرقم
    الجديد بعد البند 51):
    يُتاح زر «حذف الدائرة» ← حذف (سجل تدقيق). معلقات المحامين في الدائرة الجديدة **لا تعطل الحذف**.
6. المحامي: تنبيهه المدمج ← **صفحة معلقاته مجموعةً بالدوائر** (البند 19 — لا عمود جديد في
   `HeadAlert`) ← إدخال الرقم (فارغ إلزامي يدوي خالص؛ النوع/السنة معبأة بالقديمة) ← حفظ ذري ←
   خروج الملفات من الانتظار؛ التنبيه يُصفّى تلقائيًا عند الصفر.
7. الإنابات تتبع ملفاتها تلقائيًا حسب البند 20 من §2 (بلا تغيير إسناد).
