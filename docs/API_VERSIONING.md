# سياسة إصدار `API` والإهمال

> **الحالة:** ملزمة من `2026-11-25` (`P4-04b` / [`ADR-0011`](adr/0011-api-versioning.md)).
>
> **الخلاصة:** السطح العام **غير مُصدَّر** الآن (`/api/…` بلا بادئة إصدار). آلية الإصدار
> وقت التشغيل (`/api/v1` أو `Accept-Version`) **مؤجلة بقرار موثّق** (الجهة المالكة: مالك
> المشروع؛ الاعتمادية: `staging` لتشغيل نسختين — `P5-04`). ما دامت مؤجلة: **التغيير
> الكاسر ممنوع**، والمسموح هو التغيير الإضافي فقط. لا يُشحن أي تغيير كاسر بلا إصدار.

## 1. تمييز اصطلاحي إلزامي

| المصطلح | المعنى هنا | القيمة الحالية |
|---|---|---|
| **إصدار العقد** (contract version) | حقل `info.version` في لقطة `OpenAPI` — إصدار **وثيقة العقد** | `v1` |
| **إصدار السطح** (API version) | بادئة المسار `/api/v1` أو ترويسة `Accept-Version` — تعايش نسختين وقت التشغيل | **غير موجود** |
| **سجل الإهمال** | ملف `docs/openapi/deprecations.json` — مصدر الحقيقة للإهمالات المعلنة | `[]` (فارغ) |

اسم ملف اللقطة يطابق إصدار العقد: `docs/openapi/docgen-v1.json` ↔ `info.version = "v1"`.
هذا التطابق **مفروض آليًا**؛ تغيير أحدهما بلا الآخر يُفشل الحارس.

## 2. السطح الحالي (بلا إصدار)

- كل المسارات تحت `/api/…` بلا بادئة إصدار — **245 عملية** في لقطة `2026-11-25`.
- `operationId` حتمي بالشكل `Controller_Action` (فريد لكل عملية) — أساس أسماء مستقرة في
  العميل المولَّد.
- لقطة العقد: `docs/openapi/docgen-v1.json` (مُطبَّعة، `LF`، مفاتيح مرتّبة).
- العميل: `frontend/src/api/generated.ts` مولَّد من اللقطة عبر `npm run generate:api`
  (`openapi-typescript`)، وحارس `CI` يفشل عند أي انحراف بينه وبين اللقطة.
- المستهلك الموثّق الوحيد: تطبيق `SPA` المضمَّن في نفس النشر. لا مستهلك خارجي معروف
  حتى `2026-11-25`؛ ظهور أي مستهلك خارجي يُفعّل شرط الإصدار (§3).

## 3. متى نُدخل إصدارًا؟

يجب تفعيل آلية إصدار **قبل** شحن أول تغيير يتحقق فيه أي شرط من:

1. **مستهلك خارجي** لا يمكن ترقيته بالتزامن مع النشر (تكامل، تطبيق جوال، طرف ثالث).
2. **تغيير كاسر** لا يمكن التعبير عنه إضافيًا: حذف/إعادة تسمية مسار أو حقل، تغيير نوع
   حقل أو معدّله (`nullable`/`required`)، حذف قيمة `enum`، تغيير رمز حالة أو عقد خطأ،
   أو تشديد مصادقة/تفويض على عملية قائمة.
3. **انحراف مولَّد** يتطلب تعديل استدعاءات الواجهة بما لا يمكن عزله خلف طبقة توافق.

ما عدا ذلك (مسار جديد، حقل اختياري جديد، مخطط جديد، عملية جديدة) **إضافي** ولا يحتاج
إصدارًا، لكنه يمرّ ببوابة اللقطة والعميل المولَّد (§6).

### 3.1 `/api/v1` أم `Accept-Version`؟

- **الافتراضي عند التفعيل: بادئة المسار `/api/v1`** — ظاهرة في السجلات والكاش والبوابات،
  وتسمح بتشغيل `v1` و`v2` معًا بمحض التوجيه بلا وسيط تفاوض.
- **`Accept-Version` مرفوض الآن:** يتطلب وسيط اختيار + `Vary` + تعقيد كاش + لا يظهر في
  المسار. يُعاد فتحه فقط إذا فرض مستهلك خارجي ثبات المسارات نفسها.
- **`[ApiVersion]` / `Asp.Versioning` لم تُضَف عمدًا:** اعتمادية جديدة + تعديل كل متحكم؛
  تُضاف فقط عند التفعيل الفعلي، لا استباقًا.

## 4. سياسة الإهمال: إعلان ← تشغيل مزدوج ← إزالة

1. **الإعلان (announce):**
   - وسم العملية `deprecated: true` في `OpenAPI` — `Swashbuckle 6.6.2` **يشتقه تلقائيًا**
     من `[Obsolete]` على الإجراء (`SwaggerGenerator.GenerateOperation` يضبط
     `Deprecated = CustomAttributes().OfType<ObsoleteAttribute>().Any()`)، أو يُضاف بوسم
     صريح في فلتر. لا تُفعَّل `IgnoreObsoleteActions` لأنها **تستبعد** الإجراء كليًا بدل
     وسمه.
   - سطر في `docs/openapi/deprecations.json` بالحقول: `operationId`، `deprecatedSince`،
     `replacement`، وواحد على الأقل من `removalVersion`/`removalDate`.
   - سطر في `CHANGELOG.md`/ملاحظات الإصدار يذكر البديل.
2. **التشغيل المزدوج (dual-run):** القديم والبديل يعملان معًا لمدة **90 يومًا على الأقل**
   و**دورة إصدار كاملة واحدة على الأقل** — الأطول بينهما. تُحدَّث الواجهة إلى البديل خلال
   هذه النافذة.
3. **الإزالة (remove):** بعد انقضاء النافذة وبلوغ `removalVersion`/`removalDate`، وبعد
   التأكد أن لا مستدعي في `frontend/` ولا مستهلك خارجي موثّق. **لا إزالة في الإصدار نفسه
   الذي أُعلن فيه الإهمال.**

**الحد الأدنى المطلق للنافذة: 90 يومًا.** أي نافذة أقصر تتطلب قرار مالك مكتوبًا في ملحق
`audit` مؤرخ وتعديلًا صريحًا لهذه الوثيقة — لا استثناء صامت. تُقاس «دورة الإصدار» بظهور
النسخة في `CHANGELOG.md` ونشرها فعليًا، لا بمدة زمنية منفصلة.

> عند تفعيل الإصدار، الإهمال يخصّ النسخة القديمة (`v1`) ويُعلن بديله في النسخة الجديدة
> (`v2`)؛ تبقى `v1` عاملة طوال النافذة ثم تُزال في إصدار كاسر معلن.

## 5. قرار: لا تغيير كاسر بلا إصدار

- ما دام السطح غير مُصدَّر، **لا توجد آلية تعايش**؛ لذلك **التغيير الكاسر ممنوع** حتى تُنفَّذ
  الآلية. هذه ليست توصية بل قاعدة: الحارس يفشل عند أي انحراف في اللقطة/العميل، والمراجعة
  ترفض أي حذف/إعادة تسمية بلا قرار إصدار.
- عند التفعيل: كل تغيير كاسر يُطلق تحت إصدار جديد، وتبقى النسخة السابقة ضمن نافذة §4.
- **تفعيل الآلية قرار مالك صريح** لأنه يمسّ: كل مسار في `API`، عنوان القاعدة في
  `frontend/src/api/client.ts`، وإعادة توليد `generated.ts`، ويحتاج بيئة `staging`
  لتشغيل نسختين فعليًا (`P5-04`). **الحالة: مؤجلة عمدًا — لا `v1` ولا
  `Accept-Version` في هذا الإصدار.**

## 6. البوابات الآلية

| البوابة | ما تفرضه |
|---|---|
| `OpenApiContractTests` | اللقطة مطابقة للمولَّد، `operationId` فريد، معاملات المسار معلنة، مخطط `Bearer` وأمان كل عملية |
| `ApiVersioningPolicyTests` | اسم اللقطة = `info.version`؛ أي مسار `/api/vN` يطابق إصدار العقد؛ `operationId` بنمط `Controller_Action` وفريد؛ وجود `docs/API_VERSIONING.md` و`ADR-0011` وربطهما من الفهرس؛ مطابقة `deprecations.json` للمخطط وللقطة |
| حارس العميل المولَّد (`CI`) | `npm run generate:api` ثم `git diff --exit-code -- src/api/generated.ts` |

**مخطط سجل الإهمال** (مفروض حرفيًا؛ أي مفتاح خارج هذه القائمة يُفشل الحارس):

```json
[
  {
    "operationId": "Documents_Search",
    "deprecatedSince": "2026-12-01",
    "removalVersion": "v2",
    "removalDate": "2027-03-01",
    "replacement": "Documents_SearchV2"
  }
]
```

- `operationId` (إلزامي): عملية موجودة فعلًا في اللقطة، بلا تكرار.
- `deprecatedSince` (إلزامي): `yyyy-MM-dd`.
- `removalVersion` و/أو `removalDate`: واحد على الأقل؛ الإصدار لاحق لإصدار العقد الحالي،
  والتاريخ بعد `deprecatedSince`.
- `replacement` (إلزامي، غير فارغ): العملية/المسار البديل.
- **الاتجاهان مفروضان:** كل عملية `deprecated: true` في اللقطة **يجب** أن تكون مسجّلة
  (لا إهمال غير موثّق)، وكل سطر في السجل **يجب** أن تقابله عملية `deprecated: true` في
  اللقطة (لا سجل بلا إعلان في العقد).

**تحديث اللقطة (واعٍ فقط):**

```bash
UPDATE_OPENAPI_SNAPSHOT=1 dotnet test --filter OpenApiContractTests
cd frontend && npm run generate:api
```

أي تغيير في `deprecations.json` يمرّ بنفس المراجعة، ولا يُقبل سطر بلا بديل أو موعد.

## 8. تشديد مدخلات مالي غير كاسر للشكل (W1 — 2026-11-27)

- `POST /documents/{id}/status` (حقول `collectedAmount`/`collectedAmount2`/`collectedAmount3`
  النصية): تُقبل بالنقطة العشرية فقط (`"1500.50"` أو `"1500.5"`)، وتُقبل فاصلة الآلاف
  **العربية** `٬` (`"١٬٠٠٠"`) بحذفها، ويُرفض الفاصل الألفي/العشري بالفاصلة ASCII
  (`"1,500.50"`، `"1,5"`) بـ`400` برسالة عربية. كان `"1,5"` يُقرأ `15` صامتًا.
- `POST /documents/{id}/executed-status` (حقول `executedPaidAmount*` **الرقمية**): تُرفض
  القيم السالبة، وما يتجاوز `numeric(20,2)`، وأكثر من منزلتين عشريتين (بدل تقريب صامت)
  بـ`400`.
- **أثر توافق:** عميل `API` قديم كان يرسل `"1,500.50"` سيحصل على `400` بدل `1500.5`.
  الواجهة الحالية ترسل النقطة بلا فواصل آلاف فلا تتأثر؛ التغيير تصحيح دلالي وليس تغيير
  شكل، ولا يستوجب إصدار `API` جديدًا بموجب `ADR-0011`.
- لا تغيير في أسماء الحقول أو أنواعها أو رموز النجاح.
