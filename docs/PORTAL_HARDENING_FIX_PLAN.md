# خطة التنفيذ: تصليب البوابة (A + B + P1 + P2)

> **وضع الخطة:** القرارات الأربعة حُسمت (انظر §9) — **بانتظار إذن التنفيذ النهائي.**
> **المرجع:** التقرير النقدي السطري (A تسريب `BranchName` في التصدير، B خطأ النطاق صامت،
> C/D/E/F/G ملاحظات الجودة).
> **القاعدة الذهبية:** أي سياسة حجب تُطبَّق في مسار واحد هي ثغرة مؤجلة — الحل دالة
> واحدة يمرّ بها كل مسار، لا تعليق يُنسخ.

## 1. النطاق

**داخل النطاق (P0 ثم P1 ثم P2):**

| البند | الوصف | الأولوية |
|---|---|---|
| A | توحيد تنقية البوابة بين التفاصيل والتصدير (`ScrubForPortal`) | P0 — حاجب |
| B | إظهار خطأ `my-scope` في `PortalFiles` (إكمال M3) | P0 — حاجب جزئيًا |
| G1 | حارس انعكاس لعقد القائمة `PortalFileListItemDto` | P1 |
| G2 | اختبار قائمة عناوين التصدير المصرّح بها حرفيًا | P1 |
| E1 | استبدال اختبار N1 بتثبيت الترجمة أو حذفه | P1 |
| C | `aria-labelledby` بدل `aria-label` المنفصل في `PortalStatsView` | P2 |
| D | `max` على القيود المرئية بدل المصفوفة كاملة | P2 |
| F | تصحيح تعليق `topCurrencies` (الحذف من العقد يحتاج قرار مالك) | P2 |
| G | توحيد `scope?.entries` الدفاعي (اختياري، قيمة منخفضة) | P2 |

**خارج النطاق صراحةً:** `CorrespondenceService` واختباراته (عمل موازٍ — لا لمس)،
`M2` (كامن حتى تُضاف إعادة جلب النطاق)، `L1` حذفًا من العقد (قرار مالك)، `L5`
(درع توافق يُبقى)، `H3` (منفَّذ بافتراض قرار مسجّل — التراجع سطر واحد عند الطلب).

## 2. المبادئ الملزمة لكل بند

1. **TDD صارم:** اختبار أحمر أولًا (يُشغَّل ويُوثَّق فشله)، ثم إصلاح، ثم أخضر.
2. **لا تغييرات كاسرة:** لا تُمسّ العقود (`DTOs`) ولا أسماء نقاط النهاية ولا سلوك
   القوائم/الفلاتر القائمة إلا بتحديث شامل ومبرر.
3. **لا هجرات EF:** لا يُمسّ أي كيان — كل التعديلات منطق استعلام/عرض/اختبارات،
   فلا إجراء نشر على القواعد.
4. **التحقق الكامل بعد كل مرحلة:** `dotnet test` للمشروعين، ثم
   `npx tsc -b` و `npx oxlint src` و `npx vitest run` و `npm run build` للواجهة.
5. **مراجعة المسار:** تتبّع حقل واحد على الأقل من النهاية للنهاية
   (واجهة ← `DTO` ← خدمة ← قاعدة ← عرض/تصدير) بعد كل تغيير سلوكي.
6. **فحص البقايا:** `grep` عن المعرّفات المستبدلة بعد كل تعديل.
7. **الأمان:** لا أسرار في الكود، والواجهة ليست خط الدفاع الوحيد — الحجب سلكيًا.
8. **الواجهة:** `role="alert"` للأخطاء، `aria-labelledby` للتسميات، `…` لا `...`،
   ولا أبعاد ثابتة تكسر الجوال.

## 3. المرحلة P0 — البند A: توحيد التنقية (تسريب حقيقي)

**العيب (مُثبت سطرًا بسطر):**
`PortalService.GetFileAsync` يحجب `BranchName` (السطر ~184)، بينما
`ExportWorkbookAsync` (269–300) يبني `DocumentResponse.FromEntity` دون أي تنقية،
و`ExcelExportService.BuildValues:105` يطبعه في عمود «الفرع» الثابت
(`BaseColumns:31`) بلا راية تعطيل. الخلايا `InlineString` (السطر 216–217) أي أن
الاختبار السالب على `sheet1.xml` صالح (لا `sharedStrings`).

### 3.1. الاختبار الأحمر أولًا

- **الملف:** `backend/tests/DocGenerator.Application.Tests/PortalFileDetailTests.cs`
  (يحوي `ReadFirstSheetXml` و`SeedInScopeDocAsync` — نفس البنية المعتمدة).
- **الاسم:** `Export_ScrubsInternalBranchName_FromBranchColumn`.
- **المحتوى:** بذر ملف داخل النطاق مع `BranchName = "فرع داخلي سري"` (إن لم تدعم
  `SeedInScopeDocAsync` ضبطه، تُوسَّع بأقل تعديل)، ثم
  `ExportWorkbookAsync`، ثم `Assert.DoesNotContain("فرع داخلي سري", sheetXml)`.
- **الإثبات:** يُشغَّل قبل الإصلاح ويُوثَّق فشله (أحمر). الحالات الحدّية:
  `BranchName = null` (يُصدَّر فارغًا — سليم)، وملف بلا إجراءات.

### 3.2. الإصلاح

- استخراج كتلة التنقية الحالية في `GetFileAsync` (تبدأ عند
  `var response = DocumentResponse.FromEntity(...)`) إلى:
  `private static void ScrubForPortal(DocumentResponse response)`.
- استدعاؤها من `GetFileAsync` (مكان الكتلة الحالية — بلا تغيير سلوكي).
- استدعاؤها من `ExportWorkbookAsync` بعد بناء `responses` (قبل `BuildDocumentsWorkbook`).
- **ممنوع:** تغيير أي عمود آخر، أو إضافة رايات جديدة، أو مسّ `BaseColumns`.

### 3.3. معايير القبول

- الاختبار الجديد أحمر قبل / أخضر بعد، واختبارات التصدير القائمة
  (`Export_DoesNotLeakInternalNotes_IntoExcelColumn`، `Export_TieBreakById…`) خضراء.
- `git diff` يُظهر: دالة واحدة جديدة + استدعاءين + اختبارًا — لا أكثر.

## 4. المرحلة P0 — البند B: خطأ النطاق في `PortalFiles`

**السلوك المقرر (مطابقة `PortalStats.tsx:68,71` — توحيد لا اختراع):**
عند فشل `my-scope` يُعرض تنبيه الخطأ، وتبقى القائمة تعمل كما اليوم (الخادم
يفرض النطاق — فلا تسرب)، بلا منتقي فرع. لا مؤشر تحميل جديد (أقل تغيير).

### 4.1. الاختبار الأحمر أولًا

- **الملف:** `frontend/src/pages/PortalFiles.test.tsx`.
- **الاسم:** `M3b_ScopeFailure_ShowsScopeErrorAlert`.
- **المحتوى:** `my-scope` يرفض، و`/portal/files` ينجح (لعزل المتغير)، ثم التأكد من
  ظهور تنبيه يحمل رسالة الخطأ (`getApiErrorMessage` مُموَّهة أصلًا)، وغياب منتقي الفرع.
- **الإثبات:** يُشغَّل قبل الإصلاح ويُوثَّق فشله (لا يوجد `alert` للنطاق اليوم).

### 4.2. الإصلاح

- إضافة سطر واحد بعد قسم التصدير/الخطأ في `PortalFiles.tsx`:
  `{scopeQuery.error && <div role="alert" className="text-red-600 mb-4">{scopeQuery.error}</div>}`
  بنفس أصناف `PortalStats` حرفيًا.

### 4.3. معايير القبول

- الاختبار الجديد أحمر قبل / أخضر بعد، واختبار M3 الأصلي أخضر، ولا تغيير في أي
  لقطة عرض أخرى. `tsc` و`oxlint` نظيفان.

## 5. المرحلة P1 — تقوية بنيوية

### G1. حارس انعكاس لعقد القائمة

- **الملف:** `PortalRestructureTests.cs` (بجانب الحارس القائم).
- **الاسم:** `PortalListItem_EveryPropertyHasExplicitDisposition`.
- **المحتوى:** نفس بنية الحارس القائم (ثلاث مجموعات: محجوب/مستهلك/مقبول) مطبقة
  على `PortalFileListItemDto`، مع تدقيق حقل-بحقل ضد استهلاك `PortalFileCard`.
- **تحذير صريح:** مسار القائمة بلا دالة تنقية اليوم — إن كشف التدقيق حقلًا
  داخليًا، يُستخرج حجب مماثل في `ListFilesAsync` (قد يتوسع البند — يُعاد تقديره
  قبل التنفيذ لا أثناءه).

### G2. قائمة عناوين التصدير المصرّح بها

- **الاسم:** `PortalExport_HeadersMatchDeclaredAllowlist`.
- **المحتوى:** تصدير فارغ/عينة عبر `ExportWorkbookAsync`، واستخراج خلايا الصف الأول
  من `sheet1.xml` بالترتيب، ومقارنتها بقائمة حرفية
  (`الحالة، طالب التنفيذ، الفرع، …`) مع الرايات `false/false/false`.
- **القيمة:** أي عمود مستقبلي يُجبر صاحبه على قرار صريح بدل التسلل مع `BaseColumns`.

### E1. حسم اختبار N1

- **الخيار الموصى (أ):** استبدال `Dashboard_LegacyForciblyNullSubstatus_CountsAsExecuted`
  باختبار `Dashboard_NullSubstatusCompensatedInSql` يبني إسقاط العدّ نفسه
  ويؤكد أن `ToQueryString()` تحتوي `IS NULL` — فيُثبَّت **مصدر الحماية الحقيقي**.
  القيد المعلن: الاختبار يغطي SQLite (بيئة الاختبار) والتعويض على مستوى EF
  فينطبق على Postgres، فيُوثَّق ذلك في تعليق الاختبار.
- **الخيار (ب):** حذف الاختبار إن رُئي أن تثبيت سلوك المولّد هشاشة غير مجدية.
- **المطلوب من المالك:** اختيار (أ) أو (ب) قبل التنفيذ — الافتراض: (أ).

## 6. المرحلة P2 — صيانة مجدولة

- **C:** إعطاء `h4` التوزيع `id`، واستبدال `aria-label` بـ `aria-labelledby`،
  وتحديث اختبار L3 ليكسر عند أي انفصال لاحق.
- **D:** `Math.max(1, ...visible.map((e) => e.files))` بدل المصفوفة كاملة —
  نفس النتيجة، بلا اعتماد على ترتيب غير موثّق وبلا `spread` واسع.
- **F:** تصحيح تعليق `PortalService:382-383` ليعكس أن الحقل بلا مستهلك؛
  **حذف `TopCurrencies` من العقد يحتاج قرار مالك صريحًا** (تغيير عقد).
- **G:** توحيد `scope?.entries` الدفاعي في `PortalFiles:54,110` و`PortalStats:46,84`
  — اختياري، قيمة منخفضة، يُنفَّذ مع أول لمسة مجاورة لا مستقلًا.

- **الحجم:** A (~30 سطرًا + اختبار)، B (~5 أسطر + اختبار)، G1/G2/E1 (اختبارات
