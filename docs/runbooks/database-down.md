# Runbook — قاعدة البيانات غير متاحة

## الأعراض

- `/readyz` يعيد `503`، و`/healthz` يعيد `200` (العملية حيّة).
- أخطاء `Npgsql` في السجل، أو مهلات اتصال/مجمّع.
- طلبات تفشل بـ`500` عام (بلا تفاصيل داخلية للمستخدم).

## التشخيص

1. `/healthz` للتأكد أن المشكلة ليست عملية التطبيق.
2. السجل: ابحث عن `NpgsqlException`/`Timeout`، ومهلة فحص الجهوزية
   (`Database:Pool:HealthCheckTimeoutSeconds`، افتراضي 5s).
3. من مزوّد القاعدة: الحالة، حدود الاتصالات، القرص، الصيانة الجارية.
4. تحقق من `Database:Pool:MaxPoolSize × عدد النسخ` مقابل حد المزوّد.

## الإجراء

1. إن كان المزوّد في صيانة/انقطاع: انتظر وأبلغ المستخدمين بحالة معلنة.
2. إن كان استنزاف مجمّع: أعد تشغيل النسخ تدريجيًا، وراجع الاستعلامات البطيئة/التصديرات.
3. لا ترفع `MaxPoolSize` عشوائيًا فوق حد المزوّد؛ عدّل وفق [`../../RUN_GUIDE.md`](../../RUN_GUIDE.md) §9.
4. إن كانت القاعدة جديدة/مستعادة وتفتقد المخطط: راجع [`migrations.md`](migrations.md)
   (التطبيق يرفض الإقلاع عند هجرات معلّقة).

## التحقق

- `/readyz` = 200 و`/healthz/outbox` سليم.
- زمن الاستجابة عاد لطبيعته، ولا أخطاء متكررة.

## التصعيد

مزوّد القاعدة فورًا عند انقطاع يتجاوز 5 دقائق، ومالك النظام لأي قرار استعادة من نسخة احتياطية.
