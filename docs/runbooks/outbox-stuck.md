# Runbook — صندوق الصادر (Outbox) متوقف/متراكم

## الأعراض

- `/readyz` = `503` (تأخر أقدم رسالة فوق `HeadAlerts:Outbox:Health:LagThresholdMinutes`).
- `/healthz/outbox` = `Degraded` أو يعرض رسائل فاشلة/عالقة.
- تنبيهات الرأس لا تصل رغم إنشاء التنبيه.

## التشخيص

1. `GET /healthz/outbox` (وسم `outbox`) — العدد المعلّق والفاشل.
2. `GET /readyz` — هل السقوط بسبب القاعدة أيضًا؟
3. السجل: أخطاء `HeadAlertOutboxDispatcher` (اتصال/استعلام/معالج).
4. جدول `HeadAlertOutbox`: `Status`، `Attempts`، `NextAttemptAt`، `LastError` (بلا لصق بيانات حساسة).

## الإجراء

1. **إيقاف مؤقت للتحقيق:** `HeadAlerts:Outbox:Enabled=false` (الرسائل تتراكم ولا تُفقد).
2. أصلح السبب (قاعدة/صلاحيات/سجل) قبل إعادة التشغيل.
3. أعد التفعيل `true` وراقب `Attempts`/`LastError` — المعالجة at-least-once مع idempotency.
4. لا تحذف صفوفًا يدويًا إلا بقرار مالك وبنسخة احتياطية، وبعد فهم سبب الفشل.
5. إن كان التراكم بسبب حمل: افصل المشغّل (نسخة واحدة) ثم أعد التوزيع.

## التحقق

- `/healthz/outbox` سليم، و`/readyz` 200.
- أقدم رسالة معلّقة تحت العتبة، ووصول تنبيه اختباري فعلي.

## التصعيد

مالك النظام إن تجاوز التأخر 30 دقيقة أو تكرر الفشل بعد إصلاحين.
