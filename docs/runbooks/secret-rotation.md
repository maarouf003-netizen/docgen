# Runbook — تدوير الأسرار

## متى

- بعد شكّ في تسرب، أو انتهاء صلاحية مزوّد، أو ضمن جدول دوري معلن.
- **لا تُدوّر `Jwt__Secret`** أثناء ساعات الذروة بلا إعلان: كل الجلسات ستُبطل.

## الأسرار المعنية

| السر | مكانه | أثر التدوير |
|---|---|---|
| `Jwt__Secret` | متغيّر بيئة المنصّة | إبطال كل رموز الجلسات (إعادة دخول جماعية) |
| قاعدة البيانات (كلمة المرور/`DATABASE_URL`) | متغيّر بيئة | انقطاع قصير أثناء تطبيق المزوّد |
| `Bootstrap__AdminPassword` | متغيّر بيئة (لأول بذر فقط) | لا يؤثر بعد إنشاء الحساب؛ يُطلب تغييره أول دخول |
| `security:KnownProxies` | إعداد (ليس سرًا) | لا يمسّ البيانات |

## الإجراء

1. **نسخة احتياطية + نافذة معلنة** (راجع [`deploy.md`](deploy.md)).
2. أنشئ القيمة الجديدة في مزوّد الأسرار/لوحة المنصّة (لا في المستودع، ولا في `appsettings*.json`).
3. حدّث متغيّر البيئة ثم أعد النشر/التشغيل.
4. للقاعدة: دوّر من المزوّد أولًا، ثم حدّث `DATABASE_URL` وأعد التشغيل خلال النافذة.
5. بعد الاستقرار: أرشف القيمة القديمة في خزنة المزوّد (إن يدعم) واحذفها نهائيًا.
6. وثّق التاريخ والسبب في سجل التغييرات (لا القيمة نفسها).

## التحقق

- `/readyz` = 200، ودخول ناجح بحساب اختباري.
- لا أخطاء مصادقة/قاعدة جديدة في السجل.
- حارس `secrets-guard` يبقى نظيفًا (لا سر جديد في المستودع).

## التصعيد

مالك النظام + مزوّد القاعدة عند أي فشل بعد التدوير. عند الاشتباه بتسرب فعلي:
راجع سجل Git بـ`gitleaks` (بند مالك معلّق في `P2-05`) وأبلغ وفق [`../../SECURITY.md`](../../SECURITY.md).
