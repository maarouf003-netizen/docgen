# خطة إصلاح تحذيرات `act(...)` في اختبارات نوافذ الإنابة — تنفيذ مستقل

> خطة قابلة للتنفيذ في محادثة جديدة بالكامل، دون الاعتماد على سياق سابق.
> النسخة: 1.0 — تاريخ: 2026-09-08

---

## 1. الخلاصة التنفيذية

عند تشغيل `npx vitest run` تظهر **3 تحذيرات** `stderr` (لا إخفاقات) من نوع:

```
An update to DelegationFormModal inside a test was not wrapped in act(...).
```

موزعة على اختبارين في `DelegationFormModal.test.tsx` واختبار واحد في
`AssignDelegationModal.test.tsx`. كل الاختبارات الـ13 في الملفين خضراء —
التحذيرات ضجيج فقط، لكنها تخفي إشارات انحدار مستقبلية وتُلوث سجل التشغيل.

**التشخيص**: الاختبارات الثلاثة هي الوحيدة في الملفين التي **لا تحتوي أي `await`**
بعد `render()`، بينما يجلب المكوّنان بيانات عند التركيب (`useEffect` + `api.get`
بسخرية فورية الحل) فيستدعي `setState` بعد إغلاق نطاق `act` التابع لـ `render()`.
الإصلاح: حدّ `await` **واعٍ لـ `act`** (عبر `waitFor`) بعد التركيب في الاختبارات
الثلاثة فقط — **تعديل اختبارات فقط، بلا أي تغيير في كود المنتج**.

|---|-------|--------------------|--------------------------|
| 1 | `DelegationFormModal.test.tsx` | «يعرض حقول النموذج مع الملف المنيب ويحمّل الفروع للاختيار الخارجي» | **صفر** — تأكيدات متزامنة فقط |
| 2 | `DelegationFormModal.test.tsx` | «يختار تلقائيًا الأموال المطابقة عند التعديل ويعرض غير المتاحة كتحذير» | **صفر** — تأكيدات متزامنة فقط |

التمييز حتمي 3/3 مقابل 0/10، وليس صدفة توقيت.

## 3. السبب الجذري (آلية دقيقة خطوة بخطوة)

1. `render(<DelegationFormModal .../>)` يركّب المكوّن داخل نطاق `act` متزامن.
2. `useEffect` التركيب (`DelegationFormModal.tsx:52-66` / `AssignDelegationModal.tsx:26-39`)
   يستدعي `api.get('/branches')` أو `api.get('/users/lawyers')` **تزامنيًا** داخل النطاق.
3. السخرية في الاختبار (`mockResolvedValue`) وعدٌ محلول سلفًا، فتُحجز متابعة
   `.then((r) => { ... setBranches/setLawyers ... })` كـ microtask.
4. الاختبار يواصل عملًا **متزامنًا خالصًا** (`getBy*` + `expect`) ويعود دون أي `await`،
   فيُغلق نطاق `act` الخاص بـ `render()` أولًا، **ثم** تُنفَّذ المتابعة المحجوزة.
5. `setBranches`/`setLawyers` تُستدعى والمكوّن مركّب لكن **خارج أي نطاق `act`**
   → التحذير. (حارس `cancelled` في المكوّنين سليم ويغطي الفكّ بعد التنظيف فقط —
   وهنا لا فكّ بعد؛ التحديث يقع **بين** إغلاق `act` وبدء التنظيف، لذا لا يمنعه.)

**إغلاق التسريب (تحقق مقابِل):** `DelegationDetails.tsx` — المكوّن المضمَّن الوحيد
في `AssignDelegationModal` — **بلا أي `useEffect`/جلب** (عُرضي خالص، 92 سطرًا)،
و`onClose`/`onSaved` في الاختبارين دالتان فارغتان (`noop`). إذن الجلبان المذكوران
هما **المصدران الوحيدان** للتحديثات بعد التركيب، وعدد التحذيرات (3) = عدد الاختبارات
التي لا تنتظر شيئًا — إحكامٌ حتمي لا ثغرة فيه.

**قيد تقني صارم يُبنى عليه الإصلاح**: `await` عارية (`await Promise.resolve()`)
**لا تُصلح** — فهي تُنفّذ المتابعة خارج `act` أيضًا ويبقى التحذير. المطلوب حدّ
**واعٍ لـ `act`**: `waitFor` / `findBy` / أفعال `userEvent` (نطاقات `act` غير
متزامنة تبتلع التسوية بداخلها). أي «تبسيط» مستقبلي للحدّ المُنتظَر إلى تأكيد
متزامن **يُعيد** التحذير — وُثّق هنا لمنع الانحدار.

## 5. حزمة العمل (3 إدخالات + استيراد واحد — لا غير)

القاعدة: **حدّ `waitFor` واحد على نداء الجلب التركيبي بعد `render()` مباشرة**،
يوثّق عقد «الجلب عند التركيب» ويُفرغ `setState` داخل `act`. لا تُغيَّر أي منتقيات،
ولا تُحوَّل التأكيدات المتزامنة إلى `findBy` (إبقاء الفرق أدنى).

### 5.1 `DelegationFormModal.test.tsx` — الاختبار الأول (السطور 63-79)

بعد كتلة `render(...)` (بعد السطر 72: `);`)، أضف:

```tsx
    // حدّ act للجلب التركيبي: يُفرغ setBranches داخل نطاق مُنتظَر قبل التأكيدات المتزامنة.
    await waitFor(() => expect(api.get).toHaveBeenCalledWith('/branches'));
```

(`waitFor` مستوردة سلفًا في السطر 2 — لا تغيير استيراد.)

### 5.2 `DelegationFormModal.test.tsx` — اختبار «يختار تلقائيًا…» (السطور 200-218)

بعد كتلة `render(...)` (بعد السطر 209: `);`)، أضف السطر نفسه:

```tsx
    // حدّ act للجلب التركيبي: يُفرغ setBranches داخل نطاق مُنتظَر قبل التأكيدات المتزامنة.
    await waitFor(() => expect(api.get).toHaveBeenCalledWith('/branches'));
```

### 5.3 `AssignDelegationModal.test.tsx` — اختبار «يُظهر رسالة الفرع المناب…» (السطور 71-86)

خطوتان (هذا الملف **لا يستورد `waitFor`** حاليًا — السطر 2):

1. السطر 2 من:
   ```tsx
   import { render, screen } from '@testing-library/react';
   ```
   إلى:
   ```tsx
   import { render, screen, waitFor } from '@testing-library/react';
   ```
2. بعد كتلة `render(...)` (بعد السطر 81: `);`)، أضف:
   ```tsx
   // حدّ act للجلب التركيبي: يُفرغ setLawyers داخل نطاق مُنتظَر قبل التأكيدات المتزامنة.
   await waitFor(() => expect(api.get).toHaveBeenCalledWith('/users/lawyers'));
   ```

**ممنوع في هذه المهمة**: لمس المكوّنين (`cancelled` صحيح)، إضافة `await` عارية،
استخدام `.only`/`.skip`، تغيير أي منتقي أو حمولة متوقعة، تغيير عدد الاختبارات
(يبقى 8 + 5 = 13).

## 6. البدائل المرفوضة (مُوثقة لمنع إعادة طرحها)

| البديل | سبب الرفض |
|--------|-----------|
| تعديل المكوّن (إلغاء الجلب/تأخيره) | سلوك المنتج صحيح؛ حارس `cancelled` يغطي الفكّ الحقيقي. المشكلة في الاختبار لا المنتج |
| `await Promise.resolve()` بعد `render()` | تُنفّذ التسوية خارج `act` — لا تُزيل التحذير (§3) |
| تحويل التأكيدات إلى `findBy` | يُضخم الفرق دون مبرر؛ `waitFor` على عقد الجلب أوضح وأدق |
| سخرية مؤجلة يدوية (`deferred`) | تعقيد بلا مقابل؛ السخرية الفورية هي الحالة الواقعية للجلب التركيبي |
