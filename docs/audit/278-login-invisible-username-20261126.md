# إصلاح دخول: محارف اتجاه غير مرئية في اسم المستخدم — 2026-11-26

> **العَرَض:** حساب موجود ونشط وكلمة مروره صحيحة برمجيًا، لكن شاشة الدخول تعيد
> «اسم المستخدم أو كلمة المرور غير صحيحة».
>
> **السبب (مثبت بالدليل):** سجل تدقيق الدخول حفظ اسمًا طوله **14** بدل **13**،
> وبترميز `UTF-8` ينتهي بـ`e2 81 a9` = **U+2069 (POP DIRECTIONAL ISOLATE)**.
> هذا محرف تنسيق اتجاه يُلصق عند نسخ نص من واجهة RTL/Markdown، و`Trim()` في .NET
> لا يحذفه لأنه ليس مسافة. فيفشل البحث عن المستخدم بلا أي عدّ إخفاق (المستخدم غير موجود).

## 1. الإصلاح

| الطبقة | التغيير |
|---|---|
| الخلفية | `UsernameInput.Normalize`: يحذف `UnicodeCategory.Format`/`Control` ثم `Trim`؛ يستخدمه `LoginCommand` و`UserManagementService.NormalizeUsername`. |
| الواجهة | `normalizeUsernameInput` يحذف `U+200B–U+200F`/`U+202A–U+202E`/`U+2066–U+2069`/`U+FEFF` ويقصّ المسافات، ويُستخدم في `Login` قبل الإرسال. |
| الاختبارات | `UsernameInputTests` (7 حالات) + اختبار دخول باسم يحمل `U+2069` + اختبارا واجهة (Utility + Login). |
