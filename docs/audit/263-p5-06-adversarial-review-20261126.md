# المراجعة العدائية لـ`P5-06` والملحق التصحيحي — 2026-11-26

> **الهدف:** محاولة كسر أدوات النسخ/الاستعادة فعليًا: استعادة بلا تأكيد، هدف إنتاجي بالخطأ،
> بيئة غير مضبوطة، بصمة تالفة، مفتاح غائب، جدول/اسم غير آمن، وتعديل الحارس نفسه.
>
> **المراجع:** `docs/audit/261` (التنفيذ)، `docs/audit/262` (المراجعة النقدية)،
> `scripts/backup/*`، `docs/runbooks/backup-restore.md`.
>
> **النتيجة:** كل المحاولات المخطَّطة رُفضت عند الحاجز الصحيح، ولم تُنفَّذ أي عملية هدّامة.
> أُصلحت 3 نقاط إضافية ظهرت أثناء الاختبار (C-7، C-8، C-9 في الملحق).

## 1. المنهج والبيئة

- بيئة: `Windows` + `Git Bash` + `Windows PowerShell 5.1` + `Node 24`.
- **لا** أدوات `PostgreSQL` حقيقية محليًا؛ استُخدم مِجسّ `PATH` بأدوات وهمية
  (`pg_dump`, `pg_restore`, `psql`, `gpg`) لتسجيل الاستدعاءات والوسائط والتحقق من **التدفق
  والحواجز**، لا من محرّك PostgreSQL.
- المِجسّ يتتبّع: هل نُفِّذ `pg_restore`؟ بأي خيارات؟ هل سبقه `TRUNCATE`؟ ما رأس الهجرة؟
  هل كُتب ملف في وضع المعاينة؟
- الحارس شُغِّل بـ`--self-test` مع 8 تعديلات غير آمنة في الذاكرة.

## 2. محاولات الكسر والنتائج

| # | المحاولة | الأمر/الشرط | النتيجة المرصودة |
|---|---|---|---|
| A-1 | استعادة بلا تأكيد | `pg-restore.sh --file ... --target-db docgen_restore` | **رفض** `Refusing to restore without --yes`؛ سجل الأدوات لا يحوي `pg_restore` |
| A-2 | استعادة إلى اسم إنتاجي | `--target-db docgen_prod --yes` | **رفض** حارس الإنتاج؛ لا استدعاء `pg_restore` |
| A-3 | استعادة إلى قاعدة `postgres` الافتراضية | `--target-db postgres --yes` (bash وPS) | **رفض** «looks like PRODUCTION»؛ لا استدعاء |
| A-4 | الاستعادة فوق مصدر النسخة | `--target-db docgen --allow-nonempty --yes` مع `.meta.json` يطابق المضيف/القاعدة | **رفض** «same host+database the backup came from» |
| A-5 | بيئة اتصال غائبة | `env -u POSTGRES_CONNECTION pg-restore.sh ...` | **رفض** قبل قراءة الملف/الاتصال |
| A-6 | بصمة تالفة | إلحاق بايت بالنسخة مع إبقاء `.sha256` | **رفض** `checksum mismatch` قبل أي `pg_restore` |
| A-7 | ملف بصمة غائب | `--checksum-file /nonexistent` | **رفض** «refusing to restore an unverified backup» |
| A-8 | بصمة تخص ملفًا آخر | نسخ بصمة ملف إلى ملف مختلف | **رفض** «checksum file names a different artifact» |
| A-9 | هدف غير فارغ | استعادة كاملة إلى قاعدة فيها 52 جدولًا بلا `--allow-nonempty` | **رفض** قبل الاستعادة |
| A-10 | جدول غير آمن/حقن | `--table 'Documents;DROP TABLE x'` | **رفض** تحقق المعرّف؛ لا `psql`/`pg_restore` |
| A-11 | `--truncate-table` بلا `--table` | `--truncate-table --yes` | **رفض** خطأ استخدام |
| A-12 | مشفّر بلا مفتاح | `verify/restore` لملف `.gpg` دون `BACKUP_ENCRYPTION_KEY` | **رفض** قبل أي قراءة/استعادة |
| A-13 | معاينة تكتب ملفًا | `pg-backup.sh --dry-run` / `ps1 -WhatIf` | **لا ملف/لا مجلد**؛ خطة فقط |
| A-14 | تسريب سر في السجل | grep على مخرجات النسخ/الاستعادة/المعاينة | لا `p@ss` ولا URI خام؛ الوصف `password=***` فقط |
| A-15 | تعديل الحارس | حذف `--dry-run`, `--yes`, `--allow-production`, التحقق، `-WhatIf`, إدخال `PGPASSWORD="..."` | **الحارس رفض 8/8** تعديلات (self-test) |

**الاختبار الوظيفي:** المِجسّ نفّذ **58/58** فحصًا ناجحًا للتدفق (نسخ/تحقق/استعادة كاملة/
جزئية/تشفير/PS/bash/تقليم/حواجز). هذه أدلة تدفّق لا أدلة محرّك؛ التمرين الحقيقي يبقى الحاكم.

## 3. محاولات كسر إضافية (نتائج/قيود)

| # | المحاولة | النتيجة |
|---|---|---|
| B-1 | تمرير مسار Windows إلى `bash` على Git Bash | **كشف عيبًا**: `sha256sum` يسبق السطر بـ`\` عند المسار ذي الشرطة العكسية، فتفشل المقارنة. أُصلح (C-9)؛ يبقى مسار Windows مدعومًا رسميًا عبر PowerShell |
| B-2 | `-WhatIf` على استعادة PowerShell | كشف عيبين أُصلحا: تسرّب `WhatIf` إلى `Get-FileHash` (C-3)، وتمرير SQL عبر `argv` (C-4). الآن يُطبع `DRY-RUN` بلا كتابة |
| B-3 | استخدم `--allow-production` مع `postgres` | يسمح صراحةً ويطبع تحذيرًا؛ القرار للمالك في نافذة تغيير |
| B-4 | تشفير بـ`gpg` وهمي ثم فك | المسار يعمل تدفقيًا؛ لم يُختبر `gpg` الحقيقي (غير مثبت) — يُختبر في التمرين |
| B-5 | استعادة جدول مع `--truncate-table` | `TRUNCATE` يُسجَّل **قبل** `pg_restore`؛ الفشل بعد الحذف يترك الجدول فارغًا (موثّق) |
| B-6 | استعادة كاملة إلى هدف فيه جداول مع `--allow-nonempty` | تُمرَّر؛ `--single-transaction` يُرجع عند التصادم (لا `--clean` تلقائي) |

## 5. ما لم يُكسر (إثبات سلبي)

- لا مسار في السكربتات ينفّذ `DROP`/`TRUNCATE` تلقائيًا؛ `TRUNCATE` يتطلب `--truncate-table`
  + `--table` + `--yes`.
- لا استعادة بلا بصمة (السكربت يرفض غياب `.sha256`؛ لا خيار `--skip-checksum`).
- لا `--allow-production` ضمني؛ حتى اسم `postgres` يحتاجه.
- لا أسرار في `argv` (كلمة المرور في `PGPASSWORD` فقط)؛ `gpg` عبر stdin، `openssl` عبر
  `-pass env:`, والوصف يحجب.
- لا كتابة في `--dry-run`/`-WhatIf` (تم التحقق من عدم وجود ملف/مجلد).
- لا تعديل على كود التطبيق/المخطط/الهجرات.

| R-4 | لا محرّك `PostgreSQL` حقيقي في الاختبار | متوسط؛ التمرين الشهري شرط `DoD` |
| R-5 | مسار bash على Windows غير قياسي (`/c/...`) | منخفض؛ PowerShell هو المسار الرسمي على Windows، وباش لـLinux/WSL |

## 7. الحكم النهائي

الحواجز تعمل في الاتجاه الصحيح: **رفض قبل الكتابة**، ورفض الإنتاج بلا علم صريح، ورفض البصمة
التالفة/الغائبة، وعدم كتابة أسرار. لا توجد محاولة في هذه المراجعة أدت إلى استعادة غير
مصرَّح بها أو إلى طباعة سر. يبقى الإثبات النهائي (استعادة حقيقية موقّعة + `PITR`) مسؤولية
مالك/تشغيل، ومعلنًا كذلك في الخريطة والدليل.
