## 1. الحالات والنتائج

| # | ما فُحص | النتيجة | الإجراء |
|---|---|---|---|
| C-1 | **تجاوز حارس القاعدة بمفاتيح مكرّرة**: `Host=evil;...;Host=127.0.0.1` — Npgsql قد يقرأ الأول ونحن نقرأ الأخير | **عيب حقيقي:** تفسير مزدوج يسمح بقاعدة بعيدة | رُفضت المفاتيح المكرّرة صراحةً في `parseE2eConnectionString` + حالات اختبار |
| C-2 | **تجاوز URI عبر معاملات الاستعلام**: `postgres://…/docgen_e2e?Host=remote` (Npgsql يقرأ بعض معاملات الاستعلام كإعدادات) | **عيب حقيقي:** فحص المضيف يُتجاوز | رُفض أي `search`/`hash` في URI + حالة اختبار |
| C-3 | **سلسلة قاعدة غير مفحوصة عند عدم الإدارة**: كان الفحص مقصورًا على `E2E_MANAGED_SERVERS=1` | **عيب حقيقي:** تمرير `E2E_DB_CONNECTION` إنتاجية أثناء الاتصال بخادم قائم لا يُرفض | صار يُفحص متى وُجدت السلسلة، والإدارة تشترط وجودها |
| C-4 | **تباين الألوان في الشاشات المفحوصة بـ`axe`**: `text-gray-400` على أبيض (2.5:1)، و`text-emerald-600` على أبيض (3.8:1)، وتذييل الدخول `text-gray-500` على `slate-100` (~4.1:1) | **عيب حقيقي:** `color-contrast` = `serious` كان سيُفشل البوابة | حالات الفراغ/التذييل ← `gray-600` (7:1)، وتاريخ الإجراء ← `emerald-700` (5.5:1) |
| C-5 | **حتمية البذر**: هاش `PBKDF2` مطابق لصيغة التطبيق، idempotent، مينيمالي | **سليم:** الهاش تحقق منه بـ.NET `Rfc2898DeriveBytes`؛ 1 فرع + 4 حسابات فقط؛ `WHERE NOT EXISTS` + تحقق اكتمال | لا تغيير |
| C-6 | **جاهزية خدمة `postgres` في CI**: هل تُشغَّل الخطوات قبل الجهوزية؟ | **سليم:** `--health-cmd pg_isready` يجعل GitHub ينتظر الجهوزية؛ `dotnet ef` ينشئ `docgen_e2e`؛ البذر يفشل عند نقص الحسابات | لا تغيير |
| C-7 | **صحة وظيفة `CI`**: استعادة مقفلة، بناء قبل `--no-build`، تثبيت Chromium، `psql`، رفع الآثار | **عيب حقيقي أُصلح:** مصنع زمن التصميم يشترط `POSTGRES_CONNECTION` حتى مع `--connection` — يُصدَّر الآن من سلسلة E2E قبل `dotnet ef`؛ بقية الترتيب صحيح، ووظائف `ci.yml` الست القائمة دون مساس | تصدير `POSTGRES_CONNECTION` في خطوة الهجرة |
| C-8 | **عتبة `axe`**: هل هي عتبة حقيقية؟ | **سليم:** `critical`/`serious` فقط مع وسوم WCAG 2.0–2.2، وقائمة تبييض فارغة، وتفشل عند أي مخالفة غير مسموحة | لا تغيير؛ أُصلح C-4 مسبقًا |
| C-9 | **`flake` من انتظارات ثابتة**: بحث عن `waitForTimeout`/`sleep` | **سليم:** لا توجد؛ كل الانتظار عبر `expect` الذاتي أو `waitForResponse` | لا تغيير |
| C-10 | **فحص 375px حقيقي**: هل يقيس فعليًا؟ | **سليم:** مشروع `mobile` بـ`viewport 375×812` و`isMobile`؛ يقيس `documentElement.scrollWidth` و`body.scrollWidth` مع هامش 1px | لا تغيير |
| C-11 | **إعادة استخدام خادم API قائم**: قد يكون على قاعدة أخرى | **سليم:** `reuseExistingServer: false` للـAPI؛ فشل صريح بدل اختبار على قاعدة مجهولة؛ وVite بـ`--strictPort` فلا ينتقل صامتًا لمنفذ آخر | لا تغيير |
| C-12 | **تعدد العمال وتصادم البيانات**: قاعدة بذر مشتركة | **سليم:** عامل واحد + `fullyParallel: false`؛ مبرر مكتوب في الإعداد | لا تغيير |
| C-13 | **مراجع ARIA إلى عناصر غير مُصيَّرة في التنبيهات**: `aria-controls` لتبويب غير نشط، و`aria-labelledby` للوحة في عرض المدير بلا تبويبات | **عيب حقيقي:** IDREF مفقود = `aria-valid-attr-value` (خطير) | `aria-controls` للتبويب النشط فقط، وإسقاط `role=tabpanel`/`id`/`aria-labelledby` في عرض المدير + اختبارا وحدة |

## 2. مخاطر مقبولة ومعلنة

| الخطر | لماذا مقبول الآن | متى يُغلق |
|---|---|---|
| قاعدة staging تُقبل بشرط `E2E_ALLOW_STAGING=1` + احتواء الاسم `staging` | الراية يقرّرها المالك؛ لا يمكن ضمان أن نطاقًا ما «ليس إنتاجًا» بالنص وحده. القيمة الافتراضية fail-closed | عند توفير قائمة نطاقات staging معتمدة (allowlist صريحة بالمضيف الكامل) |
| لا لقطات بصرية بعد | إضافتها بين Chrome المحلي وChromium المثبَّت تُنتج `flake` عابرًا؛ لم نُدخل مرجعيات غير موثوقة | عند إضافتها في CI فقط بـChromium المثبَّت (موثّق في `runbooks/e2e.md`) |
| `E2E_PASSWORD` ثابتة في المصدر | كلمة مرور قاعدة مؤقتة تُهدم بعد التشغيل، ومعلنة في البذر/الدليل؛ لا تصل أي بيئة منشورة | لا حاجة؛ أي تغيير مستقبلي يبقيها اختبارية فقط |
