# `P5-07` — إغلاق Runbooks وPostmortem — 2026-11-22

> **النطاق:** تدقيق تغطية runbooks الحوادث، وإضافة قالب postmortem بلا لوم.
> **لا تغيير في الكود أو الهجرات.**

## 1. ما نُفِّذ

1. تدقيق Runbooks الموجودة: `deploy`, `rollback`, `migrations`, `database-down`,
   `auth-outage`, `outbox-stuck`, `secret-rotation`, `load-testing` — كلها تغطي
   **الأعراض → التشخيص → الإجراء → التحقق → التصعيد**.
2. `docs/runbooks/postmortem-template.md`: قالب بلا لوم يحوي الملخص، الأثر، الاكتشاف،
   الخط الزمني (UTC)، السبب الجذري/العوامل، الاستجابة، إجراءات بمالك/تاريخ/حالة،
   والدروس والاعتماد.
3. فهرس `docs/runbooks/README.md` يربط القالب.

## 2. ما كشفته المراجعة النقدية

| # | الوجد | الدليل | الإصلاح |
|---|---|---|---|
| 1 | لا قالب postmortem موحّد | لا ملف في `docs/runbooks` | أُضيف قالب كامل بلا لوم |
| 2 | خطر «إجراءات بلا مالك/تاريخ» | القالب القديم غير موجود | جدول إجراءات يلزم المالك والتاريخ والحالة |
| 3 | runbook الحمل أُضيف في `P3-07` لكن الفهرس قد لا يعرفه | `docs/runbooks/README.md` | أُضيف صف `load-testing` + صف `postmortem-template` |
| 4 | تغطية الحوادث | فحص الملفات الثمانية | لا فجوة معروفة ضمن النطاق |

## 3. التحقق

| البوابة | النتيجة |
|---|---|
| الحراس الخفيفة | نظيفة |
| فهرس runbooks | يعرض كل الملفات (بما فيها الجديدان) |
| الهجرات | لا تغيير (المعلّقة 6) |

## 4. الحدود

- تنفيذ postmortem الفعلي بعد حادثة مسؤولية المالك/الفريق؛ القالب يوحّد المحتوى
  ويمنع إغفال الإجراءات القابلة للقياس.
