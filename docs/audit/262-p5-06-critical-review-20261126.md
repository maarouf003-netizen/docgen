# المراجعة النقدية لـ`P5-06` — أدوات النسخ/الاستعادة/`DR` — 2026-11-26

> **الموضوع:** مراجعة نقدية مستقلة (قبل الدمج) لسكربتات النسخ الاحتياطي والاستعادة والتحقق
> وحارسها، مقابل `PostgreSQL 16`، وبلا افتراض أن «الاختبارات الذاتية تكفي».
>
> **المراجع:** `docs/audit/261` (التنفيذ)، `docs/runbooks/backup-restore.md`،
> `scripts/backup/*`، `RUN_GUIDE.md` §9، `docs/PERFECTION_ROADMAP.md` §`P5-06`.
>
> **النتيجة:** 7 عيوب اكتُشفت وأُصلحت (بينها 3 حرجة/عالية في المسار الحرج)، و4 مخاطر
> متبقية معلنة؛ لا حاجز أمان أُزيل.
> **الحكم:** صالح للدمج **بشرط** بقاء تمرين الاستعادة الحقيقي شرطًا لـ`DoD` (وهو معلن).

## 1. المنهج

1. تتبّع كل مسار: تحليل اتصال → نسخة → بصمة → metadata → تحقق → استعادة → فحص دخاني، في
   `bash` و`PowerShell` على حدة.
2. فحص دلالات `pg_dump`/`pg_restore`/`psql` لإصدار 16 (خيارات، stdin/stdout، معاملة واحدة،
   `-t`، `--data-only`، `--no-owner`).
3. محاولات عدائية عملية عبر أدوات وهمية في `PATH` (58 فحصًا) — انظر `263`.
4. تشغيل `backup-scripts-guard.mjs --self-test` (6 اختبارات + 8 تعديلات مرفوضة).
5. تدقيق الأسرار والترتيب والحالات الحدّية (بيئة غائبة، بصمة تالفة، مفتاح غائب، هدف إنتاجي).

## 3. فحص السلامة (بعد الإصلاح)

### 3.1 الأسرار

- لا سلسلة اتصال أو كلمة مرور مكتوبة في السكربتات (الاستثناءات: قيم اختبار
  `example.test` وسطرا تعليمات بعلامات `<user>/<password>`).
- `POSTGRES_CONNECTION` يُحذف من البيئة بعد التحليل؛ `PGPASSWORD` يُمرَّر لعملية الطفل فقط.
- `pg_dump/pg_restore` تُستدعى بـ`--no-password` (فشل سريع بدل تعليق).
- السجل يطبع وصفًا محجوبًا فقط؛ الحارس يرفض أي `echo/printf/Write-*` يطبع `$PGPASSWORD` أو
  `$POSTGRES_CONNECTION`، وأي `--password` أو `PGPASSWORD="..."` حرفي.
- البيانات الوصفية تحوي `host/db/user` (غير سرية) ولا كلمة مرور؛ اختبار grep على metadata
  في المِجسّ أكد غياب `password`.
- الاختبار الذاتي يؤكد أن كلمة المرور `p@ss:word` لا تظهر في الوصف المحجوب.
- استثناءات `scripts/secrets-baseline.json` الأربعة تخص قيم اختبار وهمية على
  `db.example.test` فقط (URI/مفتاح كلمة مرور)، وأسبابها مكتوبة بدقة؛ أي زيادة لاحقة في
  الملف تُفشل الحارس.

### 3.2 العمليات الهدّامة

| السيناريو | النتيجة |
|---|---|
| استعادة بلا `--yes` | رفض قبل أي `pg_restore` (سجل الأدوات الوهمية لا يحوي استدعاء) |
| هدف `docgen_prod` / `postgres` / مضيف `prod.*` | رفض بلا `--allow-production` |
| استعادة فوق مصدر `.meta.json` نفسه | رفض بلا `--allow-production` |
| بصمة تالفة/مفقودة/تخص ملفًا آخر | رفض قبل الاتصال الكتابي |
| هدف غير فارغ (كامل) بلا `--allow-nonempty` | رفض قبل الاستعادة |
| `--truncate-table` بلا `--table` أو اسم جدول غير آمن | رفض في تحليل الوسائط |
| هدف `template0/template1` | رفض دائم |
| استعادة مشفّرة بلا مفتاح | رفض (لا يمكن التحقق من الأرشيف) |
| `--dry-run`/`-WhatIf` | لا ملفات، لا كتابة؛ تحقق/تخطيط فقط |

### 3.3 صحة `pg_restore` ( PostgreSQL 16 )

- `--single-transaction` + `--exit-on-error` يعطيان تراجعًا كاملًا عند أي خطأ (لا استعادة
  جزئية صامتة). لا `--jobs` معه.
- `--no-owner --no-privileges` يمنع فشل الأدوار عبر البيئات، ويُوثّق أن الصلاحيات لا تُنقل.
- `--data-only -t <table>` للاستعادة الجزئية؛ `--truncate-table` قبلها خارج المعاملة
  (موثّق كخطر). المدخلات تُقيَّد بـ`^[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)?$`
  وتُقتبس في SQL.
- `pg_restore --list -` و`--data-only -t ... --file=- -` يقرآن من `stdin`؛ مسار bash يعتمد
  على أن `pg_restore` يستهلك التدفق كاملًا (ملف custom). هذا صحيح عمليًا؛ إن أُغلق الأنبوب
  مبكرًا فقد تظهر إشارة `SIGPIPE` من `gpg` مع `pipefail` — احتمال منخفض، ومعالجة الاستعادة
  الجزئية تستخدم `|| true` مع تحقق الصفوف. **مخاطرة متبقية R-1** أدناه.
- فحص الدخان: `information_schema` + `to_regclass('public."Documents"')` + رأس
  `__EFMigrationsHistory` (مطابقة الأرشيف للكامل) + عدد صفوف `Documents`.
- `psql` يستخدم `ON_ERROR_STOP=1` و`--no-psqlrc`، والاستعلامات للقراءة فقط قبل التأكيد.

### 3.4 التشفير

- `gpg` AES-256 عبر stdin (لا `argv`)، و`openssl` عبر `-pass env:` (لا `argv`).
- فك التشفير مطلوب للتحقق، وفشل المفتاح/الملف = رفض.
- `PowerShell` يستخدم ملفًا مؤقتًا للفك (ضرورة تقنية)، ويستدعي `Remove-SensitiveFile`
  (كتابة أصفار ثم حذف) في `finally`. **مخاطرة متبقية R-2** (نافذة وجود ملف نصّي مؤقت).

### 3.5 البصمة

- تُحسب على **الملف النهائي** (بعد التشفير إن وُجد)، وتُخزَّن بصيغة متوافقة مع `sha256sum -c`.
- `verify_checksum` يتحقق من: وجود الملفين، صيغة 64 hex، **اسم الملف** داخل البصمة، ثم
  المقارنة. هذا يمنع خلط بصمة ملف بملف آخر.
- لا توقيع غير متماثل؛ البصمة سلامة لا أصالة. **مخاطرة متبقية R-3** أدناه.

### 3.6 `RPO/RTO`

- الأهداف المعتمدة (24 ساعة/4 ساعات) بقيت كما هي، ولم تُستبدل باقتراح `15 دقيقة/ساعتان`.
- الاقتراح معلن كغير معتمد ومشروط بـ`PITR` وتمرين مُقاس؛ لا تناقض مع `RUN_GUIDE §9`.
- الدليل يفصل بوضوح بين «أدوات مُسلَّمة» و«تعافٍ مُثبت» (تمرين موقّع).

## 4. المخاطر المتبقية (معلنة، لا تُخفى)

| # | المخاطرة | الأثر | التخفيف |
|---|---|---|---|
| R-1 | `decrypt | pg_restore` مع `pipefail` قد يعطي فشلًا كاذبًا إذا أغلق `pg_restore` الأنبوب مبكرًا (`SIGPIPE`) | رفض نسخة صالحة (ليس استعادة خاطئة) | التحقق يفشل بأمان؛ يمكن فك التشفير يدويًا؛ يُختبر في التمرين الحقيقي. لا يُنصح بإزالة `pipefail` عمومًا |
| R-2 | ملف فك تشفير مؤقت في `PowerShell` | تعرّض محتمل أثناء الاستعادة | أصفار + حذف فوري، محطة مخصصة/قرص مشفّر، صلاحيات ملف مؤقت؛ يُفضّل bash على Linux |
| R-3 | بصمة بلا توقيع: من يعدّل الملف والبصمة معًا يمر | نسخة مزوّرة | تشفير + صلاحيات + `object lock` خارجي + مراجعة المصدر؛ التوقيع غير المتماثل خارج النطاق |
| R-4 | لا اختبار `PostgreSQL 16` حقيقي في `CI`/هذه الجلسة | عيب مزوّد قد يظهر متأخرًا | التمرين الشهري الحقيقي شرط `DoD`، والحارس يمنع الانحدار الثابت |
