# `P4-01ah` — إعادة تسمية دائرة التنفيذ (العملية الجماعية) — 2026-11-23

> **قرار النطاق:** مرحلة واحدة في PR مستقل عمدًا: التسمية تمسّ **كل ملفات الدائرة**
> وإناباتها وترحيل نص التنبيهات عبر `Outbox` وتدقيقًا حقيليًا لكل ملف — أخطر عملية
> نُقلت في `P4-01` حتى الآن.

## قبل/بعد

| قبل | بعد |
|---|---|
| `ExecutionCircuitService.RenameAsync` تفتح `_tx.RunAsync` وتنفّذ الجماعية داخلها | `RenameExecutionCircuitCommand` + معالج يملك المعاملة |
| ضمن عقد `IExecutionCircuitService` | أُزيلت من العقد والتنفيذ (لا مستدعٍ غير المتحكم) |
| `LogCircuitDocumentChangeAsync` خاصة في الخدمة | `ExecutionCircuitRules.LogDocumentChangeAsync` مشتركة (تستهلكها التسمية وإعادة القيد والإحالة) |

## الترتيب المحفوظ حرفيًا (داخل معاملة واحدة)

1. فحص الفرع/المحافظة + تطبيع الاسم.
2. `GetOwnedAsync` (فرع + نطاق ملكية)، ثم فحص `Version` برسالته.
3. فحص التكرار الودّي ورسالة المالك (ثلاث صيغ).
4. إن تغيّر الاسم: تحديث الدائرة (`Name/NameNorm/UpdatedAt/Version++`).
5. كل ملفات الدائرة: `Court/CourtNorm/SearchText/FullData/UpdatedAt/Version++` + وقعة
   `CircuitRenamed` لكل ملف.
6. صفوف الإنابة: `DelegatedCourt/DelegatedCourtNorm/UpdatedAt`.
7. `Outbox`: `EnqueueCircuitRenamedAsync` بنص التنبيهات (بالاسم **بعد** التحديث).
8. حفظ ← إبطال كاش الدوائر ← تدقيق حقلي لكل ملف ← تدقيق جماعي:
   `أعاد تسمية دائرة التنفيذ من «…» إلى «…» مع تحديث {n} ملفًا و{m} إنابة`.
9. سباق القيد الفريد → `DocumentConflictException` بالنص العام (بلا ابتلاع؛ يتراجع الوسم).
