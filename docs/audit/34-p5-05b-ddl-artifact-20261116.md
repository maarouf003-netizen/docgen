# P5-05b — أثر SQL للهجرات وقائمة مراجعة النشر — 2026-11-16

> نطاق هذه الجولة: إنتاج سكربت `PostgreSQL` **idempotent** كامل كأثر `CI` لكل تشغيل،
> وتوثيق قائمة مراجعة قبل التطبيق. لا تغيير في الكود ولا الهجرات.

## 1. المشكلة

كانت وظيفة `migration-guard` تولّد سكربتًا مؤقتًا لفحص `datetime2` فقط، ثم تحذفه. المراجع
لا يرى **نص DDL الفعلي** للـPR قبل الدمج، ولا توجد قائمة مراجعة موحّدة تربط حارس
`migration-safety` (P5-05a) بإجراء التطبيق في `RUN_GUIDE`.

## 2. ما طُبّق

1. **`ci.yml` (وظيفة `migration-guard`)**:
   - بعد فحص الأنواع الممنوعة: توليد
     `dotnet ef migrations script --idempotent -o artifacts/migrations/pg-idempotent.sql`
     (بلا اتصال بقاعدة؛ يعتمد `POSTGRES_CONNECTION` الوهمية كما في الخطوات القائمة).
   - رفع الأثر `migrations-sql` (احتفاظ 30 يومًا).
2. **`RUN_GUIDE.md §9`**: قسم «مراجعة SQL الهجرات قبل النشر (P5-05b)»:
   - الأثر المطلوب مراجعته، وترتيب النشر (نسخة احتياطية ← `database update` ← تحقق
     `__EFMigrationsHistory` ← تشغيل النسخة).
   - قاعدة **expand أولًا**، وربط أي هدم باستثناء موثّق في
     `scripts/migration-safety-allowlist.json` (حارس `P5-05a`).
   - منع `--context DocGeneratorDbContext`، وفحص ما قبل النشر للقيود المعتمدة على البيانات.

## 3. التحقق

- توليد محلي بنفس أمر `CI`: نجح، الحجم ≈ `140KB`، ويبدأ بـ`CREATE TABLE IF NOT EXISTS
  "__EFMigrationsHistory"` وكل هجرة محاطة بـ`IF NOT EXISTS(SELECT 1 FROM
  "__EFMigrationsHistory" WHERE "MigrationId" = ...)` — أي أنه آمن لإعادة التشغيل.
- `ci.yml` مُحلَّل بمحلل YAML محلي، والخطوتان الجديدتان ظاهرتان في وظيفة `migration-guard`.
- لا تغيير في الكود/الهجرات؛ الحراس الخمسة خضراء.

## 4. حدود

- الأثر **للمراجعة** لا بوابة عتبة؛ لا يمنع دمجًا بذاته (المنع من `migration-safety-guard`
  و`has-pending-model-changes`).
- لا `dry-run` على قاعدة `staging` ولا نسخة احتياطية آلية — تبقى إجراءات مالك
  (`P5-04`/`P5-06`).
- السكربت `idempotent` مبني على `MigrationsPostgres` فقط؛ لا يغطي `SQLite` (أُزيل من
  التشغيل في `P0-02`).
