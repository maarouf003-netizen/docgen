# إصلاح حارس `CSP` — نهاية وسم `script` بسمات/مسافات (`js/bad-tag-filter`) — 2026-11-18

> اكتشاف من `security-extended` بعد فرز `CodeQL` (`docs/audit/62-…`). تنبيه **حقيقي**
> (high) في أداة بناء، لا في كود التشغيل.

## المشكلة

`frontend/scripts/csp-guard.mjs` كان يطابق نهاية السكربت بـ`</script\s*>` فقط. نهاية
مثل `</script\t\n bar>` (اسمح بها بعض المحلّلات) **لا تُطابق**، فيمرّ سكربت مضمّن بلا
`src` من حارس `CSP` ويصل إلى `dist` — أي خضرة كاذبة في بوابة `P0-CSP` (الحارس نفسه هو
ما يمنع `script-src 'unsafe-inline'`).

## الإصلاح

```js
const SCRIPT_PATTERN = /<script\b([^>]*)>([\s\S]*?)<\/script\b[^>]*>/gi;
```

`\b[^>]*>` يغطي `</script>` و`</script >` و`</script\t\n bar>`. المجموعتان (السمات/الجسم)
بقيتا كما هما، فلا تغيير في منطق الفحص.

## التحقق

- اختبار عقدي مباشر: النص `'<script>alert(1)</script\t\n bar>'` يُطابق مرة واحدة وجسمه
  `alert(1)`؛ النمط القديم كان يفشل.
- `npm run build && npm run guard` في `CI` (السكربت يفحص `dist` الفعلي).
- تنبيه `js/bad-tag-filter` (#1) يُغلق في التحليل التالي بعد الدمج.

## الحدود

- الحارس أداة بناء؛ الخطر التشغيلي كان «مرور سكربت مضمّن»، لا ثغرة في وقت التشغيل.
- لا تغيير في سياسة `CSP` نفسها.
