# مراجعة عدائية وملحق تصحيحي — `P6-02i` — 2026-11-27

## 1. ما جُرّب فعلًا

| المحاولة | النتيجة |
|---|---|
| إرسال جهة عامة بلا `registryId` | **مرفوض** برسالة السجل — اختبار وحدة + اختبار نافذة قائم |
| إرسال طبيعي مع `entityName`/`registryId` | **لا تُرسل** حقول الصفة الأخرى — اختبار وحمولة النافذة |
| تفعيل الممثل مع ورثة موجودين | الورثة `[]` والعنوان `''` في الحمولة — اختباران |
| وريث مسمّى مع عنوان مكتوب | العنوان يُصفَّر فورًا ويُرسل فارغًا — اختباران |
| تاريخ ورود فارغ/فراغ مع ممثل بلا اسم | **الأولوية لتاريخ الورود** ثم اسم الممثل — اختبار |
| «إعادة تعيين» بعد تعديل ممثل/ورثة | تعود الحالة الابتدائية للمتدخل المحفوظ — اختبار نافذة |
| حذف `cleanup`/`aria-label` من زر الإغلاق | اختبارات النافذة لم تكن تغطيها؛ المدقق البصري أكّد بقاءها في القشرة |

## 2. حالات حدّية

- `registryId = 0`: ليس `null` فيُقبل (سلوك سابق نفسه) — لا انحراف.
- `initial = null` مع `receiptDate` فارغ: رسالة تاريخ الورود قبل أي شيء آخر.
- `heirs` غير موجودة (`undefined`): تُعامل `[]` في الانتقالات والحمولة.
- `nature` تتغيّر ذهابًا وإيابًا: بيانات الطلب تبقى، وحقول الطرف تُصفَّر.
- `version = 0`: يُرسل كما هو (لا فحص صحة محلي — الخادم يحكم).

## 3. بقايا

- لا استيراد ميت (`tsc`/`oxlint` نظيفان).
- لا تعريف مكرر: `NamedInput` في `InterventionPartyFields` فقط، والأصناف في
  `interventionStyles` فقط، ولا نسخة من الحمولة في النافذة.
- لا استخدام لـ`type="date"` ولا تغيير في صيغ التواريخ الخمس.
