# قائمة النشر — النسخة النهائية (v2)

> **التاريخ**: 2026-10-17. يُحلّ محل `DEPLOY-CHECKLIST.md` (2026-10-16) ويبقى الأصل محفوظًا كنسخة.
> **الشرط المسبق**: البوابات الأربع خضراء على الفرع (`backend` + `frontend` + `guards` + `audit`) — وهي خضراء في CI الحالي.
> **مرجع مفصّل**: `RUN_GUIDE.md` §9 (الهجرات، النسخ الاحتياطي، سلامة التراجع) و `ENV-VARIABLES.md` (متغيرات البيئة).

---

## 0) قبل نافذة النشر

- [ ] تحديد المضيف النهائي (`Render` أو مخدّم خاص). `render.yaml` مرجعي لا قيد حقيقي للمضيف.
- [ ] إنشاء قاعدة `PostgreSQL` مُدارة على المضيف (خطة مدفوعة وليس خطة مجانية محدودة زمنًا — البيانات قضائية).
- [ ] تجهيز الأسرار (وهي لا تُخزَّن في المستودع أبدًا):
  - `Jwt__Secret` — 32 بايت (256 بت) على الأقل، مولّدة عشوائيًا.
  - `Bootstrap__AdminPassword` — كلمة قوية وفق `PasswordPolicy` (الحد 10+، بلا كلمات ممنوعة).
  - سلسلة اتصال Postgres من المضيف (أو `DATABASE_URL` حسب نمط المضيف).
- [ ] تسجيل جدول زمني للنشر: من ينفّذ كل بند، وقته، وناتجه الفعلي.

## 1) تطبيق هجرات قاعدة البيانات (إلزامي)

> **تنبيه**: الكود الجديد وحده لا يُطبِّق الهجرات على قاعدة قائمة. على قاعدة **جديدة** يطبّقها الإقلاع أول مرة تلقائيًا (`DatabaseInitializer.cs:27` — `MigrateAsync`)، والإجراء اليدوي مساندًا للتحكم في النوافذ الحرجة:

```powershell
# من مجلد backend\ (على الخادم):
dotnet ef database update --context DocGeneratorPostgresDbContext    # قاعدة الإنتاج
dotnet ef database update --context DocGeneratorDbContext            # SQLite — محليًا فقط عند الضرورة
# إن لم يكن dotnet-ef مثبتًا: dotnet tool install --global dotnet-ef
```

- [ ] نسخة احتياطية للقاعدة قبل أي نشر (القاعدة الذهبية في RUN_GUIDE).
- [ ] تسجيل سجل الهجرات الحالي: `SELECT "MigrationId" FROM "__EFMigrationsHistory" ORDER BY 1;`
- [ ] استعلامات الكشف المسبق (عند وجود صفوف قائمة):
  - صفوف `Lawyer`/`Head`/`SubHead` بلا فرع (قيد `CK_Users_BranchRequiredForBranchRoles`).
  - تكرار (الدائرة + رقم الملف + النوع + السنة) قبل قيد `RF009`.
  - صفوف حالات غير صحيحة وفق `PB002`/`SUBHEAD`.
- [ ] بعد التطبيق: مقارنة `__EFMigrationsHistory` مع السكربت المولَّد في مهمة `migration-guard` — أي فرق = إيقاف وتحقيق.
- [ ] تجربة سلوكية بعد الإقلاع: إدخال رقم مكرر → متوقع 409؛ محاولة تعديل صف تدقيق → متوقع فشل صريح (إلحاق فقط `RF019`).

## 2) إعدادات الإنتاج (متغيرات البيئة) — التفصيل في `ENV-VARIABLES.md`

- [ ] `ASPNETCORE_ENVIRONMENT=Production`.
- [ ] `Database__UsePostgres=true` (أو يكفي `DATABASE_URL` حسب `Program.cs`).
- [ ] `ConnectionStrings__DefaultConnection` أو `DATABASE_URL` — سلسلة اتصال Postgres.
- [ ] `Jwt__Secret` — بلاها لا إقلاع (تحقق صامل مقصود).
- [ ] `Bootstrap__AdminPassword` — تُستخدم مرة واحدة عند تأسيس المدير الأول.
- [ ] `Security__KnownProxies` — على مخدّم خاص حصرًا (عناوين/CIDR الوكيل العكسي)؛ لا وكلاء خارجيين في `Render`.
- [ ] `AllowedHosts` — النطاق الحقيقي (ليس `*`).
- [ ] `Swagger__Enabled=false` (الافتراضي) — لا يُفعَّل في الإنتاج إلا بحاجة صريحة.
- [ ] مجلد `logs/` قابل للكتابة (حاوية: `volume` مساند أو مسار قابل للكتابة)؛ الاحتفاظ الافتراضي 60 يومًا.
- [ ] `RateLimiting__*` افتراضيات مقبولة للإطلاق؛ تُضبط لاحقًا على الحمل الفعلي بلوحة مراقبة `429`.
- [ ] `Security__CspReportOnly=true` في الإطلاقة الأولى، ثم `false` بعد جولة مراقبة وبشرط إغلاق `M-07` (استضافة الخطوط ذاتيًا).

## 3) نافذة النشر

- [ ] نشر الإصدار من `master` فقط.
- [ ] متابعة سجل الإقلاع: لا رسائل حراس الإقلاع (`Program.cs:56-62`)، ولا فشل تطبيق الهجرات.
- [ ] دخول أول مدير بكلمة سر التأسيس، ثم تغييرها فورًا (التغيير يُبطل أي جلسة قديمة عبر `TokenVersion`).
- [ ] إنشاء المستخدمين والفروع من داخل التطبيق حصرًا — لا إدخال جماعي خارج النظام.
- [ ] تفعيل النسخ الاحتياطي اليومي من لوحة المضيف + استعادة تجريبية موثقة (النسخة غير المستعادة ليست نسخة) — `RPO`=24h و`RTO`=4h.

---

## 4) الفحص الدخاني بعد الإطلاق — إلزامي قبل إعلان نجاح النشر

- [ ] `GET /healthz` → 200.
- [ ] تسجيل دخول `admin` → تجربة قفل الدخول (`429`) بعد 6-7 محاولات خاطئة (الحد الافتراضي `MaxLoginAttempts`).
- [ ] إنشاء ملف تجريبي → حفظ → تغيير الحالة → تصدير (إن كان السلوك معتمدًا للجلسة).
- [ ] إعادة POST نفسه بنفس ترويسة `X-Idempotency-Key` → نتيجة واحدة بنفس الجسم (RF-011).
- [ ] محاولة كلمات سر شائعة (`123456`) → مرفوضة برسالة عربية من `PasswordPolicy`.
- [ ] `curl -I` للصفحة الرئيسية: وجود `X-Content-Type-Options`, `X-Frame-Options`, `Content-Security-Policy(-Report-Only)`, وغياب `Server: Kestrel`.
- [ ] تجربة على جوال أو نافذة 375px: لا تجاوز أفقي، وتنقّل يعمل (قائمة الجانب/التنقل السفلي).

## 5) التراجع (بديل الفشل)

- [ ] عند أي فشل: التراجع للإصدار السابق من المضيف (deployment rollback) حصرًا؛ إذا كانت القاعدة متضررة — الاستعادة من النسخة الاحتياطية.
- [ ] **لا** تطبيق هجرة قديمة (`Down`) على قاعدة حية — القاعدة في RUN_GUIDE §«سلامة التراجع».
- [ ] بعد عودة الخدمة: أعد فحص الدخان (§4) كاملًا.

---

## 6) بعد النشر (مراقبة مستقرة)

- [ ] مراقبة سجل التدقيق: لا تكرار `portal_forbidden` على مندوب حقيقي مؤشرًا على أن المندوب محجوب من مسار يحتاجه (`M-08`).
- [ ] مراقبة نقطة `client-errors` (مخنوقة لكل مستخدم) لأخطاء الواجهة الحقيقية.
- [ ] أسبوعيًا: مراجعة كمية `429` وضبط `RateLimiting` عند الحاجة.
- [ ] دوريًا: تدوير `Jwt__Secret` وسلسلة Postgres حسب خزنة المضيف (مثلًا كل 6 أشهر).
- [ ] تحديث الوثائق (`docs/audit/production-readiness/`) مع كل جلسة.

> **حكم النشر**: النشر لا يُعد منجزًا إلا بعد اكتمال (0)→(4). أي فشل في التحقق الدخاني يعيد الحالة إلى (5).
