# `P6-05` — ميزانية حزمة الواجهة — 2026-11-22

> **النطاق:** تقرير حزمة محلي بلا اعتمادية جديدة + حارس `CI` لسقوف الحجم.
> **لا تغيير سلوكي في الواجهة**؛ الإضافة بناء/حارس فقط. قياس `LCP/INP/CLS` يبقى
> خارج هذه الجولة (يحتاج Lighthouse/staging).

## 1. ما نُفِّذ

1. `vite.config.ts`: إضافة `bundleReport()` (Plugin داخلي) يكتب
   `dist/bundle-report.json` بأحجام كل ملفات البناء — بديل خفيف عن
   `rollup-plugin-visualizer` بلا حزمة/قفل جديد.
2. `frontend/scripts/bundle-budget.mjs` + `npm run budget`:
   - سقوف: الإجمالي **2,000,000** بايت، أكبر حزمة **460,000**، حزمة الدخول **300,000**.
   - يفشل برسائل تسمّي التجاوز، ويطبع الإجمالي/الأكبر/الدخول.
3. `CI` — وظيفة `frontend`: خطوة `Bundle budget` بعد `Build`.
4. القياس الحالي: `JS=91` · إجمالي **1725.2kB** · أكبر **388.2kB**
   (`RichTextEditor`) · دخول **249.3kB** ⇒ ضمن الميزانية بهامش.

## 2. ما كشفته المراجعة النقدية

| # | الوجد | الدليل | القرار |
|---|---|---|---|
| 1 | `rollup-plugin-visualizer` يضيف اعتمادية/قفلًا لحاجة تقرير بسيطة | لا حاجة لتحليل تفاعلي في `CI` | Plugin داخلي يكتب JSON؛ يمكن إضافة visualizer لاحقًا عند الحاجة |
| 2 | السقوف بلا تحقق سلبي قد تكون زينة | خفض اصطناعي لحجم الدخول | شُغّل الحارس على تقرير مُعدَّل: فشل بثلاث رسائل (إجمالي/أكبر/دخول) ثم أُعيد التقرير الأصلي |
| 3 | صور بلا أبعاد (CLS) | فحص `<img>` في `Layout`/`Login` | كلها تحمل `width`/`height` و`alt` مسبقًا — لا تغيير |
| 4 | المسارات lazy | `App.tsx` يستخدم `lazy` لكل الصفحات | لا تغيير |
| 5 | `content-visibility` للقوائم الطويلة | لم يُضَف | مؤجّل: يمسّ الطباعة/القياس البصري ويحتاج قياس INP؛ لا يُشحن بلا دليل |
| 6 | `LCP/INP/CLS` غير مقيسة | لا Lighthouse في البيئة | `DoD` يبقى **جزئيًا**؛ الحارس يمنع الانحدار الحجمي فقط |
