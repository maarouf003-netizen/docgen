# آثار القياس (`P3-01`/`P3-02`) — سياسة الاحتفاظ

> هذا المجلد يحوي **خط الأساس المعتمد** لقياسات `PostgreSQL/Release`، لا كل تشغيل تجريبي.
> الغرض منع تضخّم المستودع مع الحفاظ على دليل قابل للتدقيق لكل قرار أداء.

## 1. ما يُحفظ في المستودع

- **خط أساس واحد لكل `(task, scale)`**: حاليًا `20261121-p3-01-{10000,50000}` و
  `20261121-p3-02-{10000,50000}` (JSON + ملحق Markdown).
- ملف `.json` بخطته الكاملة (`EXPLAIN ANALYZE, BUFFERS, FORMAT JSON`) وملف `.md` الموجز
  **معًا**؛ لا يُحفظ أحدهما دون الآخر.
- أي خط أساس جديد (إصدار/تغيير جوهري في الاستعلامات) **يستبدل** الملف بنفس الاسم في شجرة
  العمل؛ التاريخ يبقى في Git، ولا تُحذف الملفات من التاريخ.

## 2. ما لا يُحفظ

- **إعادات التشغيل الروتينية** (تشغيل تحقّق بعد تغيير بسيط): تُكتب في
  `%TEMP%` أو تُرفع كأثر `CI`/`artifacts`، لا تُضاف إلى `docs/audit/measurements`.
- **الملفات المؤقتة** (`--output %TEMP%\…`) و`bin/`/`obj/`.
- أي قياس بُني على `Debug` أو `SQLite` (لا يُعتمد أصلًا).

## 3. الحجم والمراجعة

- الحد العملي لكل ملف JSON: **≤ 8MB**. عند تجاوزه: احفظ ملخص الأنواع/الخطط في `.json`
  المضغوط أو اقصص الخطط إلى أعلى N استعلامات مع توثيق ذلك في `.md`.
- قبل إضافة خط أساس: راجع `git diff --cached --stat` وتأكد أن الزيادة مبررة بقرار أداء
  (ليس مجرد تشغيل عابر).
- الحجم الحالي (2026-11-21): **~28MB** لأربعة ملفات JSON (10k/50k × مهمتين)؛ لا تُضاف
  نسخ جديدة دون مراجعة المالك/PR.

## 4. الخصوصية والأمان (إلزامي)

- **لا تُشغّل البذر على بيانات إنتاج/staging حقيقية.** الأداة تحفظ قيم المعاملات
  (`PlanCapture.Parameters`) داخل JSON؛ بيانات حقيقية تعني تسرب PII إلى Git.
- القياس في `staging` يكون على **قاعدة بذر اصطناعي حتمي** (نفس `DeterministicSeeder`)،
  أو بعد إضافة تنقية صريحة للمعاملات قبل الحفظ.
- لا أسرار/سلاسل اتصال داخل الملفات؛ `secrets-guard` يفحص المستودع.

## 5. التسمية

`<YYYYMMDD>-<task>-<scale>.json|.md` حيث `task` = `p3-01`/`p3-02` (أو المهمة التالية)،
و`scale` = `10000`/`50000`. لا أسماء حرة.

## 6. عند إضافة قياس جديد

1. شغّل الأداة بـ`-c Release` و`--task` الصحيح و`--output` مؤقتًا للمراجعة.
2. راجع `p95` والخطط وأخطاء `EXPLAIN` (`0` مطلوب).
3. انسخ الملفين إلى هذا المجلد فقط إن كان **خط أساس** معتمدًا.
4. حدّث وثيقة التدقيق المؤرخة (`docs/audit/NN-…`) والخريطة في نفس التغيير.
