# P2-05 — حارس الأسرار في الملفات المتتبَّعة — 2026-11-15

> نطاق هذه الجولة: منع دخول أي سرّ إلى الملفات المتتبَّعة آليًا في `CI`، وتوسيع
> `.gitignore`، ومراجعة مسار كلمة مرور المشرف الأولي. **تدوير الأسرار وفحص سجل Git
> الكامل** خطوتان للمالك (لا يمكن تنفيذهما من الكود بلا بيانات اعتماد).

## 1. الجرد قبل التغيير

| السطح | الحالة |
|---|---|
| `.gitignore` | يغطي `.env`/`*.env`/`appsettings.Development.json`/`*Local*`/`*Secret*`/`*.pfx,*.pem,*.key,*.snk,*.jks` |
| أسرار متتبَّعة | لا مفاتيح/رموز؛ 20 مطابقة «سرّية الشكل» كلها عناصر نائبة/قيم اختبار/بناء سلاسل (موثّقة في خط الأساس) |
| `DbSeeder` (تطوير) | كلمة مرور عشوائية لكل بذر، تُطبع على الكونسول المحلي فقط عند إنشاء الحسابات، ويمكن تجاوزها صراحةً للاختبارات |
| `Bootstrap:AdminPassword` (إنتاج) | مطلوب صراحةً؛ غيابه يمنع الإقلاع؛ تُفرَض عليه `PasswordPolicy` نفسها، ويُخزَّن مقصوصًا ومُجزَّأً |
| فحص سجل Git | غير منفّذ (يحتاج `gitleaks`/تدوير — إجراء مالك) |

## 2. ما طُبّق

1. **`scripts/secrets-guard.mjs`** (بوابة `guards`):
   - يفحص الملفات **المتتبَّعة** فقط (`git ls-files`)، بنمط ratchet كحارس الحتمية.
   - القواعد: مفتاح خاص، مفاتيح `AWS`/رموز `GitHub`/`Slack`/`OpenAI`، JWT، رابط
     اتصال ببيانات دخول، إسناد `Password=`، وسرّ في إعداد JSON.
   - **لا يطبع القيم أبدًا**: المسار والقاعدة وأول ثلاثة أرقام أسطر فقط.
   - يفشل عند: مطابقة جديدة، زيادة العدد داخل ملف/قاعدة، أو قيد خط أساس لم يعد
     مطابقًا (انخفاض/اختفاء) — فيُجبر على تقليصه بـ`--update` بعد المراجعة.
2. **`scripts/secrets-baseline.json`**: 20 قيدًا، كل قيد بسبب دقيق (اختبار/عنصر نائب/
   بناء سلسلة/متغير بيئة).
3. **`.gitignore`**: إضافة `.env.*` (مع `!.env.example`)، `001.txt`، `*.publishsettings`،
   `*.keystore`، `*.mobileprovision`، `id_rsa*`، `.npmrc`.
4. **`ci.yml`**: خطوة `Secrets guard` داخل وظيفة `guards` (لا بوابة جديدة).

## 3. التحقق

- الحارس على المستودع الحالي: نظيف (20 مطابقة معروفة).
- **تحقق سلبي:** ملف مؤقت متتبَّع يحمل رمز `GitHub` وهميًا أفشل الحارس بقاعدة
  `github-token` وسطر 1، ثم حُذف وعاد نظيفًا.
- **الحارس يفحص نفسه أيضًا** (لا استثناء لملفه أو لخط الأساس): تعليق التعريف الأول
  احتوى النص الحرفي `Password=` فأسقط الفحص في `CI`؛ أُعيدت صياغة التعليق بدل استثناء
  الملف، وأُعيد الفحص بعد `git add` ليطابق حالة `CI` تمامًا.
- `node --check` + `determinism-guard` + `migration-watchlist-guard` خضراء.

## 4. المتبقي (إجراء مالك — لا يُنفَّذ من الكود)

1. **فحص سجل Git الكامل** بـ`gitleaks` (المستودع تجريبي؛ أي نتيجة تُعالَج بتدوير فوري،
   بلا طباعة القيم).
2. **تدوير** أسرار البيئة الحالية (`DATABASE_URL`/`JWT:Secret`/`Bootstrap__AdminPassword`)
   مرة واحدة قبل أي استخدام حقيقي، وتوثيق تاريخ التدوير هنا.
3. **إجبار تغيير كلمة المرور الأولية** عند أول دخول: يحتاج حقلًا/هجرة (منطق حالة
   مستخدم) — بند لاحق مستقل، خارج نطاق هذه الجولة.
4. `gitleaks` في `CI`: يحتاج قرار تثبيت الإجراء/الترخيص؛ الحارس المحلي يغطي الملفات
   المتتبَّعة الآن بلا اعتماد خارجي.

## 5. حدود

- الحارس يفحص ما يمكن **تتبعه**؛ ملفات محلية متجاهَلة (`.env`) لا تُفحص لأنها لا
  تُدفع أصلًا.
- قواعد النمط heuristic: قد تفوت سرًّا بصيغة غير مألوفة، فالتغطية ليست بديلًا عن
  `gitleaks` في السجل.
- `password-assignment` يعتمد على خط أساس بعدّادات؛ إضافة كلمة مرور اختبار جديدة في
  ملف معروف تُفشل الحارس حتى تُوثَّق — وهو السلوك المقصود.
