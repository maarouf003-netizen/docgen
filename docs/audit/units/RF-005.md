# `RF-005` — تسجيل الأحداث الأمنية الصامتة

> الفرع: `refactor/RF-005-seclogging`. الحالة: موجز مكتوب (Step 2) — بانتظار التنفيذ والتحقق.

## Objective

لا مسح ممنهج ولا رش بلا أثر: تدقيق رفض البوابة (`403`) والمحاولات على المقفل وطلبات اختيار
الفرع — مع خنق يمنع فيض السجل.

## Current problem

كل `403` صامت (الحارس بلا `ILogger` في `EntityManagerPortalGuard.cs:34-39`)، وإعادة المحاولة
على حساب مقفل صامتة (`AuthService.cs:71-72,90-91`)، وطلب اختيار الفرع بلا تدقيق (`:73-76`) —
`SEC-006`/`SEC-007` + بقية `ARC-003`.

## Evidence

- `EntityManagerPortalGuard.cs:18-46` (رفض مباشر بلا تسجيل).
- `AuthService.cs:45-91` (المسارات الصامتة الثلاثة) مقابل `:86,:111,:134,:137` (الموثقة).
- الخنق: `ClientErrorsController.cs:55-62` (نمط `IMemoryCache` لكل مستخدم) + حد الدخول القائم
  (`login-ip` و`DbLoginRateLimiter` — يقيّد مسارات الدخول أصلًا فلا خنق إضافي لها).
- التوكن يحمل `ClaimTypes.Name` (`TokenService.cs:31`) — متاح للحارس.

## Files affected

- `EntityManagerPortalGuard.cs` (تسجيل `portal_forbidden` مخنوق: صف واحد لكل مستخدم كل 5 دقائق).
- `AuthService.cs` (صف `login_locked_retry` عند الإرجاع صامتًا + صف `login_branch_choices` بالعدد فقط).
- اختبار جديد `RF005SecurityLoggingTests.cs`. لا غير.

## Business behavior affected

none — صفوف تدقيق إضافية فقط (تظهر في `GET /api/audit-logs` للمدير/المشرف/الرئيس).

## Security impact

يغلق العمى الرصدي (`SEC-006`/`SEC-007`): أي مسح معرفات أو رش مقفل يترك أثرًا قابلًا للتنبيه.
الخنق يمنع تحويل التسجيل نفسه لمتجه فيض (صف واحد/مستخدم/5د للحارس؛ مسارات الدخول مقيدة أصلًا).

## Database impact

none — صفوف `AuditLogs` عادية بلا تغيير مخطط.

## API impact

none — نفس الرموز والأجسام (`403`/`423`/`BranchSelectionRequired`).

## Test strategy

ثلاثة اختبارات إظهار (تفشل قبل الإصلاح: لا صف):
1. مندوب يطلب `/api/documents` → `403` + صف `portal_forbidden` بالمسار.
2. قفل حساب (5 فاشلة) ثم إعادة → `423` + صف `login_locked_retry`.
3. دخول بلا فرع لمكرر الاسم → `requiresBranchSelection` + صف `login_branch_choices`.
الاستعلام عن الصفوف من `AuditLogs` مباشرة عبر نطاق (أدق من API التدقيق).

## Rollback strategy

عكس الملفين + حذف الاختبار (التزامان: اختبارات، ثم تنفيذ + تقرير).
