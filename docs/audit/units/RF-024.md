# `RF-024` — قياس البحث ثم الحكم على الفهارس (`INT-009` + `INT-010`)

> الفرع: `refactor/RF-015-currency` (تراكمي). الحالة: قياس منفذ ومُتحقق — بانتظار التثبيت.

## Objective

الحكم بالأرقام لا بالتخمين: هل يستحق البحث فهارس (وهجرات) أم لا — القياس أولًا حسب نص الوحدة.

## Current problem

- بحث الملفات `Contains` بلا `ToLower` + `Any` على ~7 جداول توابع لكل بحث
  (`DocumentRepository.cs:257-298,310-338`) بلا فهرس نصي كامل — `INT-009` (الأثر INFERRED).
- `ExecStatus` (فلتر الحالة الرئيسي) بلا فهرس؛ `Lawyer`/`FileYear`/`BranchName` بلا فهارس — `INT-010`.

## Evidence

- اختبار قياس دائم `SearchMeasurementTests.cs` (روح `M6`): زرع 10k ملف + 10k كفيل (≈ 5 سنوات
  بمعدل 2000/سنة)؛ العدّات مثبتة حتميًا؛ الأزمنة والخطط مسجلة بلا فشل عليها.

## Files affected

- جديد: `backend/tests/.../SearchMeasurementTests.cs` فقط — لا `src`، لا عقود، لا هجرات.

## Business behavior affected

none — قياس قرائي.

## Security impact

none.

## Database impact

none — قراءة + `EXPLAIN` فقط (حتى الزرع في `SQLite` مؤقتة تُرمى مع الاختبار).

## API impact

none.

## Test strategy

- عدّات حتمية: بحث اسمي جزئي «مقترض 7» = 1100 (11% محسوبة)؛ فلتر التريث = 2000 (الخُمس).
- `EXPLAIN QUERY PLAN` للشكلين (تثبيت بنيوي: `EXISTS`/`SEARCH` مقابل `SCAN` — نص الخطة يتبدل بين الإصدارات).

## Rollback strategy

عكس الالتزام الواحد.

## Verification (نتائج حقيقية — `SQLite` بذاكرة هذه البيئة، لقطة واحدة)

- الزرع: 10k ملف + 10k كفيل ≈ 13 ثانية (إعداد لمرة واحدة).
- بحث اسمي (`Contains` + `Any` + صفحة 20 بسلسلة `Includes` المعتمدة): ≈ 1080ms (العدّ 1100 ✓).
- فلتر الحالة (تريث): ≈ 430ms (العدّ 2000 ✓).
- الخطة (اسمي): `SCAN d USING COVERING INDEX … | SEARCH g EXISTS USING INDEX IX_Guarantors_DocumentId`
  — مسبار التوابع مفهرس بالخارجية؛ المسح الخارجي حتمي (`LIKE '%…%'` لا ينتفع بأي `B-tree`).
- الخطة (حالة): `SCAN d` — مسح كامل (لا فهرس على `ExecStatus`).

## الحكم: لا وحدة فهارس الآن

1. البحث الاسمي لن يصلحه أي فهرس `B-tree` (بدل wildcard) — البديل `FTS/trigram` (ملحق `Postgres` +
   مزامنة) غير متناسب مع 2000 ملف/سنة و≈ ثانية واحدة عند 5 أضعاف الحجم الحالي.
2. فلتر الحالة سينتفع بفهرس، لكن ≈ 430ms عند 5 أضعاف الحجم لا يبرر هجرتين (قاعدتان) اليوم.
3. تحفظ: القياس على `SQLite` بذاكرة ≠ إنتاج `Postgres` — يُعاد القياس على `Postgres` بحجم حقيقي
   عند أول شكوى `p95` أو تضاعف الحجم ×5؛ اختبار القياس باقٍ كسلك تعثر (الزمن غير مؤكَّد عمدًا).
