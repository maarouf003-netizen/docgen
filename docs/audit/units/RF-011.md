# `RF-011` — مفاتيح عدم التكرار للكتابة (`INT-007` ← `BQ-032`)

> الفرع: `refactor/RF-011-idempotency` (من رأس `refactor/RF-019-appendonly` التراكمي).
> الحالة: موجز مكتوب (Step 2) — بانتظار التنفيذ والتحقق.
> **تنبيه قاعدة 5**: الهجرتان تُكتَبان ولا تُطبَّقان (`dotnet ef database update` محظور)؛ نصا `SQL`
> في `docs/audit/migrations/`؛ ثم STOP لاعتماد صريح منفصل قبل أي تطبيق.
> الأولويات المعتمدة (`BQ-032`، جلسة `RF-011`): (1) الإنشاء، (2) الاستيراد/الدمج،
> (3) النقل الجماعي. النافذة الافتراضية 72 ساعة (بلا اعتراض فسارية).

## Objective

النقرة المزدوجة/إعادة الإرسال لا تُكرر الأثر: نفس المفتاح يُرجع نفس النتيجة
المخزنة بدل تنفيذ جديد — للمسارات الثلاثة المعتمدة فقط.

## Current problem

صفر `IdempotencyKey` في `src` (`INT-007` — تحققت): إعادة إرسال الإنشاء تُنشئ
ملفًا ثانيًا (`DocumentService.CreateAsync` بلا بصمة)؛ اعتماد الدمج/التوحيد
يُعاد تطبيقه (نتائج مختلفة: `skipped` بدل الإنشاء)؛ النقل الجماعي الثاني يعيد
`0` بدل العدد الأصلي؛ حراس الواجهة (`disabled={saving}`) تجميل فقط.

## Business behavior affected

مقصود ومعتمد: إعادة نفس المفتاح تُرجع نفس النتيجة (الثانية `200` بالجسم نفسه؛
الأولى `201` للإنشاء كاليوم). مفتاح مستعمل لحمولة مختلفة → `400` («المفتاح
مستعمل لطلب مختلف»). مفتاح على عملية قيد المعالجة → `409` («قيد المعالجة»).
غياب المفتاح = السلوك القديم تمامًا (عملاء قدامى لا ينكسرون).

## Security impact

تضييق إعادة التشغيل الخبيثة لعمليات الكتابة الثقيلة؛ المفاتيح `uuid` غير قابلة
للتخمين ومسنودة للمستخدم والعملية (مفتاح مسرّب لا يعمل لغير صاحبه وعمليته).

## Database impact

**NEEDS-MIGRATION** (تحليل قاعدة 5 أدناه). جدول مفاتيح جديد — بيانات جديدة
لا تمس القائمة.

## API impact

compatible — ترويسة اختيارية جديدة؛ بلا تغيير `DTO`؛ نفس الأجسام (الثانية `200`
بدل `201` للإنشاء فقط — مقصود وموثق).

## Test strategy

1. إظهار (يفشل قبل الإصلاح): إرسال مزدوج بنفس المفتاح (إنشاء/دمج/نقل) → اليوم
   أثران/نتيجتان مختلفتان؛ وبعده نتيجة واحدة مخزنة.
2. بصمة مختلفة بنفس المفتاح → `400` (اليوم: تنفيذ ثانٍ).
3. بلا مفتاح → السلوك القديم (توصيف، يخضر قبل/بعد).
4. الكاملة خلفية + `oxlint + tsc -b + vitest + build` واجهة على قواعد معزولة.

## Rollback strategy

عكس الكود (التزامات) + حذف ملفي الهجرة + إعادة اللقطتين. القاعدة الحية لا تُمسّ
حتى الاعتماد المنفصل. صفوف المفاتيح المخزنة تُهمَل بانتهائها (72 ساعة) ولا تتطلب تنظيفًا.

## Type / Dependencies

**NEEDS-MIGRATION** + قرار أولويات (`BQ-032` مبتوت). تعتمد `RF-001`.

## تحليلات الهجرة (قاعدة 5)

- **الهجرة**: جدول `IdempotencyKeys` (`Id` + `Key(100)` + `Operation(100)` +
  `UserId` + `Fingerprint(64)` + `ResponseBody(text, null = قيد المعالجة)` +
  `CreatedAt` + `ExpiresAt`) + قيد فريد `(Key, Operation, UserId)` + فهرس
  `ExpiresAt` — `SQLite` (`TEXT`/`INTEGER`) و`Postgres` (`text`/`timestamptz`).
- **الأثر**: إدخالات بحجم أجسام الاستجابة (عشرات `KB` × آلاف/3 أيام — عشرات `MB`
  حدًا أقصى) + تنظيف انتهازي (`DELETE` المنتهية عند كل حجز) — بلا مهمة خلفية،
  بلا قفل. `INSERT` الحجز خارج معاملة العملية (التزام مستقل) فلا تعشيش معاملات.
- **التوافق**: كود قديم/مخطط جديد: يعمل (بلا مفاتيح أصلًا). كود جديد/مخطط قديم
  (نافذة النشر قبل الهجرة): تعذّر الحجز لغير التكرار (جدول غائب) → تنفيذ بلا
  إزالة تكرار + تحذير سجلي (`fail-open` موثق — التوافر أولًا في النافذة)؛ وترتيب
  النشر المعتمد (هجرة أولًا ثم كود — `RUN_GUIDE.md` §9) يجعل النافذة معدومة أصلًا.
- **الصفوف القائمة**: لا شيء — جدول جديد فارغ.
- **النسخ الاحتياطي**: إلزامي قبل التطبيق (نسخة مُتحقَّق منها + `RUN_GUIDE.md` §9).
- **التراجع**: `Down` يُسقط الجدول (بيانات المفاتيح فقط — لا بيانات عمل) —
  يُختَبر على نسخة مهملة حصرًا.
- **نصا `SQL`**: `docs/audit/migrations/RF011_{sqlite,postgres}.sql` (مولّدان، للقراءة والمراجعة).
