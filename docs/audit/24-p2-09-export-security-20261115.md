# P2-09 — أمان التصدير (Excel/Word/`Content-Disposition`) — 2026-11-15

> نطاق هذه الجولة: إغلاق فجوات تصدير الملفات (Formula Injection، Path Traversal في
> القوالب، تنقية اسم الملف، سقوف الحجم) مع اختبارات مدخلات خبيثة. لا تغيير في العقود
> ولا في أعمدة التصدير. المرجع: `docs/PERFECTION_ROADMAP.md` §`P2-09`.

## 1. جرد الوضع قبل التغيير

| السطح | الحالة قبل | الحكم |
|---|---|---|
| Excel — Formula Injection | كل الخلايا تُكتب `CellValues.InlineString` (لا عناصر `<f>`)، فيعرض إكسل النص حرفيًا ولا ينفّذه | **آمن بالتصميم** لكن بلا اختبار يحرسه |
| Excel — سقف الصفوف | `ExportOptions.MaxRows = 10_000` مفروض في `DocumentSearchService.ExportAsync` و`PortalService`؛ تصدير سجل التغييرات محدود بـ`5000`؛ إحصاءات الدوائر محدودة بعدد الدوائر | موجود |
| Excel — الذاكرة | توليد `SAX` (`OpenXmlWriter`) بذاكرة `O(1)` | موجود |
| Word — Path Traversal | القالب يُختار من قاموس مغلق، لكن `Path.Combine` بلا تحقق احتواء؛ اسم مطلق أو `..` في الإعداد كان يقرأ خارج مجلد القوالب | **فجوة** |
| اسم الملف / `Content-Disposition` | `Path.GetInvalidFileNameChars()` فقط — على Linux لا يحظر إلا `/` و`\0`، فيمرّ `"` وCR/LF ومحارف bidi | **فجوة** |

## 2. ما طُبّق

1. **`ExportFileName.Sanitize`** (`Application/Common/Security`): تنقية مستقلة عن المنصة
   — إزالة محارف التحكّم (`char.IsControl`)، و`< > : " / \ | ? *`، ومحارف تحكّم الاتجاه
   (`U+202A–U+202E`، `U+2066–U+2069`)، وطيّ المسافات، وتقليم النقطة/المسافة الطرفية
   (يرفضها Windows)، وسقف `120` محرفًا بلا بتر زوج `surrogate`، وارتداد إلى `fallback`
   عند الفراغ. استُخدم في `WordDocumentGenerator` بدل الدالة الخاصة.
2. **`WordTemplateRenderer.ResolveTemplatePath`**: رفض الأسماء المطلقة، وحساب المسار
   الكامل (`Path.GetFullPath`) والتحقق من احتوائه في مجلد القوالب (مقارنة
   `OrdinalIgnoreCase` على Windows و`Ordinal` على Linux) قبل أي فتح ملف.
3. **اختبارات حارسة** (كلها `Category=Unit`، تعمل في الحلقة السريعة):
   - `ExcelExportSecurityTests`: خمس حِمول (`=cmd|...`, `+1+1`, `-2+3`, `@SUM(1+1)`,
     `=HYPERLINK(...)`) تُكتب `inlineString` بلا `CellFormula` ولا `CellValue`، وورقة
     العمل بلا أي عنصر `<f>` مع تساوي عدد `<is>` وعدد الخلايا.
   - `ExportFileNameTests`: حقن ترويسة (CR/LF/`:`/`"`)، مسارات (`../`, `..\`)، bidi،
     عربية سليمة، فراغ، سقف الطول، وسلامة `surrogate`.
   - `WordTemplateRendererTests`: اسم قالب هارب `../outside.docx` واسم مطلق كلاهما
     `ArgumentException`.
4. **لماذا لا نُضيف بادئة `'` للقيم التي تبدأ بـ`= + - @`** (كما تقترح الخطة حرفيًا):
   البادئة تغيّر البيانات المعروضة في كل خلية بريئة تبدأ بـ`-` (أرقام سالبة) أو`+`،
   بلا فائدة أمنية هنا لأن الخلية **نصية** أصلًا وليست صيغة. الحارس الحقيقي هو نوع الخلية،
   وقد ثُبّت باختبار. لو أُضيف تصدير `CSV` مستقبلًا (لا وجود له الآن) تلزم البادئة هناك
   لأن `Excel` يفسّر `CSV` عند الفتح.

## 3. حدود معروفة

- لا سقف حجم بالبايت؛ السقف العددي (`MaxRows`) والكتابة `SAX` يحدّان الأثر عمليًا.
- تصدير سجل التغييرات يستخدم `5000` ثابتًا خارج `ExportOptions`؛ توحيده مع الإعداد
  تحسين لاحق منفصل (لا خطر أمني حالي).
- لا تصدير `CSV` في النظام اليوم، فلا مسار حقن عبر فاصل الحقول.
- `WordDocumentGenerator` ينقّي اسم الملف فقط؛ أسماء ملفات Excel في المتحكمات ثابتة
  (بادئة عربية + تاريخ) فلا تحتاج تنقية.

## 4. التحقق

- بناء الحل `-warnaserror` أخضر.
- الاختبارات الجديدة: `14/14` (Excel 6، أسماء 8 بما فيها الوحدتان المضافتان إلى
  `WordTemplateRendererTests`).
- المجموعتان الكاملتان (Application/Api) والمجموعة الوحدوية السريعة خضراء.
