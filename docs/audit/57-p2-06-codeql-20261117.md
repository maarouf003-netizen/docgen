## 2. القرارات

1. **CodeQL أولًا لا `Semgrep`:** CodeQL مدمج في GitHub (لا توكن خارجي)، يدعم C# ببناء
   فعلي وJS/TS بلا بناء، ويرفع SARIF إلى تبويب الأمان. `Semgrep` يحتاج اختيار قواعد
   وضبط ضجيج (وقد يحتاج توكن للتشغيل الكامل) — يُؤجَّل حتى تتوفر دورة فرز نتائج.
2. **`dependency-review` مؤجّل (حاجز إعداد لا كود):** شُغّل أول مرة على الـPR نفسه
   وفشل: «Dependency review is not supported on this repository… Dependency graph is
   enabled». GitHub Dependency graph غير مفعّل في إعدادات المستودع (Settings → Security
   analysis) — **إجراء مالك**؛ بعد تفعيله تُضاف الوظيفة (سطر واحد) بلا تغيير في
   الاعتماديات. لا نترك وظيفة تفشل دائمًا كضجيج.
3. **ليست ضمن البوابات الست بعد:** لا تُقفل الحماية على أداة جديدة قبل إثبات استقرارها
   (زمن، ضجيج، ثبات). تُضاف الوظيفة إلى حماية `master` بعد تاريخ أخضر متكرر — قرار مالك.
4. **تأجيل `DAST` و`Trivy` و`Snyk`:** `DAST` يحتاج `staging` منشورًا (P5-04)؛ `Trivy`
   يحتاج بناء صورة في CI وخط أساس للنتائج؛ `Snyk` يحتاج `SNYK_TOKEN` من المالك.
   تسجيلها هنا يمنع اعتبار `P2-06` مكتملًا.

## 3. المراجعة النقدية

- **`security-events: write` فقط حيث يلزم:** أعلى الملف لرفع SARIF؛ لا صلاحيات كتابة
  أخرى (لا تعليقات، لا تعديل كود).
- **بناء C# مطلوب:** CodeQL لا يستخرج C# بلا تجميع؛ خطوة البناء تستخدم `--locked-mode`
  ثم `--no-restore`، فلا تنحرف الاعتماديات داخل الفحص.
- **`paths-ignore` للوثائق:** PR وثائقي لا يستهلك دقائق CodeQL؛ لكن تغيير **هذا الملف**
  يُشغّله (لأنه ليس تحت `docs/`)، فيُختبر التغيير نفسه.
- **النتائج لا تُفشل الـPR افتراضيًا:** CodeQL يرفع تنبيهات Code scanning؛ التحويل إلى
  بوابة حاجبة يحتاج ضبط `fail-on` أو إضافة الوظيفة إلى الحماية بعد الفرز — لم ندّعِه.
- **لا كشف أسرار:** لا توكنات/مفاتيح جديدة؛ `security.yml` يستخدم `GITHUB_TOKEN` فقط.

- **CodeQL ناجح فعليًا على الـPR:** `csharp` 3m42s و`javascript-typescript` 1m30s

  يعيدها).
- البوابات الست الحالية تبقى كما هي: `backend` · `frontend` · `guards` · `audit` ·
  `backend-postgres` · `migration-guard`.
- لا تغيير في الكود/الاعتماديات/الهجرات.

## 5. الحدود

- `CodeQL` قد يحتاج فرز تنبيهات أولية (ضجيج `security-and-quality`) — بند متابعة.
- لا `DAST` (staging)، ولا `Trivy` (صورة)، ولا `Snyk`.
- **`dependency-review` يحتاج تفعيل GitHub Dependency graph** (Settings → Security
  analysis) — إجراء مالك؛ بعده تُضاف الوظيفة بسطر واحد.
- الوظيفة غير مطلوبة في حماية الفرع بعد (قرار مالك بعد استقرار).
- لا ادّعاء بأن كل فئات الثغرات مغطاة؛ القواعد محدودة بما يدعمه CodeQL.
