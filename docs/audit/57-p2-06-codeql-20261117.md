# `P2-06` (تكملة) — SAST ومراجعة اعتماديات الـPR — 2026-11-17

> PR: [#199](https://github.com/maarouf003-netizen/docgen/pull/199)
>
> نطاق هذه الجولة: إضافة تحليل ساكن للكود (CodeQL) ومراجعة اعتماديات على كل `PR`،
> مع قرار موثّق بتأجيل `Semgrep`/`DAST`/`Trivy` لأسباب محددة. لا تغيير في الكود أو
> الاعتماديات.

## 1. ما أُضيف

`.github/workflows/security.yml`:

| الوظيفة | النطاق | متى |
|---|---|---|
| `CodeQL (csharp)` | `backend/` — بناء فعلي (`--locked-mode`) ثم استخراج دلالي | push إلى `master` · PR · أسبوعيًا |
| `CodeQL (javascript-typescript)` | `frontend/` — بلا بناء | push إلى `master` · PR · أسبوعيًا |
| `Dependency review` | تغييرات الاعتماديات في الـPR، `fail-on-severity: high` | `pull_request` فقط |

- الاستعلامات: `security-and-quality` (تضيف قواعد جودة بجانب الأمن)، والنتائج تُرفع
  كـSARIF إلى **Code scanning** (`security-events: write`).
- `paths-ignore` للوثائق فقط، `concurrency` لإلغاء التشغيلات القديمة، `timeout` صريح،
  وجدولة أسبوعية لتحديث القواعد حتى بلا تغيير كود.

## 2. القرارات

1. **CodeQL أولًا لا `Semgrep`:** CodeQL مدمج في GitHub (لا توكن خارجي)، يدعم C# ببناء
   فعلي وJS/TS بلا بناء، ويرفع SARIF إلى تبويب الأمان. `Semgrep` يحتاج اختيار قواعد
   وضبط ضجيج (وقد يحتاج توكن للتشغيل الكامل) — يُؤجَّل حتى تتوفر دورة فرز نتائج.
2. **Dependency review بجانب بوابات الاعتماديات:** `dependency-audit` و
   `npm-audit-guard` يفحصان الحالة الحالية؛ `dependency-review` يفحص **فرق** الـPR
   (ماذا أُضيف/رُقّي) ويفشل على `high+` — أقرب لبوابة سلسلة توريد.
3. **ليست ضمن البوابات الست بعد:** لا تُقفل الحماية على أداة جديدة قبل إثبات استقرارها
   (زمن، ضجيج، ثبات). تُضاف إلى `master` protection بعد تاريخ أخضر متكرر — قرار مالك.
4. **تأجيل `DAST` و`Trivy` و`Snyk`:** `DAST` يحتاج `staging` منشورًا (P5-04)؛ `Trivy`
   يحتاج بناء صورة في CI وخط أساس للنتائج؛ `Snyk` يحتاج `SNYK_TOKEN` من المالك.
   تسجيلها هنا يمنع اعتبار `P2-06` مكتملًا.

## 3. المراجعة النقدية

- **`security-events: write` فقط حيث يلزم:** أعلى الملف، ووظيفة `dependency-review`
  تُقلّص صلاحياتها إلى `contents: read` + `pull-requests: read` (لا تعليق تلقائي
  `comment-summary-in-pr: never`).
- **بناء C# مطلوب:** CodeQL لا يستخرج C# بلا تجميع؛ خطوة البناء تستخدم `--locked-mode`
  ثم `--no-restore`، فلا تنحرف الاعتماديات داخل الفحص.
- **`paths-ignore` للوثائق:** PR وثائقي لا يستهلك دقائق CodeQL؛ لكن تغيير **هذا الملف**
  يُشغّله (لأنه ليس تحت `docs/`)، فيُختبر التغيير نفسه.
- **النتائج لا تُفشل الـPR افتراضيًا:** CodeQL يرفع تنبيهات Code scanning؛ التحويل إلى
  بوابة حاجبة يحتاج ضبط `fail-on` أو إضافة الوظيفة إلى الحماية بعد الفرز — لم ندّعِه.
- **لا كشف أسرار:** لا توكنات/مفاتيح جديدة؛ `security.yml` يستخدم `GITHUB_TOKEN` فقط.

## 4. التحقق

- الـworkflow يُشغَّل على PR هذه الجولة؛ النتيجة (CodeQL/JS/TS/Dependency review) تُسجَّل
  في الـPR. لا يمكن اختبار GitHub Actions محليًا.
- البوابات الست الحالية تبقى كما هي: `backend` · `frontend` · `guards` · `audit` ·
  `backend-postgres` · `migration-guard`.
- لا تغيير في الكود/الاعتماديات/الهجرات.

## 5. الحدود

- `CodeQL` قد يحتاج فرز تنبيهات أولية (ضجيج `security-and-quality`) — بند متابعة.
- لا `DAST` (staging)، ولا `Trivy` (صورة)، ولا `Snyk`.
- الوظائف غير مطلوبة في حماية الفرع بعد (قرار مالك بعد استقرار).
- لا ادّعاء بأن كل فئات الثغرات مغطاة؛ القواعد محدودة بما يدعمه CodeQL.
