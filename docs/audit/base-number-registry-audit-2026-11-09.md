# تدقيق سجل أرقام الأساس v2 — 2026-11-09

> **النطاق:** تدقيق قراءة فقط قبل هجرة `BaseNumberRegistry` / `BaseNumberRegistry_Pg`.
> **المرجع:** `docs/base-number-registry-plan-v2.md` §8.1 و§10.

## 1) محاولة الوصول إلى قاعدة `Supabase` الحية

- سلسلة `DATABASE_URL` قُرئت من `001.txt` على سطح المكتب **دون طباعتها**.
- المضيف المباشر (`db.<ref>.supabase.co`) يُرجع سجل `AAAA` فقط، ولا توجد واجهة `IPv6` على جهاز التنفيذ،
  لذلك تعذّر الاتصال المباشر.
- جُرّبت عناوين برك `Supabase` (`aws-0/aws-1-<region>.pooler.supabase.com`) للمناطق المعروفة:
  الردود كانت `tenant/user postgres.<ref> not found` أو مهلات شبكة، فلم يُحدَّد مضيف بركة صالح.
- **النتيجة:** تعذّر تنفيذ تدقيق §8.1 على القاعدة الحية من بيئة التنفيذ هذه.
  لم تُطبع أي أسرار أو بيانات شخصية.

## 2) النسخة الاحتياطية

- Render free بلا نسخ آلية، وتعذّر `pg_dump` لعدم الوصول إلى القاعدة.
- **قبول مخاطرة موثّق (مؤقت):** لا تُطبَّق الهجرة على القاعدة الحية قبل أخذ نسخة احتياطية
  (`pg_dump` أو لقطة من مزوّد `Supabase`) وتشغيل تدقيق §8.1 من بيئة تملك `IPv4`/بركة صالحة.

## 3) تدقيق قاعدة التطوير المحلية (لقطة 2026-11-06)

على نسخة من `backend/src/DocGenerator.Api/docgen.db` (قراءة فقط، ثم نسخة اختبار منفصلة):

| البند | القيمة |
|---|---|
| إجمالي الملفات | 67 |
| الملفات المحذوفة منطقيًا | 41 |
| صفوف `DocumentBaseNumbers` | 0 |
| الملفات المرقّمة | 64 |
| تكرارات بعد التطبيع `(CircuitId, TypeKey, Year, NumberKey)` | 0 |
| ملفات مرقّمة بلا دائرة | 0 |
| ملفات ذات وقعة تبديل دائرة من التعديل | 0 |
| صفوف أقدم من وقعة تبديل الدائرة | 0 |
| ملف مرقّم بسنة مستقبلية (2027) | 1 (بيانات تجريبية) |

- مسار الهجرة المختار: **هجرة واحدة لكل سياق** (`BaseNumberRegistry` / `BaseNumberRegistry_Pg`) مع
  تعبئة وبوابات توقف داخلية، لأن مخطط `DocumentBaseNumbers` موجود وقد تحمل القاعدة الحية صفوفًا.
- **انحراف موثّق:** يبقى عمودا `ExecutionCircuitId` و`CircuitName` قابلين للفراغ على مستوى القاعدة
  (مع تعبئتهما لكل الصفوف)، لأن حذف دائرة إدارية يستخدم `ON DELETE SET NULL` ويجب أن يبقى الصف
  التاريخي معروضًا (`CircuitName` لقطة). الكاتب `IDocumentNumberRegistry` يفرض دائرة لكل كتابة جديدة،
  ومراجعة الاتساق R9 ترفض الإقلاع عند أي ملف مرقّم بلا صف قيد/دائرة.
- اختُبرت الهجرة على نسخة التطوير بعد تصحيح السنة المستقبلية في **نسخة الاختبار فقط**: نتج 64 صف قيد،
  39 صفًا ملغى `document-deleted` للمحذوفة، صفر صفوف بلا دائرة، وصفر ملفات مرقّمة بلا صف قيد.
- **ملاحظة نشر:** إن رفضت الهجرة على القاعدة الحية بسبب صف بلا دائرة/تبديل دائرة/تكرار/سنة غير صالحة،
  فالرسالة تحدد البوابة؛ عالج الصفوف يدويًا ثم أعد التطبيق. لا تُنسب الصفوف القديمة للدائرة الحالية صامتة.

## 4) خلاصة

- الكود والهجرات جاهزة، لكن **التدقيق الحي والنسخة الاحتياطية معلّقان على بيئة تملك اتصالًا صالحًا**.
- قبل النشر: `dotnet ef database update --context DocGeneratorDbContext` ثم
  `dotnet ef database update --context DocGeneratorPostgresDbContext`، وإلا رفض الإقلاع
  (`Database:AutoMigrate=false`).
