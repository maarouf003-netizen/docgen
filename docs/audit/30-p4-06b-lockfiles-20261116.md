# P4-06b — أقفال الاعتماديات ووضع القفل الصارم — 2026-11-16

> نطاق هذه الجولة: إكمال ما أُجّل في `P4-06`: `packages.lock.json` لكل مشروع، والتحقق
> بـ`locked-mode` في `CI`، وتوثيق سير عمل تحديث الأقفال. لا تغيير في كود التشغيل.

## 1. المشكلة

بعد `CPM` صار **المباشر** مثبّتًا مركزيًا، لكن حلّ **التابعين** بقي عائمًا داخل نطاقات
`NuGet`: بناءان على جهازين مختلفين قد يجلبان إصدارات تابعين مختلفة، فلا قابلية إعادة
إنتاج كاملة — وهو ما يهم في نظام قانوني يُنشر بنسخ محددة.

## 2. ما طُبّق

1. `backend/Directory.Build.props`: `<RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>`.
2. `dotnet restore --force-evaluate` ولّد **7 ملفات** `packages.lock.json`
   (Domain/Application/Infrastructure/Api + ثلاثة مشاريع اختبار)، والتزمت في Git.
3. `CI` يتحقق بالقفل الصارم:
   - `backend`: خطوة `Restore (locked)` ثم `dotnet build --no-restore -warnaserror`.
   - `backend-postgres`: `Restore (locked)` قبل الاختبارات.
   - `migration-guard`: التهيئة `--locked-mode` (كانت عادية).
   - `audit`: `Restore (locked)` قبل `dotnet list package` (الأمر يُعيد التهيئة تلقائيًا).
   - `flake-sentinel`: `Restore (locked)` + بناء `--no-restore`.
4. أي انحراف يفشل بـ`NU1004` صراحةً، فلا يمرّ بناء بمكوّنات مختلفة بصمت.

## 3. سير العمل المعتمد (للمطوّر)

- ترقية/إضافة حزمة: عدّل `backend/Directory.Packages.props` ثم `dotnet restore`
  (يحدّث الأقفال) و**التزم ملفات `packages.lock.json` في نفس التغيير**.
- لا تُستخدم `--force-evaluate` إلا لتحديث مقصود بعد مراجعة فرق الأقفال.
- `CI` يفشل عند نسيان الالتزام — وهذا هو الغرض.

## 4. التحقق

- `dotnet restore --locked-mode` على الحالة الملتزمة: نجح.
- `dotnet build --no-restore -warnaserror`: 0 تحذير/خطأ.
- **تحقق سلبي:** تغيير `AngleSharp` في CPM إلى `1.7.0` بلا تحديث القفل ⇒
  `NU1004: ... Lock file version [1.7.1, ), central package management version [1.7.0, )`
  + «lock file is inconsistent ... pass `--force-evaluate`». أُعيد الإعداد الأصلي
  فعاد `locked-mode` نظيفًا.
- الحلقة السريعة + `Architecture.Tests` بعد التغيير ✅ (لا تغيير كود).

## 5. حدود

- القفل يغطي حزم `NuGet` فقط؛ أدوات `dotnet tool` (مثل `CycloneDX`/`dotnet-ef`) مثبّتة
  بإصدار صريح في `CI` لكنها ليست داخل `packages.lock.json`.
- `npm` مقفول أصلًا بـ`package-lock.json` (وسبقت إضافة `npm ci` في وظيفة `audit`).
- لا يزال `dotnet format`/المحللات خارج البوابة (ديون تنسيق قائمة) — `P4-06` يبقى
  جزئيًا لهذا السبب فقط.
