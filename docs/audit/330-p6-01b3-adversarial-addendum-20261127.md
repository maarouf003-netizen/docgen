# مراجعة عدائية وملحق تصحيحي — `P6-01b/3` — 2026-11-27

## 1. دليل الطفرة الفعلي (نُفِّذ ثم أُعيد)

| الطفرة | النتيجة |
|---|---|
| حذف `rejectedOnly` من `queryKey` | **فشل اختباران**: تمرير الفلتر، وعدم تكرار المفتاح المخزَّن |
| حذف `invalidateRequests()` من `onSuccess` | **فشل** اختبار «إعادة الجلب بعد الفعل» (القائمة القديمة تبقى) |
| إعادة الملف إلى `useCancellableRequest` (خطأ تشغيلي أثناء الطفرة) | اكتُشف فورًا بـ`tsc`/الاختبارات، وأُعيد الترحيل — دليل أن الاختبارات تمسك الاكتمال |

## 2. محاولات إفشال إضافية (تحليل/تنفيذ جزئي)

| المحاولة | النتيجة |
|---|---|
| فعل توجيه بلا `sectionId` | زر التوجيه معطّل قبل الإرسال (شرط `redirectSectionId === ''`) |
| رفض بلا سبب | الزر معطّل، والحمولة لا تُرسل |
| فشل `POST` | رسالة الخادم في `role=alert`، والنافذة تبقى مفتوحة، والصف يُعاد تفعيله |
| تبديل الفلتر أثناء فعل جارٍ | `busyId` يخص الصف، والفلتر يجلب مفتاحًا آخر؛ لا تعارض حالة |
| فشل `/sections` لرئيس قسم | الصفحة تعرض الطلبات، ونافذة التوجيه تعرض خيارًا افتراضيًا فقط |
| رئيس شعبة يفتح الصفحة | لا طلب `/sections` (enabled)، ولا زرا توجيه/تراجع |
| خطأ تحميل أولي | رسالة + زر «إعادة المحاولة» يعمل عبر `refetch` |
| الاعتماد ثم الرجوع للصفحة | الإبطال يجلب القائمة الجديدة (اختبار قائم + عدّ) |

## 3. حالات حدّية

- `delegations = []`: حالة فارغة كما هي.
- `rejectedOnly` صحيح: `params: { rejectedOnly: true }` (بلا `false` صريح).
- `redirectedToSectionId = 0`: `!= null` يبقى صحيحًا (لا انحراف عن المصدر).
- `assignedLawyerId = 0`: الشرط `== null` كما كان.
- فشل `onSuccess` في الإبطال (شبكة): يبقى النجاح ظاهرًا وتُعاد المحاولة عند أول تفعيل
  لاحق (TanStack يعيد الجلب عند `mount`/`invalidate`).

## 4. بقايا

- لا استيراد ميت (`tsc`/`oxlint` نظيفان).
- لا نسخة ثانية من مسارات الأفعال أو شروط العرض.
- لا تغيير في عقد `/delegations/*` ولا في الصلاحيات.

## 5. الحكم

الطفرة الفعلية تثبت أن الاختبارين الجديدين غير أجوفين. لا فجوة متبقية.
