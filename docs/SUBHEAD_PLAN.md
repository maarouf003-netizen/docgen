# خطة رئيس الشعبة (`SubHead`) — وثيقة معتمدة للمراجعة (لا تنفيذ قبل موافقة المالك)

> الحالة: **معتمدة ومنفَّذة (المراحل 1–8م)** على فرع `feature/subhead` — البوابات خضراء؛
> المرحلة 9 (عزل/سباق + `PR`) جارية. القرارات الـ29 أدناه ملزمة كما هي — أي تعديل سلوكي
> لاحق يتطلب موافقة المالك الصريحة أولًا.
> الفرع الحي `master` محمي — الدمج عبر `PR` فقط (بلا دفع مباشر).
> تاريخ آخر مراجعة شاملة مقابل الكود: 2026-10-06 (أربعة تدقيقات مستقلة + تحقق مباشر من ~20 ادعاءً)؛ مراجعة ثانية للنسخة المُعاد كتابتها بنفس التاريخ (أصلحت مرجعين مكسورين + صياغة فهرس معكوسة، وأضافت القرارات 22′/23′/25′/27/28/29 بإجابات المالك).

## 1. الهدف والنطاق

- إضافة دور سادس `SubHead` بصلاحيات رئيس القسم نفسها (`Head`) لكن محصورة **بملفات دوائر تنفيذ تتبع له** داخل نفس `BranchId` للفرع الأم (مثال: `شعبة مصياف — فرع حماة`).
- التبعية **حسب الملف** (دائرة الملف) لا بتثبيت المحامي؛ المحامي قد تكون له ملفات في نطاقين، وكل ملف يُعامَل حسب دائرته.
- لا إشراف متبادل: رئيس القسم لا يرى ملفات الشعب والعكس (عزل كامل)، باستثناءات موثقة أدناه (§17).
- الاستئناف: تنبيه واحد لمالك دائرة الملف + إحالة `شعبة → قسم` فقط + تراجع قبل الإسناد.
- الإنابة: التوجيه حسب **الدائرة المنابة** (`DelegatedCircuitId` إلزامي للداخلية) + توجيه الخارجية لرئيس القسم ثم لشعبته + رفض يُعاد للمحامي.
- **طبقة التفويض**: مساعد مركزي `IsHeadOrSubHead` + سياسة واحدة بدل تعديل السمات يدويًا (قرار §2.21).

## 3. نتيجة المراجعة النقدية مقابل الكود (ملخص الفحص — معتمد كملحق إلزامي)

- لا يوجد أي `SectionId`/`SubHead`/`RecipientSectionId` في الكود اليوم (النتيجة الوحيدة: تعليق توسعة في `backend/src/DocGenerator.Api/Authorization/RolePermissions.cs:139`). أي إحالة/تراجع/نطاق شعبة **مستحيل دون هجرات**.
- **طبقة التفويض أربع لا واحدة**: `RolePermissions.Can*` + سمات `[Authorize(Roles=...)]` (38 سمة بعدّ مباشر — ترفض `subhead` قبل أي منطق) + فحوصات `IsHead / Role == UserRole.Head` (~50 موقعًا تشتق النطاق، وتفشل **مفتوحة**: `UserManagementController.cs:91,106,137,159` تعطي `branchId` العميل، و`StatisticsController.cs:109,134,174` توسع للإحصاءات، و`AuditLogsController.cs:31` تُسقط الفلتر، وخدمات الجهات تتخطى فلترة المحافظة) + مبدّلات `role switch` بـ `_ => throw` (`CorrespondenceService.cs:162`، `ReviewLetterService.cs:125`). الخطة تغطيها كلها عبر القرار 21.
- `§5.1` الأصلية ذكرت ~10 من 15 `Can*` — **المكتمل**: تُوسَّع الخمس الغائبة أيضًا (`CanViewDeletedDocuments:24`، `CanViewCounters:34`، `CanSeeAssignedLawyer:96`، `CanSearchByLawyer:100`، `CanManageEntityRegistry:111`)، وتُوثَّق **المجموعة السلبية** (لا يرث `HasFullAccess`، `CanManageUsers`، `CanManageBranches`، `CanSeeAdministrativeBranch`).
- سباق الإسناد في **3 مسارات** (`AssignAsync:326` خارج `_tx:336`، و`TransferAsync:369` خارج `379`، و`TransferAll:409` خارج `411`) + `TransactionRunner` بلا عزل عمدًا (`B1`) → الحل: عمود `Version (IsConcurrencyToken)` + فحص بعد إعادة القراءة داخل المعاملة في الثلاثة + اصطياد `DbUpdateException` وتحويله لرسالة `مأخوذة مسبقًا` (فهرس `SourceDelegationId` الفريد يحمي الإنابة من التوأم لكنه يرمي `500` غير مترجم اليوم).

- `GET /users/lawyers` مفلتر خادميًا بالفرع فقط (`UserManagementController.cs:91`) وكل المودالات تستدعيه بلا بارامتر — الفصل يتطلب وضعين خادميين لا فلترة واجهة، مع قاعدة تفويض خادمية لمن يجوز له `mode=branch`، ومعالجة القدامى (`CreatedById = null` يراهم الجميع دائمًا — تُضمَّن في `mode=mine`).

## 4. نموذج البيانات (هجرات `SQLite` + `Postgres`)

1. `UserRole.SubHead = 6` + تسمية `رئيس شعبة` + حارس `Enum.IsDefined` في `ParseRole` (`UserManagementService.cs:309` يقبل رقمية اليوم).

3. `User.SectionId?` (إلزامي لـ `SubHead`، `null` لغيره) + `User.CreatedById?` (يضبطه فاعل الإنشاء في `CreateLawyerAsync` — المصدر: المستخدم المنشئ؛ `null` للقدامى).

5. `DocumentAppeal`: حقول إحالة `ForwardedBy?, ForwardedAt?, ForwardState (Owned|ForwardedToHead), ForwardReason?` + عمود `Version (IsConcurrencyToken)` — كل `NOT NULL` جديد بـ `DEFAULT` صريح + ترحيل صفوف (`Owned` + `Version = 1`) وإلا فشلت `ALTER TABLE` في `SQLite`.
6. `DocumentDelegation`: حقول `RedirectedToSectionId?, RejectReason?` + عمود `Version (IsConcurrencyToken)` + **فحص خدمة بدل `CHECK`**: داخلية (`IsExternal = false`) ⇒ `DelegatedCircuitId NOT NULL` (مع backfill للصفوف الثلاثة: قديمة/انتقالية/مفكوكة بالحذف، وتعديل `DeleteAsync` ليتوافق)، خارجية ⇒ `DelegatedCircuitId IS NULL`.
7. `ReviewLetter.RecipientSectionId?` + `Correspondence.RecipientSectionId?` (لبلا ملف) — مع عقد §10: `TargetUserId` = الرئيس المفعّل وقت الإنشاء (قرار 24).
8. جدول `HeadSuccession { Id, BranchId, SectionId?, UserId, Role, Event, At, ActorName, Reason }` بلا تعديل/حذف — يُكتب ضمن نفس معاملة الحدث عبر `IAuditLogger` نمطًا.
9. فهارس جزئية بصياغة `Postgres`-آمنة: `UNIQUE(User.SectionId) WHERE Role = 'SubHead' AND "IsActive"` + `UNIQUE(User.BranchId) WHERE Role = 'Head' AND "IsActive"` — أي الوحدانية على **المفعّلين فقط** (صياغة `NOT "IsActive"` مرفوضة هنا لأنها تعني المعطّلين؛ نمط `NOT "Col"` يُستخدم فقط لأعمدة تُقارن بالنفي) — مع **فحص ما قبل الهجرة** (رؤساء مكررون/شعب بلا فرع/شعب بلا رئيس مفعّل/دوائر يتيمة) وتقرير تنظيف قبل النشر.
10. ترحيل: الدوائر القائمة `SectionId = null` (ملك القسم)؛ المستخدمون القدامى `CreatedById = null` (مرئيون للجميع)؛ الكتب القديمة بلا مستلم شعبة تُنسَب للقسم (ولا مراسلات قديمة أصلًا حسب المالك — بلا ترحيل)؛ `ForwardState = Owned` و`Version = 1` للصفوف القائمة.

## 5. الصلاحيات والنطاق (الخلفية)

1. **طبقة التفويض المركزية** (قرار 21 — نُفذت في 1ج): مساعد `IsHeadOrSubHead` (أو `RequireHeadOrSubHead`) يُستبدل به كل فحص `Role == UserRole.Head` / `IsHead` المشتق للنطاق، وتُحدَّث سمات `[Authorize]` بسياسة واحدة — لا تعديل يدوي متناثر. **قرار تنفيذي موثق (2026-10-06)**: تحويل السمات الـ38 **مؤجل مرحليًا** — كل سمة تُحوَّل مع فلترة نطاق منطقتها (§5–§12) لا دفعة واحدة، لأن التحويل المبكر يفتح البوابات قبل اكتمال الفلاتر (تسريب عبر `IsHead ? فرعي : branchId-العميل` في `UserManagementController:91` ونظرائه). حتى الاكتمال تبقى السمات ترفض `subhead` (مغلق).
2. توسيع كل `Can*` الخاصة بـ `Head` الخمس عشرة لتشمل `SubHead` (بما فيها الخمس الموثقة في §3) + توثيق **السلبية**: لا `HasFullAccess` ولا `CanManageUsers` ولا `CanManageBranches` ولا `CanSeeAdministrativeBranch`.
3. قاعدة الفلترة: كل استعلام `Head/SubHead` يضيف قيد ملكية الدائرة (`Document.ExecutionCircuit.SectionId = OwnSectionId`، والقسم `IS NULL`) **+ الاستثناء القرائي للإحالة** (قرار 22: `ForwardState = ForwardedToHead` لنفس الفرع — **يمتد لفتح الملف**: `DocumentsController.CanAccess` + مسار `documents/{id}/appeals` + `CanAccessOrFollowAsync`، وينتهي **بعد الحسم النهائي**) — وتشمل: `DocumentsController.CanAccess/Search/Export/FilterOptions/Deleted/StruckOff/Executed/ReferredToStart/Transfer/TransferAll/Count/OwnerCount/View/Generate/Actions/Changes`، `AppealsController` (بحث + `CanAccessDocument:37` + `CanViewAppealAsync:46` + `assign/transfer/transfer-all/owner-count/decide/strike` + مسار `documents/{id}/appeals`)، `DelegationsController.Pending/PendingCount/Assign`، `AlertsController` (قراءة بالمستلم لا بالفرع)، `ReviewLetterService` (+ `pending-count`)، `CorrespondenceService` (+ `targets` + `ListByDocument`)، `StatisticsController` (النقاط الثلاث)، `ExecutionCircuitsController`، `AuditLogsController` (**دائري** — قرار 23)، `UserManagementController` (قراءة وكتابة)، `EntityRegistryController`/`PublicEntityService` (فلترة المحافظة تبقى)، كل المستودعات المقابلة (`HeadAlertRepository.ListByBranchAsync`، `PublicEntityRepository`، `UserRepository`).
4. `GET /users/lawyers` بوضعين خادميين بتفويض صريح: `mode=mine` (الافتراضي: له ملف في دوائري أو أنا أنشأته أو قديم بلا منشئ — الثلاثة ضمن نطاق الفرع) و`mode=branch` (نوافذ الإسناد/النقل فقط + صفحة `BranchLawyers` للإدارة) — مع فلتر `IsActive` المعلن سلوكه.
5. `TransferAll` (ملفات واستئنافات) ينقل **نطاق المالك فقط** (تقاطع `SourceLawyerId` مع ملكية الدائرة) مع تحذير صريح في الواجهة + إصلاح مسار المعاينة `owner/{id}/count` للنطاق نفسه.
6. ملفات `ExecutionCircuitId = null` (مسودة/خارجي/انتقالي): مرئية لرئيس القسم + منشئ الملف فقط (لا للشعب) — بصيغة قيد صريحة: `(الملكية) OR (ExecutionCircuitId IS NULL AND (القسم OR المنشئ))`، والملف الخارجي المخزن بفرع أجنبي يُعامل بقاعدة فرعه المخزن.
7. **بطاقة الملف المناب للفرع المصدر** (قرار 25): في `DocumentView` للملف **المنيب** (المصدر) تُعرض بطاقة تفاصيل قراءة فقط للملف **المناب** المرتبط (`ExecutedByDelegationId IS NOT NULL`) لرئيس قسم فرع المصدر — **دون** منحه `CanAccess` على الملف المناب نفسه (لا قوائم، لا إحصاء، لا تحرير، لا ملاحة مباشرة للملف المناب). شرط البوابة الصريح: الطالب رئيس قسم + فرعه = فرع الملف المنيب.

## 6. الاستئنافات

1. الإشعار الأولي لمالك واحد حسب دائرة الملف (`SectionId` → رئيس شعبته، `null` → رئيس القسم) — مع تحميل سلسلة `Include(ExecutionCircuit)` في مسار الإشعار.
2. زر `إحالة لرئيس القسم` لرئيس الشعبة فقط (اتجاه واحد) بالنص المعتمد + حذف **انتقائي** لتنبيهه وإنشاء تنبيه قسم + تدقيق `forward_appeal` + ترجمة المفتاح في `AuditLogs.tsx ACTION_LABELS`.
3. الإحالة استثناء لمرة واحدة (القسم يسند رغم أن الدائرة ليست له) لأي محامٍ في `BranchId` — مخرج صريح في `AssignAsync` + الاستثناء القرائي (قرار 22: **يبقى القسم يرى المسار كاملًا حتى الحسم**).
4. الرؤية بعد الإحالة: المحيل يبقى يرى (قراءة)؛ القسم يرى المحال له **حتى الحسم النهائي** (قرار 22′ — لا اختفاء بعد الإسناد)؛ ما أسنده رئيس الشعبة في دوائره لا يراه القسم.
5. التراجع قبل الإسناد فقط (المحيل استرجاع / المستلم إعادة) + تدقيق `recall_forward`؛ بعده نقل عادي — دون كسر تمييز `AppealsList` (`mode transfer` التلقائي يراعي `ForwardState`) — وبعد الحسم ينتهي الاستثناء وتعود الرؤية الدائرية الصرفة.
5. التراجع قبل الإسناد فقط (المحيل استرجاع / المستلم إعادة) + تدقيق `recall_forward`؛ بعده نقل عادي — دون كسر تمييز `AppealsList` (`mode transfer` التلقائي يراعي `ForwardState`).
6. نقل الدائرة يعيد توجيه الإحالات المفتوحة للمالك الجديد + تدقيق (التنبيهات المسلَّمة سابقًا تُعالج: إنشاء بديلة للمالك الجديد لا تعديل القديمة).
7. ذرية المسارات الثلاثة: `Version` + فحص بعد إعادة القراءة داخل `‎_tx` + اصطياد تعارض + اختبار سباق مزدوج لكل مسار.
8. `AppealDto` يحمل `ForwardState/SectionId/ExecutionCircuitId` (للبحث والعرض).
9. قرار توفّر معتمد (F7 — أ): إشعار ملف شعبة بلا رئيس مفعّل يسقط على رئيس القسم — مع تدقيق `head_alert_failed` وتنبيه (`DocumentAppealService.cs:1150-1153`) بدل الضياع الصامت؛ توسيع مقصود لنص «`null` → قسم»، لا تسريب (المستلم قسم الفرع نفسه).

## 7. الإنابات

1. قلب القاعدة للداخلية: الاعتماد لمالك **الدائرة المنابة** لا المنيب (يشمل العابرة للفروع: مالك الدائرة أينما كان) — بتعديل متزامن: `PendingByBranchQuery` + فرع الاعتماد في `AssignAsync` + قيد فرع المحامي + نطاق التنبيه.
2. `DelegatedCircuitId` إلزامي للداخلية مع منع `أنشئ دائرة أولًا`؛ `DelegatedCourt` النصي للخارجية فقط — بفحص خدمة (لا `CHECK`) يطابق `IsExternal`.
3. الخارجية لرئيس قسم الفرع المناب ثم زر `توجيه للشعبة` (قائمة شعب فرعه) بالنص المعتمد + تراجع قبل الإسناد.
4. الدائرة الخطأ: رفض برسالة معتمدة تُعيد المحامي للتصحيح — مع فلتر `مرفوض بانتظار التصحيح` في نافذة الاعتماد والعدّاد + سطح رؤية للمحامي (بطاقة الملف + تنبيه `by-delegation`) وإلا بقي الرفض غير مرئي له.
5. **الملف المناب `BranchId/ExecutionCircuitId` من الدائرة المنابة** (قرار 25) — فيورث النطاق تلقائيًا (دائرة تتبع للشعبة ⇒ إحصاءاتها)؛ **ولا وصول استمرار لقسم الفرع المصدر** — فقط بطاقة §5.7 للملف المنيب.
6. تعديل قاعدة `DelegationService:375-378` صراحة (المحامي من فرع ≠ فرع الملف مشروع في العابرة) + `BranchName`/`AdministrativeBranchName`/`governorateFromBranch` من الفرع الجديد.
7. ذرية الاعتماد + تحويل `DbUpdateException` الفريد إلى `مأخوذة مسبقًا` + اختبار.

## 8. الدوائر والشعب (الإدارة)

1. `Admin` فقط اليوم للفروع ← يصبح `Manager + Admin` للفروع **والشعب** (توسيع مقصود موثق؛ البوابة الفعلية `CanManageBranches:50` + `BranchesController:25,38,62` — لا `GuardManagerAdminBoundary` الذي يخص حسابات `Admin` فقط).
2. زر `إضافة شعبة` بجانب `إضافة فرع` (مشروط بوجود الفرع الأب — واجهة، مرحلة الواجهة) + تعديل الاسم + حذف/تعطيل ممنوع مع وجود دوائر (وجوب اختيار مالك بديل ينقلها دفعة + تدقيق + سجل تعاقب) — تنفيذيًا: التعطيل إخفاء من القوائم فقط ولا يوقف عمل الرئيس (مرآة فلسفة السجل)، والحذف يتطلب صفر دوائر وصفر حسابات.
3. إجراء `نقل دائرة` باختيار المالك الجديد (قسم الفرع أو شعبة فيه — النقل داخل الفرع نفسه؛ `BranchId` الدائرة لا يتغير أبدًا) — المفتوح والمغلق يتبع الجديد، والتدقيق ثابت.
4. `Admin` لا ينشئ دوائر (النقل فقط)؛ الدائرة ينشئها صاحبها وتلحق به تلقائيًا (ضبط `SectionId` من المنشئ في `CreateAsync`).
5. شعبة فارغة مسموحة (رئيسها ينشئ دوائره).

## 9. الحسابات والخلافة والتعاقب

1. إنشاء `SubHead`: فرع + شعبة (مفلترة بالفرع) إلزاميان + تطابق الفروع + رفض `الشعبة مشغولة برئيس مفعّل` + إظهار الإشغال في القائمة — مع توسيع حارس الدخول `AuthService.cs:123` ليشمل `SubHead` (فرع `null` يُرفض).
2. رئيس قسم واحد مفعّل لكل فرع (رفض الثاني) — بعد تنظيف ما قبل الهجرة.
3. التعطيل دائمًا مسموح مع خلف إجباري (قائم أو جديد) في نفس المعاملة: نقطة نهاية/حقل `successor` جديد في `UpdateUserRequest` + تعطيل السلف + `TokenVersion++` + منح الخلف نفس `SectionId` + نقل `CreatedById` لمحامي الصفر ملفات + نقل التنبيهات المعلقة والكتب المعلقة + تدقيق + سجل تعاقب. يسري على القسم أيضًا. (ملاحظة: `SetLawyerActiveAsync:151` مقصور للمحامين اليوم — يلزم مسار تعطيل رؤساء.)
4. إعادة تفعيل قديم مع خلف مفعّل → رفض برسالة (لا خطأ قاعدة — mapping نمط `CorrespondenceService.cs:302`).
5. `HeadSuccession` يُكتب آليًا (تعيين/تعطيل/إحلال/نقل دائرة/تعديل اسم) ويراه المدير والمشرف فقط (تبويب في صفحة الفروع).
6. التوكن: `section_id` + تحقق دفاعي في **`Program.cs:182-200` (`OnTokenValidated`)** + امتداد `GetSectionId` + إسقاط الجلسات عبر `TokenVersion`.
