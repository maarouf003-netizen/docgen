# خطة سجل أرقام الأساس — النسخة v2 (المبسّطة)

> **الحالة:** معتمدة من المالك (v2 + الفروق الثلاثة) في 2026‑11‑08 — **لا يبدأ التنفيذ قبل إذن صريح**.
> **النطاق:** أرقام أساس الملفات التنفيذية (`DocumentBaseNumbers`).
> **خارج النطاق:** أرقام أساس الاستئنافات (`AppealBaseNumbers`).
> **النسخة v1 (جدول الأرشيف + `RotationEligibleFromYear` + `Kind`) مُلغاة**؛ هذه الوثيقة تحلّ محلها.

---

## 0) ضمان الحفظ (تأكيد صريح)

**كل رقم أساس سُجِّل كصف يبقى محفوظًا ومعروضًا في «سجل أرقام الأساس» — لا يُحذف صف فيزيائيًا أبدًا.**

| الحالة | يبقى الصف؟ | يظهر في السجل؟ | الأثر على الهوية/الحجز |
|---|---|---|---|
| القيد الأول | ✅ | ✅ «قيد» | هوية سنة القيد |
| تعديل سنة القيد أو إفراغه | ✅ (بعلامة **ملغى**) | ✅ «قيد ملغى/سابق» | يُحرَّر الرقم القديم؛ الصف الجديد فعّال |
| التدوير السنوي | ✅ | ✅ «تدوير سنة …» | هوية سنته؛ الأقدم توثيق |
| الشطب | ✅ | ✅ «رقم سنة الشطب» | يبقى حاجزًا في سنته |
| التجديد بعد الشطب (نفس السنة أو غيرها) | ✅ القديم + الجديد | ✅ الاثنان | الأحدث `CreatedAt` هو الفعّال؛ المشطوب توثيق |
| الإحالة إلى دائرة أخرى | ✅ | ✅ مع اسم الدائرة القديمة | يبقى حاجزًا في **دائرة الإدخال القديمة/سنتها**؛ لا يؤثر في الدائرة الجديدة |
| تغيير الدائرة من التعديل | ✅ القديم + الجديد | ✅ | الجديد هوية الدائرة الجديدة؛ القديم توثيق |
| العودة إلى دائرة قديمة | ✅ | ✅ | رقم جديد للسنة الحالية؛ القديم توثيق |
| حذف الملف | ✅ (بعلامة **ملغى**) | ✅ «ملغى — حذف ملف» | يُحرَّر الرقم (يُستثنى من الفهرس الفريد) |
| التراجع عن تدوير السنة الحالية | ✅ (بعلامة **ملغى**) | ✅ «ملغى — تراجع» | يُحرَّر الرقم؛ يعود الملف للجدول |
| التصحيح | ✅ الصف نفسه | ✅ القيمة المصحّحة | القيمة السابقة تبقى في **سجل التدقيق** (قبل/بعد)، لا كصف رقم منفصل |

> الاستثناء الوحيد لـ«الظهور كرقم» هو **التصحيح**: الصف يبقى لكن بقيمته المصحّحة، والسابقة في التدقيق.
> الحذف والتراجع **لا يحذفان الصف**، بل يضعان `VoidedAt` (ملغى) ويحرران الرقم.

### 0.1 التكرار: طبقتان (حجب صلب + تجاوز موثّق)

| الطبقة | الحالة | السلوك | الرسالة |
|---|---|---|---|
| **حجب صلب** | نفس الدائرة + النوع + السنة، وصف **غير ملغى** (بما فيه مشطوب/منفذ) | رفض نهائي `409 number_duplicate` — **لا تجاوز** | «الرقم {n} مستخدم بالفعل في الدائرة نفسها لسنة {year} ونوع {type}. لا يمكن تكرار الرقم…» |
| **تحذير + تجاوز** | نفس السنة + النوع، لكن الصف **ملغى** (في نفس الدائرة **أو دائرة أخرى**) أو **غير ملغى في دائرة أخرى** | `409 number_reuse_warning`؛ يُقبل بإعادة الإرسال مع `warningToken` الصادر مع التحذير + تدقيق | «تأكد من الرقم {n}؛ لأنه مستخدم في ملف آخر (سنة {year}، نوع {type}، دائرة {circuit}). هل تريد إدخاله على أي حال؟» |
| **مسموح بلا تحذير** | سنة سابقة، أو نوع مختلف، أو دائرة+سنة مختلفتان | يُدخل مباشرة | — |

- **من يملك التجاوز؟** المالك الذي يُدخل الرقم (المحامي) — وليس أي دور آخر.
- **التجاوز لا يمسّ الحجب الصلب**؛ قاعدة «لا رقمين متطابقين في نفس الدائرة/النوع/السنة» باقية.
- **المشطوب/المنفذ** صفّه غير ملغى ⇒ ضمن **الحجب الصلب** (رقم سنة حالية محجوز)؛ تجاوزه يحتاج تغيير D‑05 صراحةً.
- **لا كشف للملف الآخر (R6):** الرسائل لا تحمل معرّف/اسم/حالة الملف الآخر؛ تُظهر النطاق (السنة/النوع/الدائرة) فقط. المعرّف/الحالة للتدقيق الداخلي.
- **`warningToken` (R7):** رمز قصير العمر يصدره الخادم مع `409`، مرتبط بالمستخدم + الصف المصادم + بصمة الطلب؛ يُشترط إرجاعه. لا يُقبل `confirmReuse` منطقي أعمى.
- **التدقيق:** يُسجَّل التجاوز مع رقم الملف الآخر/سنته/دائرته/نوعه (داخليًا).

## 1) النموذج الذهني

- لكل ملف **أرقام أساس**، كل رقم مرتبط بـ**سنة** و**دائرة إدخال** ونوع.
- **الرقم الفعّال** هو رقم **السنة الحالية** في **دائرة الملف الحالية**؛ وإلا **أحدث رقم سابق** في الدائرة نفسها؛ وإلا `FileNumber`.
- كل رقم لسنة/دائرة أخرى هو **توثيق** يظهر في السجل ولا يدخل الهوية اليومية.
- عند قدوم سنة جديدة: جدول يعرض الملفات التي لها رقم سابق **ولا رقم للسنة الحالية**، مع رقمها السابق وحقل إدخال الرقم الجديد.
- الشطب/التجديد: الجديد هو المعتبر، والقديم توثيق.
- الإحالة: القديم يبقى في دائرة الإدخال القديمة للتوثيق؛ والجديد يُدخل في الدائرة الجديدة.

## 3) نموذج البيانات

### 3.1 `DocumentBaseNumbers` (الجدول الوحيد)

| العمود | النوع | الوصف |
|---|---|---|
| `Id` | int PK | — |
| `DocumentId` | int FK → `Documents` | الملف |
| `ExecutionCircuitId` | int FK → `ExecutionCircuits` **NOT NULL** | دائرة الإدخال (نطاق التفرد) |
| `CircuitName` | nvarchar(200) **NOT NULL** | لقطة اسم الدائرة وقت الإدخال (للعرض بعد إعادة التسمية) |
| `Year` | int | السنة |
| `FileType` | nvarchar(100) NULL | لقطة النوع |
| `TypeKey` | nvarchar(100) NOT NULL | النوع مطبَّعًا |
| `BaseNumber` | nvarchar(50) NOT NULL | الرقم للعرض |
| `NumberKey` | nvarchar(50) NOT NULL | الرقم مطبَّعًا |
| `Source` | nvarchar(20) NULL | `registration` / `rotation` / `renewal` (اختياري، للوسم/التراجع) |
| `CreatedById` / `CreatedAt` / `UpdatedAt` | (قائم) | التدقيق |
| `UpdatedById` | int NULL | آخر مصحّح |
| `VoidedAt` | datetime NULL | **ملغى** (حذف/تراجع) — `null` = فعّال |
| `VoidedById` | int NULL | من ألغى |
| `VoidReason` | nvarchar(30) NULL | `document-deleted` / `undo-rotation` / `registration-superseded` / `registration-cleared` |

**الفهارس:**
- فريد جزئي: `(ExecutionCircuitId, TypeKey, Year, NumberKey)` بشرط `VoidedAt IS NULL`.
- غير فريد: `(DocumentId, Year, CreatedAt)` للتاريخ.
- `(ExecutionCircuitId, Year)` للهوية.

**ملاحظات:**
- لا تُقبل صفوف بلا دائرة (V‑18).
- `VoidedAt` لا يحذف الصف؛ يُخرجه من الفهرس الفريد ومن الهوية، ويبقى في السجل.
- فلتر الاستعلام على المستند الأب: يُستخدم `IgnoreQueryFilters` عند عرض سجل ملف محذوف (V‑17) **وعند فحص التحذير** (E7).
- **FK:** `OnDelete(Restrict)` للمستند/الدائرة/المستخدم (الحذف المنطقي فقط).
- **`Source=null`** لصفوف قديمة: البحث عن صف القيد يستخدم `Source=registration` في الدائرة/السنة أولًا؛ وإن لم يوجد يُقبل احتياطيًا صف `Source IS NULL` **بشرط `NumberKey == NormalizeNumber(FileNumber)`** و`VoidedAt IS NULL`؛ وإلا يُنشأ صف جديد (E16/R10).

## 4) السياسة والسجل

```csharp
// نقي: قواعد فقط
public static class DocumentBaseNumberPolicy
{
    public const int MaxNumberLength = 50;

    public static string NormalizeType(string? fileType);
    public static string NormalizeNumber(string? number);              // يرمي عند الفارغ
    public static string? ValidateNumber(string? number, string fieldName);
    public static int? ValidateYear(string? rawYear, int currentYear);  // رقمي + 1900..current

    public static bool IsEligible(Document doc, int currentYear);       // V-12
    public static bool NeedsRotation(Document doc, int currentYear) => IsEligible(doc, currentYear);

    public static EffectiveNumber? ResolveEffective(Document doc, int asOfYear); // دائرة الملف الحالية
    public static IReadOnlyList<BaseNumberHistoryDto> BuildHistory(
        Document doc, IReadOnlyCollection<DocumentBaseNumber> rows, int currentYear); // يشمل الملغى
}

// البيانات/الكتابة: معاملة + قفل + تفرد
public interface IDocumentNumberRegistry
{
    Task SyncRegistrationAsync(Document doc, int? actorUserId, string? warningToken, CancellationToken ct);
    Task<NumberConflict?> FindConflictAsync(int? excludeRowId, int circuitId, string typeKey, int year, string numberKey, CancellationToken ct);
    Task AddRotationAsync(Document doc, string number, int actorUserId, string? warningToken, CancellationToken ct);
    Task CorrectAsync(int documentId, int year, int? rowId, string number, int actorUserId, string? warningToken, CancellationToken ct);
    Task UndoRotationAsync(int documentId, int year, int actorUserId, CancellationToken ct);
    Task VoidForDocumentDeleteAsync(Document doc, int actorUserId, CancellationToken ct);
    Task<IReadOnlyList<BaseNumberHistoryDto>> GetHistoryAsync(int documentId, CancellationToken ct);
}

public sealed record NumberConflict(
    bool IsHard, int ExistingDocumentId, int Year,
    int CircuitId, string CircuitName, string FileType, string? Status,
    string? WarningToken); // للرد الداخلي/التدقيق؛ لا يُعرض المعرّف/الحالة للمستخدم غير المخوّل
```

**الفعّال (V‑04):** أحدث صف **غير ملغى** في `ExecutionCircuitId == دائرة الملف الحالية` و`Year <= asOfYear`، ترتيب `Year DESC, CreatedAt DESC, Id DESC`، وإلا `FileNumber`.

**الأهلية (V‑12):**

| الشرط | التفصيل |
|---|---|
| `!IsDraft` / `!NeedsRegistration` / `!IsDeleted` | كما هو |
| `ExecutionCircuitId != null` | V‑18 |
| الحالة | منفذ/إيداع: `ExecutedStatus == None`؛ غير ذلك: `!IsExecuted && != "مشطوب"` |
| لا صف غير ملغى للسنة الحالية **في دائرة الملف الحالية** | `!rows.Any(!voided && r.ExecutionCircuitId == doc.ExecutionCircuitId && Year == current)` |
| يوجد صف غير ملغى لسنة سابقة **في دائرة الملف الحالية** | `rows.Any(!voided && r.ExecutionCircuitId == doc.ExecutionCircuitId && Year < current)` |

> **كل شروط الأهلية مقيّدة بدائرة الملف الحالية** (E1/F1): صفوف الدوائر القديمة توثيق ولا تُؤهّل. استعلام `GetRotationCandidatesAsync` يطبّق نفس القيد. لا `RotationEligibleFromYear` ولا `FileYear != current` كشرط أساسي.

**مصدر السنة (G1):** `currentYear = ServerClock.CurrentYear(_clock, _timeZone)` في كل استدعاء؛ يُمنع `DateTime.UtcNow.Year`/`DateTime.Today.Year`.

## 5) المسارات

### 5.1 الإنشاء/التعديل — صف القيد

- `SyncRegistrationAsync` داخل معاملة الكتابة:
  - إن وُجد صف قيد **غير ملغى** في **الدائرة الحالية** لنفس `(DocumentId, Year)` (`Source=registration` أولًا؛ وإن لم يوجد فاحتياطي `Source IS NULL` بشرط `NumberKey == NormalizeNumber(FileNumber)` و`VoidedAt IS NULL`) ⇒ تحديثه موضعيًا (الرقم/النوع/المفاتيح/`CircuitName`). **صفوف الدوائر الأخرى لا تُمس** (E2/F2).
  - تغيّر السنة ⇒ **إلغاء** صف القيد القديم في الدائرة الحالية (`VoidedAt`, `registration-superseded`) وإدراج جديد (مع فحص التفرد)؛ القديم يبقى في السجل.
  - إفراغ الرقم ⇒ الملف مسودة؛ **إلغاء** صف القيد الحالي (`VoidedAt`, `registration-cleared`) — يبقى توثيقًا.
  - **لا يُحدَّث صف ملغى أبدًا** (`VoidedAt == null` شرط البحث) (E3/F2).
- **داخل القفل (G3):** بعد أخذ قفل `(circuit, year)` تُعاد قراءة الصفوف من القاعدة (لا `doc.BaseNumbers` المحمّلة قبل القفل).
- **تزامن المستند:** كتابة `SearchText`/حقول المستند عبر `WithConcurrencyGuardAsync` (Version)، ويُعاد بناء/إلحاق `SearchText` بعد تغيير الرقم/السنة/النوع (F10).
- **تمييز الواجهات (C‑1):** تصحيح النوع/السنة من نموذج تعديل الملف؛ نقطة الأساس (§5.3) تصحّح الرقم فقط. تحديث `Documents.FileNumber` داخل `IDocumentNumberRegistry` (C‑2).
- **التكرار في القيد (D‑REG‑SOFT):** عند إدخال رقم قيد مستخدم في ملف آخر (لين: صف ملغى/دائرة أخرى) ⇒ `409 number_reuse_warning` + نافذة تأكيد في `DocumentForm` («تأكد من الرقم…»)، وإعادة الإرسال مع `warningToken` + تدقيق. الصلب (نفس الدائرة/النوع/السنة، غير ملغى) ⇒ رفض بلا تجاوز.
- **المسارات:** `CreateAsync`، `UpdateAsync` (بما فيه المعلّق)، `CompleteRegistrationsAsync`، `RegisterAsync` (§5.10).

### 5.2 التدوير (`PUT /documents/rotate`)

- `CanRotate` + المالك + `IsEligible`.
- قفل `(circuit, year)` بترتيب مفاتيح مرتّب؛ إعادة قراءة داخل القفل (G3).
- إن وُجد صف **غير ملغى** للسنة **في دائرة الملف الحالية** ⇒ رفض: «يوجد رقم مسجّل للسنة الحالية؛ استخدم التصحيح» (R1).
- تطبيع + طول + تفرد (داخل القفل، باستثناء الصف نفسه) + `WithNumberGuardAsync`.
- **التكرار (V‑21):** بعد القفل، `FindConflictAsync`:
  - صلب ⇒ `409 number_duplicate` (لا تجاوز).
  - لين وبلا `warningToken` صالح ⇒ `409 number_reuse_warning` مع نطاق التحذير فقط (بلا معرّف/حالة الملف الآخر — R6).
  - لين ومع `warningToken` صالح ⇒ يُدخل + تدقيق التجاوز.
- **الملف نفسه (F5):** إن كان الصف المصادم للملف نفسه: اللين يُتجاهل (لا تحذير)، والصلب برسالة «الرقم مستخدم سابقًا لهذا الملف في هذه الدائرة/السنة — أدخل رقمًا جديدًا أو استخدم التصحيح».
- **الدفعة المختلطة (F9):** أي صلب ⇒ `409` كامل بلا إدخال؛ لين بلا `warningToken` ⇒ `409` بقائمة التحذيرات + رمز؛ مع `warningToken` صالح ⇒ إدخال الكل + تدقيق.
- إدراج صف `Source=rotation` + تدقيق «دوّر الملف…».
- الدفعة: `HashSet<(DocumentId)>` + `HashSet<(TypeKey, NumberKey)>` لكل دائرة/سنة؛ سقف **500**؛ `RateLimitingSetup.ExpensivePolicy` (موجود في `DocumentsController.cs:196`).
- الإدخال الفارغ = **لا تغيير** (دلتا عقد G8).
- **الواجهة:** تعرض رقم السنة السابقة (الفعّال) وحقل إدخال؛ ترسل ≤ حجم الصفحة (20).

### 5.3 التصحيح (`PUT /documents/{id}/base-numbers/{year}`)

- `CanRotate` + المالك.
- الجسم: `{ baseNumber, rowId? }`؛ إن لم يُرسل `rowId` يُستهدف **الصف الفعّال** لتلك السنة (آخر صف غير ملغى).
- **التحقق (F4/R5):** `rowId` يجب أن يخصّ `documentId`، و`row.Year == year`، والمستخدم مالكه، والصف **غير ملغى**؛ وإلا `403/404`. الصفوف الملغاة مجمّدة (لا تصحح).
- تحديث موضعي + تحرير الرقم القديم + تدقيق **قبل/بعد** + `UpdatedById` (G12).
- إن كان الصف `Source=registration` **و** `row.ExecutionCircuitId == doc.ExecutionCircuitId` **و** `VoidedAt == null` ⇒ تحديث `Documents.FileNumber` (F10). غير ذلك لا يمسّ المرآة.
- إن كان `Source=renewal` ⇒ لا تُمس `RenewalFileNumber`/وقعة التجديد (لقطة أصلية).
- **التكرار (V‑21):** صلب ⇒ رفض؛ لين ⇒ تحذير/تجاوز بـ`warningToken`؛ الصفوف الملغاة لا تحجز لكنها تُنبّه (بلا كشف معرّف/حالة — R6).
- لا حذف من هذا المسار.

### 5.4 التجديد (المسارات الأربعة)

`RestoreStruckOffAsync`، `SetExecutedStatusAsync`، `UpdateAsync`، `ReturnFromReferredToStartAsync` — كلها عبر `ApplyRenewalAsync`:
- قفل + تفرد + `WithNumberGuardAsync` + تطبيع + طول + سنة رقمية.
- إدراج صف `Source=renewal`؛ الأحدث `CreatedAt` هو الفعّال.
- شرط: سنة التجديد ≥ أحدث هوية غير ملغاة **في دائرة الملف الحالية** (R1).
- **التكرار (V‑21):** صلب ⇒ رفض؛ لين ⇒ تحذير/تجاوز بـ`warningToken`.
- **تجديد بنفس الرقم/السنة** ⇒ يرفضه الفهرس الفريد (مقصود) + اختبار (G9).

### 5.5 الإحالة بين الدوائر

1. قفل `(الدائرة القديمة, سنة كل صف)`.
2. **لا تُحذف/تُلغى** صفوف الملف: تبقى كما هي بدائرتها القديمة (V‑07).
3. تصفير `FileNumber/FileType/FileYear` و`NeedsRegistration=true`.
4. إعادة القيد: صف `Source=registration` جديد في الدائرة الجديدة بعد فحص التفرد؛ لا تدوير تلك السنة (لأن رقمها للسنة الحالية).
5. الصفوف القديمة تبقى حاجزة في الدائرة القديمة/سنتها، ولا تظهر في الهوية اليومية للدائرة الجديدة.

> **السنة الماضية (F7):** إن أُدخل رقم إعادة القيد بسنة ماضية، يظهر الملف في جدول السنة الحالية (لأنه لا يملك رقمًا لها) — سلوك v2 المقصود.

### 5.6 تغيير الدائرة من التعديل

- صفوف الدائرة القديمة تبقى (توثيق/حجز)؛ **صف القيد القديم يبقى غير ملغى** في الدائرة القديمة، ويُنشأ صف قيد جديد في الدائرة الجديدة بعد فحص التفرد (F3/E4). لا إلغاء لصف القيد القديم.
- لا `RotationEligibleFromYear`؛ الهوية الجديدة = صف الدائرة الجديدة.

### 5.7 الشطب

- الصفوف تبقى غير ملغاة؛ الملف يُستبعد من التدوير بالحالة؛ رقمه يبقى حاجزًا في سنته.
- التجديد يضيف صفًا جديدًا؛ الأحدث فعّال.

### 5.8 الحذف والاستعادة

- **الحذف:** `VoidForDocumentDeleteAsync` يضع `VoidedAt/VoidedById/VoidReason=document-deleted` على كل صفوف الملف؛ تُحرَّر الأرقام (الفهرس الجزئي) وتبقى معروضة «ملغاة». `Documents.FileNumber` يبقى للتوثيق بعد الحذف (الفهرس مستثنى بـ`IsDeleted`)، ويُفرَّغ عند الاستعادة (E14).
- **الاستعادة:** `NeedsRegistration=true`، تُفرَّغ حقول الرقم الجارية، ويُطلب رقم جديد (إعادة قيد)؛ الصفوف الملغاة تبقى توثيقًا؛ لا استعادة صفوف. `SyncRegistrationAsync` يبحث عن صف قيد **غير ملغى** فقط؛ الصفوف الملغاة لا تُحيا (E3).
- السجل يستخدم `IgnoreQueryFilters` لعرض صفوف الملف المحذوف عند فتحه من صفحة المحذوفات، مع فحص النطاق/الصلاحية.

### 5.9 التراجع عن تدوير السنة الحالية

`DELETE /documents/{id}/base-numbers/{year}`:
- السنة الحالية فقط، `CanRotate` + المالك، والصف `Source=rotation` **في دائرة الملف الحالية**.
- **شرط (R1):** لا توجد هوية أخرى غير ملغاة لنفس السنة **في دائرة الملف الحالية**؛ وإلا `409`.
- `VoidedAt` (`undo-rotation`) + تدقيق؛ يتحرر الرقم ويعود الملف للجدول؛ الصف يبقى معروضًا «ملغى».
- لا يُسمح بإلغاء صفوف `registration`/`renewal` من هذا المسار.

### 5.10 تسجيل الإنابة

`DocumentDelegationService.RegisterAsync`:
1. إضافة `int? ExecutionCircuitId` إلى `RegisterDelegationRequest` (إلزامي للخارجية).
2. رفض إن بقي الملف بلا دائرة.
3. `SyncRegistrationAsync` (صف `Source=registration` في الدائرة) + تفرد + قفل + `WithNumberGuardAsync`؛ والتكرار (V‑21): صلب ⇒ رفض، لين ⇒ تحذير/تجاوز بـ`warningToken`؛ واستثناء الملف نفسه اللين.
4. الواجهة تعرض منتقي دائرة للإنابة الخارجية.
5. **`SearchText`:** يُعاد بناؤه بعد تسجيل الرقم (F10).

### 5.11 رسائل التكرار (نهائية)

**حجب صلب (`409 number_duplicate`، لا تجاوز):**
> «الرقم {number} مستخدم بالفعل في الدائرة نفسها لسنة {year} ونوع {type}. لا يمكن تكرار الرقم في نفس الدائرة والنوع والسنة؛ اختر رقمًا آخر.»

**تحذير مع تجاوز (`409 number_reuse_warning`، يُقبل بـ`warningToken`):**
> «تأكد من الرقم {number}؛ لأنه مستخدم في ملف آخر (سنة {year}، نوع {type}، دائرة {circuit}). هل تريد إدخاله على أي حال؟»

- أزرار الواجهة: «إدخال على أي حال» / «إلغاء».
- عند القبول: يُعاد الإرسال مع `warningToken`، ويُسجَّل تدقيق «أكد استخدام رقم مستخدم في ملف آخر: …».
- **لا كشف للملف الآخر (R6):** لا معرّف/اسم/حالة في الرسالة أو الرد العام؛ تُحفظ للتدقيق فقط.
- **`warningToken` (R7):** قصير العمر، مرتبط بالمستخدم + الصف المصادم + بصمة الطلب؛ `confirmReuse` المنطقي غير مقبول.
- **يشمل التحذير:** صفًا ملغى في نفس الدائرة **أو أي دائرة أخرى**، أو صفًا غير ملغى في دائرة أخرى (سنة/نوع نفسيهما). لا يشمل سنة سابقة/نوعًا مختلفًا.
- **الملف نفسه:** التحذير اللين يُلغى إذا كان الصف للملف نفسه؛ والصلب الذاتي برسالة «الرقم مستخدم سابقًا لهذا الملف في هذه الدائرة/السنة — أدخل رقمًا جديدًا أو استخدم التصحيح».
- **المشطوب/المنفذ:** صلب (D‑05).
- **مسموح بلا رسالة:** رقم من سنة سابقة (تدوير طبيعي)، أو نوع مختلف، أو دائرة وسنة مختلفتان.

## 8) الهجرة والنشر

### 8.1 تدقيق مسبق (قراءة فقط)

على `Supabase` بجلسة قراءة فقط: عدد الملفات المرقّمة، عدد `DocumentBaseNumbers`، التكرارات بعد التطبيع `(CircuitId, TypeKey, Year, NumberKey)`، الملفات بلا دائرة ولها رقم، والصفوف التي أبوها بلا دائرة. **ويُضاف (R2/R3):** عدد الملفات المحذوفة منطقيًا ولها أرقام؛ وعدد الملفات ذات وقعة تبديل دائرة من التعديل (`circuit-change`) وصفوفها الأقدم من الوقعة. بلا بيانات شخصية.

### 8.2 الهجرة (جدول واحد)

هجرة واحدة لكل سياق داخل معاملة:
1. إضافة الأعمدة: `ExecutionCircuitId`, `CircuitName`, `TypeKey`, `NumberKey`, `Source`, `UpdatedById`, `VoidedAt`, `VoidedById`, `VoidReason`.
2. تعبئة الصفوف القائمة (R2/R3): الدائرة/الاسم من **وقعة تبديل الدائرة** إذا كانت الصفوف أقدم منها (وإلا **تتوقف التعبئة بتقرير** للمعالجة اليدوية — لا نسبة صامتة للدائرة الحالية)؛ النوع/المفاتيح من المستند؛ `Source=rotation`؛ `VoidedAt = doc.IsDeleted ? UtcNow : null` و`VoidReason = doc.IsDeleted ? 'document-deleted' : null`.
3. إنشاء صف `Source=registration` لكل ملف مرقّم، في **دائرته الحالية**، بعد البحث `(DocumentId, Year, ExecutionCircuitId, Source=registration)`؛ إن لم يوجد أُنشئ (R4). للمحذوف: صف قيد **ملغى** `document-deleted` **دائمًا** (توثيق؛ لا يُتخطّى).
4. جعل `ExecutionCircuitId/CircuitName/TypeKey/NumberKey` إلزامية.
5. إنشاء الفهرس الفريد الجزئي (`WHERE VoidedAt IS NULL`).

> **التكرار في التعبئة (F8):** التعبئة **تفشل بتقرير** عند أي تكرار (قيد/تدوير/مفتاح مكرر) أو صف بلا دائرة/`CircuitName`؛ لا تنظيف صامت؛ المعالجة يدوية.

> **اختيار المسار:** إن كانت `DocumentBaseNumbers` والملفات المرقّمة صفرًا ⇒ المسار النظيف؛ أي قيمة >0 ⇒ `Expand/Contract` (تعبئة C# عبر `dotnet run -- --backfill-number-registry`، ثم `Contract`). `Contract` على نسخة واحدة يمكن أن يكون بلا توقف بالترتيب (Expand ← نشر ← تعبئة ← Contract)، وليس «شكليًا».

**أسماء الهجرات المقترحة:** `BaseNumberRegistry` (SQLite) و`BaseNumberRegistry_Pg` (Postgres).

### 8.3 النشر

1. إيقاف الخدمة (`Render` Suspend) — لا كتابة أثناء الهجرة.
2. **نسخة احتياطية بحسب المتاح:** لا نسخ آلية (Render free + قاعدة تجريبية)؛ `pg_dump` يدوي إلى ملف خارج المستودع، أو **قبول المخاطرة** موثّقًا.
3. `dotnet ef database update` للسياقين.
4. نشر النسخة الجديدة، ثم التشغيل والتحقق من `/healthz`.
5. `RUN_GUIDE.md` §9: إضافة الهجرتين في نفس التغيير وشطبهما بعد التطبيق.
6. `Down()` بعد إيقاف الكود الجديد.
7. **محظور:** تطبيق الهجرة والكود القديم يكتب (الأعمدة الإلزامية).

## 9) الاختبارات

- **حفظ التوثيق (جوهر الطلب):** بعد التدوير/الشطب/التجديد/الإحالة/الحذف/التراجع ⇒ كل الصفوف ما زالت في السجل، والملغاة معروضة بوسمها، والفعّال واحد فقط.
- التطبيع (نوع/رقم)، السنة الرقمية، حدّ السنة (G1).
- الأهلية: مسودة/معلّق/منفَّذ/مشطوب/بلا دائرة/له هوية حالية/سنة سابقة.
- الفعّال: صف الدائرة الحالية فقط، وتجاهل الملغى، والرجوع إلى `FileNumber`.
- التفرد: نفس الدائرة/النوع/السنة (غير ملغى) ⇒ حجب صلب `409 number_duplicate`؛ الملغى/الدائرة الأخرى ⇒ تحذير `number_reuse_warning` يُقبل بـ`warningToken` + تدقيق؛ اختلاف النوع/السنة/الدائرة+السنة ⇒ بلا تحذير.
- مالك فقط يملك التجاوز؛ والتجاوز **لا يمرّ** على الحجب الصلب.
- التدوير/التصحيح/التراجع/التجديد/الإحالة/إعادة القيد/تسجيل الإنابة.
- إعادة القراءة داخل القفل (G3)، ومخالفة `SQLite` حقيقية ⇒ 409 (G10).
- تجديد بنفس الرقم/السنة ⇒ 409 (G9).
- تصحيح: قبل/بعد في التدقيق + وسم «مصحّح» (G12).
- دلتا العقود: إفراغ التدوير = لا تغيير؛ `RegisterDelegationRequest.ExecutionCircuitId` (G8).
- **F1/E1:** أهلية/قائمة مقيّدة بالدائرة (صفوف دائرة قديمة لا تؤهل).
- **F2/E3:** صف قيد دائرة أخرى لا يُحدّث؛ صف ملغى لا يُحيا.
- **F4/E5:** `rowId` لملف آخر/صف ملغى ⇒ 403/404.
- **F5/E6:** صف الملف نفسه: لين بلا تحذير، صلب برسالة ذاتية.
- **F6/E7:** تحذير رقم ملف محذوف يظهر (`IgnoreQueryFilters`).
- **F7/E9:** إعادة قيد بسنة ماضية ⇒ يظهر في جدول السنة الحالية.
- **F8/E10:** تعبئة بتكرار ⇒ فشل بتقرير.
- **F9/E11:** دفعة مختلطة: صلب ⇒ لا إدخال؛ لين ⇒ تحذير/تأكيد.
- **F10/E12/E13:** تصحيح صف دائرة قديمة لا يغيّر `FileNumber`؛ `SearchText` يتحدث.
- **R1:** تدوير/تجديد/تراجع مع صف قديم لنفس السنة في دائرة أخرى ⇒ لا يمنع العملية في الدائرة الحالية.
- **R2:** هجرة ملف محذوف ⇒ صفوفه `VoidedAt`/`document-deleted` ولا تحجز.
- **R3:** هجرة ملف بدّل دائرته من التعديل ⇒ دائرة الصف القديمة من الوقعة، أو توقف بتقرير (لا نسبة صامتة).
- **R4:** التعبئة تُنشئ صف القيد في الدائرة/السنة الصحيحة فقط.
- **R5:** `rowId` بسنة مختلفة عن المسار ⇒ 400/404.
- **R6/R7:** رسالة/رد التحذير بلا معرّف/حالة الملف الآخر؛ والتجاوز بـ`warningToken` لا بمنطقي أعمى.
- **R9:** مراجعة اتساق: كل ملف مرقّم له صف قيد غير ملغى في دائرته/سنته؛ لا صفوف يتيمة.
- **R10:** احتياطي `Source IS NULL` لا يطابق صف تجديد/تدوير برقم مختلف.
- واجهة: السجل يعرض الكل (بما فيه الملغى)، الجوال، زر التراجع، منتقي دائرة الإنابة.

## 13) ترتيب التنفيذ (بعد إذن البدء)

1. تدقيق القراءة على القاعدة الحية + `pg_dump`/قبول المخاطرة.
2. `DocumentBaseNumberPolicy` + `IDocumentNumberRegistry` + اختباراتهما (بلا تغيير سلوك).
3. توسيع الكيان/المخطط + الهجرة (جدول واحد + فهرس جزئي).
4. توحيد المسارات: قيد/تدوير/تصحيح/تراجع/تجديد/إحالة/إعادة قيد/تسجيل إنابة.
5. `EffectiveFileIdentity` (الدائرة) + `DocumentExportRow` + العقود/الواجهة (السجل الكامل).
6. البوابات + اختبارات الحفظ/التزامن + تقرير الإنجاز (أسماء الهجرات + تنبيه `dotnet ef database update` للسياقين).
