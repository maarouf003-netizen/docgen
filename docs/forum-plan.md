# خطة منتدى المحامين — تيار رسائل مسطّح بنمط واتساب — منقحة بعد مراجعة الخبير، ويُمنع التنفيذ قبل موافقة صريحة

> **الحالة**: نسخة 2 — منقحة بعد المراجعة النقدية للخبير (ترقيم بمفتاح `Id` بدل الإزاحة + مصفوفة تفويض
> صريحة + ترتيب حذف الاحتفاظ الصريح + توثيق المخاطر المتبقية + آلية تحقق هجرة `Postgres`).
> — **يُمنع بدء التنفيذ (أي كود/هجرة/اختبار) قبل موافقة صريحة منفصلة.**
> **المبدأ**: بناء مخصص (لا مكتبات خارجية) — البحث أثبت غياب مكتبة `‎.NET‎` ناضجة قابلة للتضمين، ومنصات
> (`‎Discourse‎`/`‎Talkyard‎`/`‎NodeBB‎`) أنظمة ثانية كاملة، و`‎Disqus‎` مرفوض أمنيًا (بيانات محامين خارج الحدود).

## 1) الهدف والنطاق

- منتدى نقاش **غير متزامن** = **تيار رسائل واحد للجميع** (غرفة واحدة عابرة للفروع عمدًا): رسائل نصية
  + اقتباس رد (نمط واتساب) + نسخ أي رسالة + نافذة «شوهدت بواسطة» للكاتب + عدّاد غير مقروء
  (شارة على أيقونة المنتدى) + تثبيت رسالة + حذف صلب تلقائي للأقدم من 6 أشهر.
- كل رسالة تُعرض بهوية كاتبها الكاملة (الاسم — الصفة — الفرع) وتاريخ إرسالها.
- **خارج النطاق صراحة**: مواضيع/خيوط نقاش (مرفوضة بقرار المالك)، لحظية `‎SignalR‎` (مرحلة 3 مشروطة)،
  دفع الهاتف (`‎FCM‎`)، مرفقات، ردود فعل، رسائل خاصة، سجل تدقيق للمنتدى، متابعة/إلغاء متابعة،
  حذف ناعم لرسائل الدردشة (مرفوض بقرار المالك — حذف صلب فقط)، سطر شفافية الاحتفاظ في الواجهة
  (مرفوض بقرار المالك)، مؤشر حضور/«يكتب الآن»، الإرسال المتفائل (مرشح لاحقًا لا ملتزم)،
  قفز البحث للنتيجة مع التظليل (مرشح لاحقًا لا ملتزم)، مفتاح عدم تكرار `‎X-Idempotency-Key‎`
  (مؤجل — الآلية القائمة موثقة في `‎RF-011‎` عبر `‎IdempotencyGuard‎` والترويسة اختيارية تُعيد الثانية `‎200‎`
  بالجسم نفسه؛ التأجيل قرار واعٍ لأن تعطيل زر الإرسال أثناء الطلب يكفي هنا — ليس شرط قبول).

## 2) القرارات المعتمدة (نهائية ما لم يُطلب تغييرها)

| البند | القرار |
|---|---|
| النموذج | رسائل مسطّحة في تيار واحد للجميع — لا `‎ForumTopic‎` ولا خيوط ولا صفحة تفاصيل (`‎/forum/:id‎` ملغاة) |
| الكتابة | كل الأدوار الموثقة (مشرف/مدير/رئيس/محامٍ) — المندوب مستبعد تلقائيًا بالحارس (لا يُضاف المنتدى للقائمة البيضاء) + مسار `‎/forum‎` بحارس دور يُقصي المندوب كبقية المسارات |
| القراءة | نفس الكتّاب (عابر للفروع عمدًا — كسر لعزل الفروع مقصود هنا فقط، وخطر التسرب المتبقي موثق في §2-ب) |
| التعديل/الحذف الذاتي | مسموح للكاتب، مع ختم «عُدّل» (`‎EditedById/EditedAt‎`)؛ **الحذف صلب** (بلا `‎IsDeleted‎`) |
| حذف أي رسالة | المشرف فقط — صلب (انظر مصفوفة §2-أ) |
| التثبيت | رسالة واحدة لمرة واحدة للمشرف (تثبيت جديد يُسقط السابق تلقائيًا)؛ شريط مميّز أعلى التيار؛ **مستثناة من التنظيف**؛ الوحدانية مضمونة بفهرس فريد مفلتر `‎HasFilter‎` (اصطلاح `‎DocumentConfiguration.cs:180‎` الصالح لـ SQLite وPostgres معًا) |
| النقل اللحظي | استطلاع 60 ثانية (`‎useBadgeCount‎`) + إيقاف الاستطلاع بخفاء التبويب (`‎visibilitychange‎` — معامل اختياري `‎pauseWhenHidden‎` بقيمة افتراضية لا تكسر الدعوات القائمة، مع اختبار عدم انكسارها) — `‎SignalR‎` مرحلة مشروطة بشكوى حقيقية فقط |
| الترتيب | `‎(CreatedAt, Id)‎` تصاعديًا — الأقدم أعلى والأحدث أسفل (واتساب)؛ `‎Id‎` عددي متسلسل (اصطلاح `‎int Id‎` بالإجماع في الكيانات) فيضمن الترتيب الكلي والثبات |
| الترقيم | **بمفتاح مستمر `‎Id‎` لا بالإزاحة** (درس المراجعة): `‎limit‎` (افتراضي 30) + `‎before=Id‎` للأقدم + `‎after=Id‎` للأحدث — لا `‎skip‎`/`‎take‎` في العقد إطلاقًا، لأن الإزاحة تتزحزح مع الوارد أثناء التمرير فتُضاعف/تُسقط |
| المحتوى | نص عادي فقط (لا `‎HTML‎`) — هروب عند العرض |
| الاقتباس | `‎QuotedMessageId?‎` (`‎SetNull‎`) + لقطة `‎QuotedAuthorName/QuotedExcerpt‎` تبقى بعد حذف/تعديل الأصل (سلوك واتساب)؛ اقتباس رسالة غير موجودة `‎400‎` |
| النسخ | زر في قائمة إجراءات كل رسالة → `‎navigator.clipboard.writeText‎` + `‎Toast‎` نجاح/فشل |
| «من شاهد» | صفوف صريحة `‎ForumMessageRead { MessageId, UserId, UserName (لقطة), ReadAtUtc }‎` (سابقة `‎CorrespondenceReceipt‎`)؛ النافذة بعنوان **«شوهدت بواسطة»** (تسمية صادقة — التتبع من فتح التيار لا زر تأكيد صريح) **للكاتب فقط** (`‎403‎` للغير)؛ الكتابة دفعة `‎INSERT…SELECT‎` واحدة عند فتح التيار؛ القائمة كاملة بلا ترقيم (محدودة بعدد مستخدمي النظام) |
| العدّاد | `‎GET unread-count‎` = رسائل بلا إيصال لي (يُشتق من `‎MAX(MessageId)‎` لكل مستخدم عبر فهرس `‎(UserId, MessageId)‎`) |
| الاحتفاظ | **حذف صلب** يومي للأقدم من `‎Forum:RetentionMonths = 6‎` (إعداد، `‎0‎` = معطّل، السالب يُرفض عند بدء التشغيل) عدا المثبّتة؛ أول `‎BackgroundService‎` في المشروع (منطق منفصل قابل للاختبار + مضيف رفيع)؛ الحذف على **خطوات صريحة مرتبة** (تصفير مراجع الاقتباس إلى المستهدفة مع بقاء اللقطات، ثم الإيصالات، ثم الرسائل — وعلاقة `‎Cascade‎` توثيق لا اعتماد، لضمان الحتمية على المزودين معًا)؛ التنظيف `‎idempotent‎` وآمن مع تعدد النسخ |
| الخنق | سياسة `‎AddRateLimiter‎` القائمة (نافذة دقيقة — `‎RateLimitOptions‎`) على `‎POST‎` الرسائل |
| الجرس | لا جرس رأس منفصل — **شارة على أيقونة «المنتدى»** في `‎Layout.tsx‎` (`‎NavItem.badge‎` + `‎+99‎` + `‎aria-label‎`) تُغذى من `‎unread-count‎`؛ النقر يفتح `‎/forum‎` مباشرة؛ حذف `‎comingSoon: true‎` |
| اللقطات | `‎AuthorName‎` على الرسالة (سابقة `‎CorrespondenceMessage.cs:38‎`) + `‎UserName‎` على الإيصال (سابقة `‎CorrespondenceReceipt.cs:17‎`) — تصمد بعد تغيير الاسم/التعطيل |
| هوية الكاتب | الخادم يلقط **الأجزاء فقط** لحظة الإرسال: `‎AuthorName‎` + `‎AuthorRole‎` (سلسلة `‎ToString().ToLowerInvariant()‎` — تطابق نوع `‎Role‎` الأمامي حرفيًا) + `‎AuthorLocation‎` + `‎AuthorSection?‎`؛ الواجهة تُركّب `‎{الاسم} — {formatRoleScope(...)}‎` (**الدالة المعتمدة الوحيدة** — `‎roleLabels.ts‎` — بلا ازدواج صياغة)؛ الموقع = `‎Branch.Governorate ?? Branch.Name ?? 'كل الفروع'‎`؛ الشعبة من `‎Section.Name‎` خلفيًا (إلزامية لرئيس الشعبة — `‎User.cs:18‎`) لا من مدخلات العميل إطلاقًا؛ مثال: «علي محمد معروف — رئيس قسم — اللاذقية» |
| تاريخ الإرسال | `‎CreatedAt‎` مخزّن لكل رسالة؛ العرض: طابع نسبي («منذ…» — دالة صغيرة جديدة + اختبارها، إذ لا نسبية قائمة) + فواصل الأيام في التيار + التاريخ والوقت الكاملان عند النقر/التلميح عبر `‎formatDateTime‎` القائمة (`‎ar-SY‎` — `‎utils/dates.ts:18‎`) |

## 2-أ) مصفوفة التفويض (ملزمة — تُختبر سطرًا بسطر)

| العملية | المسموح | المرفوض |
|---|---|---|
| نشر رسالة | مشرف/مدير/رئيس قسم/رئيس شعبة/محامٍ | المندوب (`‎403‎`)، المجهول (`‎401‎`) |
| تعديل رسالة | **الكاتب فقط** (مع ختم «عُدّل») | أي غيره (`‎403‎`) — حتى المشرف لا يعدّل، يحذف فقط |
| حذف رسالة | الكاتب لرسالته + **المشرف لأي رسالة** (صلب) | البقية (`‎403‎`) |
| تثبيت/إسقاط | **المشرف فقط** (تبديل؛ الجديد يُسقط السابق) | البقية (`‎403‎`) |
| نافذة «شوهدت بواسطة» | **الكاتب فقط** (`‎403‎` للغير) | — |
| فتح التيار/العدّاد/البحث/الذِّكر | نفس الكتّاب الخمسة | المندوب (`‎403‎`)، المجهول (`‎401‎`) |

## 2-ب) مخاطر متبقية موثقة (مقبولة بقرار المالك — لا تُسكت عنها)

- **الحذف الصلب بعد 6 أشهر قد يمحو مراسلات ذات قيمة إثباتية** — لا تجميد قانوني (`‎legal hold‎`) في التصميم؛
  القرار للمالك وموثق هنا، وأي حاجة لاحقة للاحتفاظ القانوني تتطلب مرحلة مستقلة.
- **التيار عابر للفروع عمدًا**: تبادل نص حر بين محامي فروع مختلفة قد يسرّب استراتيجيات قضايا؛
  الضبط الحالي لافتة توعية ثابتة فقط (سطر واجهة واحد) — مقبول بقرار المالك وموثق هنا.
- **بلا سجل تدقيق للمنتدى** — مقبول بقرار المالك وموثق هنا.

## 3) البنية المعزولة (نعم — العزل أفضل برمجيًا هنا، بهذا الحدّ الدقيق)

**الحكم الخبير**: عزل المنتدى كشريحة عمودية (`‎feature slice‎`) أفضل للتوسعة (مرحلة 2 ثم 3 تسقطان في نفس
الشريحة دون لمس بقية التطبيق)، **لكن العزل الكامل مستحيل في مونوليث بقاعدة واحدة** — والحدّ الصادق:

- **معزول فعلًا**: الخدمة + العقود + المتحكم (+ `‎Hub‎` لاحقًا) + خدمة الاحتفاظ + واجهات المنتدى + اختباراته —
  في مواضعها الاصطلاحية (لا مجلدات مخصصة تكسر بنية المشروع)، ولا يستوردها أي كود خارجها.
- **مشترك حتمًا**: الكيانات (في `‎Domain‎`)، و`‎DbSets‎` (في السياق المشترك)، والهجرات (في تاريخ الهجرات المشترك).
- **القاعدة الذهبية**: المنتدى يستورد من المشترك (المصادقة/المستخدمون/البنية) فقط، ولا شيء يستورد من المنتدى.

```
backend/src/DocGenerator.Domain/Entities/ForumMessage.cs (+ ForumMessageRead.cs)
backend/src/DocGenerator.Application/Services/ForumService.cs (واجهة + تنفيذ — عرف المراسلات)
                                             + ForumRetentionService.cs + DTOs/ForumDtos.cs
backend/src/DocGenerator.Api/Controllers/ForumController.cs (مسطّح — عرف المتحكمات)
backend/src/DocGenerator.Api/Background/          ← ForumRetentionHostedService (مضيف رفيع فقط)
backend/tests/.../ForumServiceTests.cs + ForumApiTests.cs ← اختبارات الشريحة

```

## 4) معايير جمال الواجهة (ملزمة — فوق قواعد `‎AGENTS.md‎` المعتادة)

- إحساس واتساب حرفيًا `‎RTL‎`: فقاعات، حقل كتابة أسفل الشاشة، تمرير تلقائي للأسفل عند الفتح والإرسال،
  «تحميل المزيد» للأعلى، أفاتار ملوّن بالأحرف الأولى، **سطر هوية الكاتب (الاسم — الصفة — الفرع)**
  عبر `‎formatRoleScope‎` (مع `‎truncate‎` و`‎min-w-0‎` للأسماء الطويلة)، طوابع زمنية نسبية («منذ…»)
  بأرقام `‎tabular-nums‎`.
- علامتا واتساب ✓✓ على رسائلي (تُشتق من عدّاد الإيصالات باستعلام `‎GROUP BY‎` واحد لكل صفحة — لا `‎N+1‎`)،
  وزر «رسائل جديدة ↓» عند وصول جديد أثناء التمرير للأعلى، وفواصل التاريخ (اليوم/أمس/التاريخ)،
  وطيّ الرسائل الطويلة («عرض المزيد» بعد ~4 أسطر).
- شريط التثبيت أعلى التيار (دبوس + خلفية مميزة + قفز للرسالة)، وكتلة الاقتباس فوق الرسالة
  (بالاسم فقط إيجازًا؛ النقر يمرّر للهدف ويُظلّله مع احترام `‎prefers-reduced-motion‎`)،
  وحفظ مسودة حقل الكتابة في `‎localStorage‎`، **وتعطيل زر الإرسال أثناء الطلب** (منع النقر المزدوج).
- التيار `‎role="log"‎` مع `‎aria-live="polite"‎`؛ حالات فارغة مصممة (لا صفحات بيضاء)، وهياكل تحميل
  (`‎skeletons‎`)، وعدّادات `‎tabular-nums‎`.
- لمس `‎min-h-11‎`، تباين كافٍ، `‎focus-visible‎`، ولا `‎transition: all‎`.
- تنبيه سياسة مهني ثابت أعلى صفحة المنتدى: «لا تشارك بيانات ملفات حساسة» (سطر واجهة واحد — التطبيق قانوني).

## 5) المرحلة 1 — التيار الأساس (≈ جلسة ونصف)

- **الكيانات**: `‎ForumMessage { Id (int)، Body ≤2000 (مرفوض الفراغ)، AuthorId Restrict، AuthorName (لقطة)،
  AuthorRole (لقطة)، AuthorLocation (لقطة)، AuthorSection؟ (لقطة)، IsPinned، CreatedAt (UtcNow افتراضيًا)،
  EditedById/EditedAtUtc؟ (بلا UpdatedAtUtc — زائد)، QuotedMessageId؟ SetNull، QuotedAuthorName؟ ≤150،
  QuotedExcerpt؟ ≤200 }‎` (بلا `‎IsDeleted‎` — الحذف صلب بقرار المالك)،
  و`‎ForumMessageRead { Id بديل (عرف CorrespondenceReceipt — لا مفتاح مركب)، Unique(MessageId, UserId)،
  MessageId Cascade، UserName (لقطة)، ReadAtUtc }‎`.
- **الأمان (شرط لا تحسين)**: المحتوى نص عادي فقط — لا `‎HTML‎` تخزينًا ولا عرضًا؛ هروب عند العرض.
  أي عرض غني مستقبلًا يستلزم مراجعة أمنية مستقلة.
- **الهجرات**: `‎AddForumMessages‎` (SQLite) + `‎AddForumMessagesPg‎` (Postgres) + استبدالات `‎timestamptz‎`
  لكل عمود زمني (درس `‎AlignPostgresTimestampTypes‎` — لا يُنسى أي عمود) + **مراجعة سكربت الهجرتين
  سطرًا بسطر وفحص `‎Npgsql‎ mapping‎`، لأن اختبارات `‎SQLite‎` لا تكشف خطأ نوع `‎Postgres‎` إطلاقًا**.
- **الفهارس** (`‎OnModelCreating‎` — فهارس `‎FK‎` مجانية من `‎EF‎` تلقائيًا): فريد مفلتر لوحدانية التثبيت،
  و`‎ForumMessage(CreatedAt)‎` (للفرز والعدّ والتنظيف)، و`‎ForumMessageRead(UserId, MessageId)‎`
  (للعدّاد) — وإلا مسح كامل لشارات كل مستخدم.
- **النقاط** (كلها `‎[Authorize]‎`): `‎GET /api/forum/messages?limit=&before=&after=&q=‎`
  (تصاعدي `‎(CreatedAt, Id)‎`؛ `‎before‎` للأقدم و`‎after‎` للأحدث بمفتاح `‎Id‎` — بلا `‎skip‎`/`‎take‎‎`؛
  `‎q‎` يطابق نص الرسائل، وتتضمن أجزاء الهوية لكل رسالة + `‎readCount‎` لرسائلي فقط)،
  `‎GET /api/forum/messages/{id}‎` (رسالة واحدة — لصدق `‎201 Created‎` عند النشر)،
  `‎GET /api/forum/pinned‎` (للشريط — `‎204‎` عند عدمها)، `‎POST /api/forum/messages { body, quotedMessageId? }‎`
  (يلقط الهوية خلفيًا من `‎User+Branch+Section‎` — اقتباس غير موجود `‎400‎` + خنق المعدل القائم)،
  `‎PUT /api/forum/messages/{id}‎` ذاتي (يختم «عُدّل»)، `‎DELETE /api/forum/messages/{id}‎` ذاتي أو للمشرف (صلب)،
  `‎POST /api/forum/messages/{id}/pin‎` للمشرف (تبديل؛ الجديد يُسقط السابق)،
  `‎POST /api/forum/read { upToMessageId }‎` (عدّادي — `‎max‎` فقط بلا تراجع + توسيع الإيصالات دفعة واحدة)،
  `‎GET /api/forum/messages/{id}/readers‎` (القائمة كاملة — للكاتب فقط وإلا `‎403‎` — وتعرض هوية كل قارئ)،
  `‎GET /api/forum/unread-count‎` (للشارة).
- **الاحتفاظ**: `‎ForumRetentionService.ExecuteOnceAsync‎` (قابل للاختبار المباشر) + مضيف يومي
  (`‎PeriodicTimer‎` كل 24 ساعة): حذف صلب (`‎ExecuteDeleteAsync‎` — المشروع `‎net10.0‎`) للرسائل
  `‎CreatedAt < UtcNow.AddMonths(-RetentionMonths)‎` عدا `‎IsPinned‎`، **على خطوات صريحة مرتبة**
  (تصفير الاقتباسات ثم الإيصالات المستهدفة ثم الرسائل)، وتسجيل العدد في السجل (`‎ILogger‎`).
  المنضم الجديد تُعلَّم قراءته من أول فتح (سلوك موثّق).
- **الواجهة**: مسار `‎/forum‎` واحد في `‎App.tsx‎` (بحارس دور) + استدعاء `‎api‎` المباشر (عرف الصفحات) +
  مكونات (`‎ForumPage‎`، `‎MessageStream‎`، `‎MessageBubble‎` (رأس الهوية + الطابع النسبي + `‎title‎` الكامل)،
  `‎MessageMenu‎` (نسخ/اقتباس/تعديل/حذف/تثبيت/«شوهدت بواسطة»)، `‎MessageComposer‎`، `‎PinnedBanner‎`،
  `‎ReadersDialog‎` (‎modal‎ مكتبي / ‎sheet‎ جوّال — صفوف الهوية الكاملة)، `‎NewMessagesPill‎`،
  `‎ForumSearchBox‎`، دالة `‎formatRelativeTime‎` الصغيرة) + ربط الشارة في `‎Layout.tsx‎` عبر `‎useBadgeCount‎`.
- **الاختبارات**: عبور-فروعي، المندوب `‎403‎`، المجهول `‎401‎`، السقوف والفراغ `‎400‎`،
  **مصفوفة التفويض سطرًا بسطر** (حذف/تعديل الغير `‎403‎`، المشرف يحذف أي رسالة ولا يعدّل، التثبيت للمشرف
  فقط `‎403‎` لغيره + إسقاط السابق + سباق التثبيت المزدوج → خطأ ودود)،
  **الترقيم بمفتاح** (إدراج أثناء التمرير لا يُضاعف ولا يُسقط + `‎before‎`/`‎after‎` حدوديان)،
  اقتباس غير موجود `‎400‎` + بقاء اللقطة بعد حذف الأصل، عدّادية القراءة وعدم تراجعها، الإيصالات
  (توسيع دفعة واحدة + عدم تكرار + `‎403‎` لغير الكاتب + بقاء اسم القارئ بعد تغيير اسمه)، العدّاد
  يصفر بعد القراءة، **حدود الاحتفاظ (اليوم الفاصل بالضبط) + استثناء المثبّتة + حذف الإيصالات معها
  بالترتيب الصريح**، **الهوية** (لقط الأجزاء لحظة الإرسال + التركيب عبر `‎formatRoleScope‎` + رئيس شعبة
  بشعبته + بلا فرع ← «كل الفروع» + بقاء الهوية بعد تغيير الفرع/الاسم)، **التاريخ** (النسبية + فواصل
  الأيام + الكامل)، + `‎vitest‎` للمكونات (زر النسخ مع محاكاة `‎clipboard‎` وفشله، هروب `‎XSS‎`، الشارة
  `‎+99‎` و`‎aria-label‎`، إزالة `‎comingSoon‎`، علامتا ✓✓، تعطيل الإرسال أثناء الطلب، عدم انكسار دعوات
  `‎useBadgeCount‎` القائمة).

## 6) المرحلة 2 — الذِّكر (≈ نصف جلسة)

- منتقي مستخدمين في المحرر (بحث `‎GET /api/users/lookup?q=‎` — **غير موجود حاليًا فيُنشأ**: يعيد
  `‎id‎` + أجزاء الهوية (الاسم/الدور/الموقع/الشعبة) فقط للنشطين، وتُعرض الخيارات بالصيغة نفسها)
  + تحقق الخادم (وجود + نشاط) + **سقف ≤10 مذكورين لكل رسالة**؛
  الذِّكر بنية مولّدة من الخادم (ضد `‎XSS‎`) وشرائح ملوّنة عند العرض + إبراز ذِكري بلون مختلف.
- **لا هجرات في هذه المرحلة** (استعلام بحث فقط).
- **الاختبارات**: تحقق المذكور (غير موجود/معطّل `‎400‎`)، سقف العشرة، عرض الشرائح وهروبها.

## 7) المرحلة 3 — لحظية `‎SignalR‎` (مستقبلية، مشروطة)

- **لا تُبنى إلا بشكوى حقيقية من قِدم الدقيقة.** المحتوى عندها: `‎ForumHub‎` (مصادقة الكوكي تعمل مع
  `‎WebSocket‎`) + سقوط تلقائي للاستطلاع؛ و`‎Redis backplane‎` شرط للتوسع الأفقي فقط.
- **تنبيه صريح**: لا شيء من هذا يوصل إشعارًا لهاتف مغلق المتصفح — ذلك يحتاج `‎FCM‎`/تطبيقًا أصليًا (خارج النطاق).

## 8) معايير القبول والنشر (لكل مرحلة تُسلَّم)

- تحقق `‎AGENTS.md‎` الكامل: `‎dotnet test‎` منفصلًا، `‎npx vitest run‎`، `‎oxlint‎`، `‎tsc -b‎`، `‎npm run build‎` — كلها خضراء.
- مراجعة المسار الكامل للعقود + بحث بقايا المصطلحات + فحص جوال بصري (375px).
- **مراجعة سكربت الهجرتين سطرًا بسطر** (`‎timestamptz‎` لكل عمود زمني) — إلزامية لأن اختبارات `‎SQLite‎`
  لا تغطي `‎Postgres‎`.
- العمل على فرع (`‎feature/forum-…‎`) ثم `‎PR‎` — لا دفع مباشر إلى `‎master‎`.
- تذكير النشر: **هجرتان فقط** (`‎AddForumMessages‎` + `‎AddForumMessagesPg‎`) + وجوب `‎database update‎`
  للسياقين + إدخالهما في قائمة `‎RUN_GUIDE.md‎` التراكمية — وإلا `‎no such table‎` رغم اخضرار الاختبارات —
  والتنظيف `‎idempotent‎` فلا مانع من تشغيله على أكثر من نسخة.
