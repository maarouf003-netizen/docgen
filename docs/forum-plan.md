# خطة منتدى المحامين (نقاش عابر للفروع + إشعارات وذِكر) — معتمدة جزئيًا، بانتظار موافقة التنفيذ

> **الحالة**: خطة معتمدة الأفكار (الأدوار، الاعتدال، الاستطلاع، المنتقي) + تحسينات المراجعة الخبيرة (1–8)
> — **يُمنع بدء التنفيذ قبل موافقة صريحة.**
> **المبدأ**: بناء مخصص (لا مكتبات خارجية) — البحث أثبت غياب مكتبة `‎.NET‎` ناضجة قابلة للتضمين، ومنصات
> (`‎Discourse‎`/`‎Talkyard‎`/`‎NodeBB‎`) أنظمة ثانية كاملة، و`‎Disqus‎` مرفوض أمنيًا (بيانات محامين خارج الحدود).

## 1) الهدف والنطاق

- منتدى نقاش **غير متزامن** عابر للفروع: مواضيع + ردود + إشعارات (جرس) + ذِكر مستخدمين.
- **خارج النطاق صراحة**: لحظية `‎SignalR‎` (مرحلة 3 مشروطة)، دفع للهاتف (`‎FCM‎`)، مرفقات، ردود فعل، رسائل خاصة، سجل تدقيق للمنتدى، متابعة/إلغاء متابعة (مؤجلة — قاعدة «المشاركون + المذكورون» تكفي).

## 2) القرارات المعتمدة (نهائية ما لم يُطلب تغييرها)

| البند | القرار |
|---|---|
| الكتابة | كل الأدوار الموثقة (مشرف/مدير/رئيس/محامٍ) — المندوب مستبعد تلقائيًا بالحارس (لا يُضاف المنتدى للقائمة البيضاء) |
| القراءة | نفس الكتّاب (عابر للفروع عمدًا — كسر لعزل الفروع مقصود هنا فقط) |
| التعديل/الحذف الذاتي | مسموح للكاتب، مع ختم «عُدّل»؛ حذف موضوع يُسقط ردوده تباعًا (`‎Cascade‎`) |
| التثبيت/القفل/حذف أي منشور | المشرف فقط |
| النقل اللحظي | استطلاع 60 ثانية (نمط `‎ReviewPendingBell‎`) — `‎SignalR‎` مرحلة مشروطة بشكوى حقيقية فقط |
| الذِّكر | منتقي مستخدمين (يُدخل `‎userId‎` صريحًا) — لا تحليل `‎@‎` حر (الأسماء فريدة لكل فرع والعربية متعددة التطبيع) |
| الفرز | `‎IsPinned DESC‎` ثم `‎LastActivityAtUtc DESC‎` (آخر نشاط — لا تاريخ الإنشاء وحده) |
| المحتوى | نص عادي فقط (لا `‎HTML‎`) — هروب عند العرض، والذِّكر بنية من الخادم (ضد `‎XSS‎`) |

## 3) البنية المعزولة (نعم — العزل أفضل برمجيًا هنا، بهذا الحدّ الدقيق)

**الحكم الخبير**: عزل المنتدى كشريحة عمودية (`‎feature slice‎`) أفضل للتوسعة (مرحلة 2 ثم 3 تسقطان في نفس
الشريحة دون لمس بقية التطبيق)، **لكن العزل الكامل مستحيل في مونوليث بقاعدة واحدة** — والحدّ الصادق:

- **معزول فعلًا**: الخدمة + العقود + المتحكم (+ `‎Hub‎` لاحقًا) + واجهات المنتدى + اختباراته — كلها في مجلدات
  `‎Forums‎`/`‎features/forum‎` الخاصة، ولا يستوردها أي كود خارجها.
- **مشترك حتمًا**: الكيانات (في `‎Domain‎`)، و`‎DbSets‎` (في السياق المشترك)، والهجرات (في تاريخ الهجرات المشترك).
- **القاعدة الذهبية**: المنتدى يستورد من المشترك (المصادقة/المستخدمون/البنية) فقط، ولا شيء يستورد من المنتدى.

```
backend/src/DocGenerator.Application/Forums/      ← DTOs + ForumService + IForumService
backend/src/DocGenerator.Api/Controllers/Forum/   ← ForumController (+ ForumHub لاحقًا)
backend/tests/.../Forums/                         ← اختبارات الشريحة
frontend/src/features/forum/                      ← pages/ + components/ + api.ts + hooks/ + styles
```

## 4) معايير جمال الواجهة (ملزمة — فوق قواعد `‎AGENTS.md‎` المعتادة)

- لغة عربية أولًا `‎RTL‎` كاملة؛ بطاقات على الجوال (نهج `‎DocumentsList‎`) وجدول/شبكة على المكتبي.
- هوية بصرية للمنتدى: أوائل أسماء ملوّنة (أفاتار بالأحرف)، طوابع زمنية نسبية («منذ ساعتين»)، تمييز المثبت
  (دبوس + خلفية)، والمقفل (قفل + تعطيل الرد)، وشرائح `‎@‎الذِّكر` ملوّنة داخل النص.
- حالات فارغة مصممة (لا صفحات بيضاء)، وهياكل تحميل (`‎skeletons‎`) أثناء الجلب، وعدّادات `‎tabular-nums‎`.
- الجرس: نسخة من نمط `‎ReviewPendingBell‎` (أحمر + `‎+99‎` + `‎aria-label‎` + ثبات عند الفشل) بجانب الجرس القائم.
- لمس `‎min-h-11‎`، تباين كافٍ، `‎focus-visible‎`، ولا `‎transition: all‎`.
- تنبيه سياسة مهني ثابت أعلى صفحة المنتدى: «لا تشارك بيانات ملفات حساسة» (سطر واجهة واحد — التطبيق قانوني).

## 5) المرحلة 1 — المنتدى الأساس (≈ جلسة ونصف)

- **الكيانات**: `‎ForumTopic { Title ≤150 (مرفوض الفراغ)، Body ≤4000، AuthorId Restrict، IsPinned، IsLocked،
  ReplyCount، LastActivityAtUtc، CreatedAt/UpdatedAtUtc، EditedById/EditedAt؟ }`،
  و`‎ForumReply { TopicId Cascade، AuthorId Restrict، Body ≤2000 (مرفوض الفراغ)، CreatedAt/UpdatedAtUtc، EditedById/EditedAt؟ }`.
- **الأمان (شرط لا تحسين)**: المحتوى نص عادي فقط — لا `‎HTML‎` تخزينًا ولا عرضًا؛ هروب عند العرض؛ شرائح
  `‎@‎الذِّكر` بنية مولّدة من الخادم لا نصًا محللًا. أي عرض غني مستقبلًا يستلزم مراجعة أمنية مستقلة.
- **الهجرات**: `‎AddForum‎` (SQLite) + `‎AddForumPg‎` (Postgres) + استبدالات `‎timestamptz‎` لكل عمود زمني
  (درس `‎AlignPostgresTimestampTypes‎` — لا يُنسى أي عمود).
- **الفهارس** (`‎OnModelCreating‎` — فهارس `‎FK‎` مجانية من `‎EF‎` تلقائيًا): مركّبان صريحان فقط —
  `‎ForumReply(TopicId, CreatedAt)‎` و`‎ForumNotification(UserId, IsRead)‎` — وإلا مسح كامل لجرس كل مستخدم.
- **النقاط** (كلها `‎[Authorize]‎`): `‎GET /api/forum/topics‎ (+?q=‎ يطابق العنوان والمتن **ونص الردود** ويعيد
  المواضيع — بلا مقتطفات مميزة في المرحلة 1)`، `‎GET /api/forum/topics/{id}‎ (الردود تصاعديًا `(CreatedAt, Id)`
  للثبات + `‎skip/take‎` أو «تحميل المزيد» + `‎ReplyCount‎`)`، `‎POST /api/forum/topics‎`،
  `‎POST /api/forum/topics/{id}/replies‎ (يُحدِّث `‎LastActivityAtUtc‎` و`‎ReplyCount‎` في نفس المعاملة)`،
  `‎PUT /api/forum/...‎` ذاتي (يختم «عُدّل — بواسطة فلان» عبر `‎EditedById/EditedAt‎`)، `‎DELETE /api/forum/...‎` ذاتي،
  `‎POST /api/forum/.../pin|lock‎` للمشرف — خنق إنشاء خفيف لكل مستخدم.
  **الفرز**: `‎IsPinned DESC‎` ثم `‎LastActivityAtUtc DESC‎`.
- **الواجهة**: `‎/forum‎` + `‎/forum/:id‎` + عميل `‎features/forum/api.ts‎`.
- **الاختبارات**: عبور-فروعي، المندوب `‎403‎`، المجهول `‎401‎`، السقوف `‎400‎`، حذف الغير `‎403‎`، التثبيت للمشرف،
  تتالي الردود، **الفرز (مثبت أولًا ثم آخر نشاط)**، **تحديث `‎LastActivityAtUtc‎`/`‎ReplyCount‎` مع الرد**،
  **سقف الذِّكر**، **مطابقة البحث لنص الردود** + `‎vitest‎` للمكونات (منها **هروب `‎XSS‎`** في العرض).

## 6) المرحلة 2 — الإشعارات والذِّكر (≈ جلسة)

- **جدول واحد**: `‎ForumNotification { UserId, TopicId, ReplyId?, Kind (NewReply|Mention), IsRead, ReadAt?, CreatedAt }‎`
  + هجرتا `‎AddForumNotifications‎` المزدوجة.
- **قواعد الإشعار** (ضد الضجيج): الرد يُشعر **المشاركين في الموضوع فقط** (عدا الكاتب) — لا تعميم لكل المحامين؛
  الذِّكر عبر المنتقي + تحقق الخادم (وجود + نشاط) + **سقف ≤10 مذكورين لكل رد**؛ إزالة تكرار (ذِكر مشارِك =
  صف واحد بأولوية `‎Mention‎`).
- **النقاط**: `‎GET /api/forum/notifications/unread-count‎` + قائمة + تعليم مقروء (فردي/للموضوع/للكل).
- **الواجهة**: `‎ForumBell.tsx‎` (استطلاع 60s، مخفي للمندوب) + منتقي مستخدمين في المحرر (بحث `‎GET /api/users/lookup?q=‎`
  يعيد `‎id‎/اسم/فرع` فقط للنشطين).
- **الاختبارات**: قواعد المشاركة، تحقق المذكور، منع التكرار، تدفقات المقروئية، عرض الجرس والعداد.

## 7) المرحلة 3 — لحظية `‎SignalR‎` (مستقبلية، مشروطة)

- **لا تُبنى إلا بشكوى حقيقية من قِدم الدقيقة.** المحتوى عندها: `‎ForumHub‎` (مصادقة الكوكي تعمل مع `‎WebSocket‎`) +
  مجموعات لكل موضوع + سقوط تلقائي للاستطلاع؛ و`‎Redis backplane‎` شرط للتوسع الأفقي فقط.
- **تنبيه صريح**: لا شيء من هذا يوصل إشعارًا لهاتف مغلق المتصفح — ذلك يحتاج `‎FCM‎`/تطبيقًا أصليًا (خارج النطاق).

## 8) معايير القبول والنشر (لكل مرحلة تُسلَّم)

- تحقق `‎AGENTS.md‎` الكامل: `‎dotnet test‎` منفصلًا، `‎npx vitest run‎`، `‎oxlint‎`، `‎tsc -b‎`، `‎npm run build‎` — كلها خضراء.
- مراجعة المسار الكامل للعقود + بحث بقايا المصطلحات + فحص جوال بصري (375px).
- تذكير النشر: الهجرات بأسمائها وعددها (سياقان) + وجوب `‎database update‎` للسياقين + إدخالها في قائمة `‎RUN_GUIDE.md‎`
  التراكمية — وإلا `‎no such table‎` رغم اخضرار الاختبارات.
